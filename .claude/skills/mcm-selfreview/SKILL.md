对一份美赛（MCM/ICM）论文稿做**投稿前自查**：产出 **A 组合规判定（一票否决）** 与 **B 组内容质量清单**，并给出一行「能不能提交」的结论。

判据一律以 `corpus/official/INDEX.md` §2.1–§2.5 为准；引用时写指针，不要复述规则原文后不加指针。每条标**证据分级**（`[官方]`／`[半官方]`／`[社区]`）与**时效标记** `†`，定义见 `INDEX.md` §0。

## 开工前先取输入（一次问清）

本 skill 有六项（**A1、A2、A6、A7、A10、A14**）的证据**不在稿件内**，须向用户索取；**另有第 4 条（AI 使用情况）——它同样不在稿件内，但它是 A11 的触发依据，不使 A11 变成 `未判定` 项**。**开工时一次性问清**，不要等判到那一步再逐个回头问——拿到这几项，结论行才可能直接落到「可提交」或「不能提交」，而不必停在「待补数据」：

1. **提交件**：编译后的**实际页数**、摘要**是否容于单页**、**实际上传的文件名**、PDF **体积**（依次对应 A1、A2、A6、A7）。
2. **提交动作**：除这一个 PDF 外，**是否随解答另附了程序／软件／数据库或其他非论文文件**（A10）。
3. **题面**：所选**题目**（题号），以及该题**是否自带附加要求**（memo／letter、特定解答格式、特定页数限制）（A14）。
4. **AI 使用情况**：**用过哪些 AI 工具**（含 LLM、翻译软件、数学软件、代码补全；**未用则明确答"无"**）——这是**唯一无法从稿件本身查出的证据**（整篇中译英或通篇 LLM 润色可以**不留任何痕迹**），**它是 A11 的触发依据**（判据见「判定细则」的 A11／A12 条）。此项与上面三项不同：它不是"取不到就判 `未判定`"的项，而是 **A11 能否成立的前提**——**问不到就继续问，不得跳过**；始终未确认时按「结论行」一节的**前置条件未满足**处理（**不出具结论行**，也不得改判 `通过`）。

**兜底不变**：用户一时给不出时，对应项仍判 `未判定`、结论行仍走第三形态，**不得**据此判「通过」。**给不给得出输入，只影响该判 `未判定` 还是 `通过`／`不通过`，不影响判据本身**——输入齐备也不放宽任何一条判据。`[社区]`（操作纪律；各项的官方指针见本文件的 A 组清单与 §2.1.1、§2.2.2、§2.3.4、§2.3.7、§2.3.9、§2.1.6）

## 输出

**两组必须分开呈现。** 不得混排、不得合并成一张表、不得把 B 组的缺口写进 A 组。

### A 组｜合规（一票否决）

逐项列，**每项必填三列**：`检查值` / `是否通过` / `证据位置`。**不许跳过任何一行**，不许用「无问题」「远未触限」「无法从源码判定」一句话打发——取不到值就写 `未判定`（**仅限证据不在稿件内的项**，其适用面见下段，**是封闭的**），并写清该向谁取（见「`未判定` 项怎么取」）。

**`未判定` 的适用面是封闭的、且按证据位置界定**：它**仅限**那些**证据不在被审稿件内**的项——证据在**编译产物**（**A1 页数、A2 摘要是否容于单页、A7 PDF 体积**）、**提交动作**（**A6 实际提交文件名、A10 是否随解答提交了非论文文件**）、或**题面**（**A14 题目特定要求**）中的项。**其余各项（A3/A4/A5/A8/A9/A11/A12/A13/A15）在源码或 PDF 中必有证据，只能判 `通过` 或 `不通过`，不得写 `未判定`。**（A2 与 A1 同属**编译后版式属性**，源码无法确定，故按同一原则处理——不得改用"字数／行数启发式"去估。）`[社区]`（操作纪律：官方无"未判定"这一概念，本节是自查协议；上限口径见 §2.1.1、§2.2.2）

```
| # | 检查项 | 检查值 | 是否通过 | 证据位置 |
| :--- | :--- | :--- | :--- | :--- |
| A1 | 总页数 ≤25 | <实测值，或"用户报告 N 页"> | 通过／不通过／未判定 | <文件:行号，或"用户报告"> |
| A2 | … | | | |
```

**未过合规的论文，内容再好也无效。** A 组任一项判「不通过」，结论一律为**不能提交**，该项列为第一优先修复项；B 组照常给，但排在 A 组之后。

### B 组｜内容质量

按 `INDEX.md` §2.5.3 的官方 10 条清单**逐条**给结论（`有`／`部分`／`缺`），并指到论文的节名或行号；**另单列一项 B11**——官方以 `must` 写死的**来源记录**义务（§2.5.7），它不是 §2.5.3 清单里的项，**不得**并进 B10 一笔带过。**B 组不参与「能不能提交」的判定**，只影响得分；**但 B11 若记 `缺`，须在结论行之外显式提示**（它是硬义务，虽不进 A 组否决，也不该被埋在清单里）。

### 结论行

最后**必须**给一行，**三种形态**：

```
结论：可提交（A 组 15/15 通过；B 组缺口 N 条）
结论：不能提交（A 组未过：A?、A?；另需补：A?）
结论：待补数据（未判定：A?、A?）
```

若 A 组**没有**「不通过」项、但有「未判定」项，结论行写第三种（`结论：待补数据（未判定：A?、A?）`）——它**既不等于**「可提交」（没有依据判通过），**也不等于**「不能提交」（尚无项判不通过）。同时列出要向用户取的那几个值。**第一形态的 `15/15 通过` 只在 A 组**无**「未判定」项时成立**；一旦有项判 `未判定`，一律改写为第三形态（或第二形态的 `另需补` 分句），**不得**把 `未判定` 项算进"通过"的分子。

第二形态末尾的 `另需补：A?` 用于**两种状态并存**时——既有「不通过」项、又有「未判定」项，不写这个分句，那些「未判定」项就会从结论行消失；没有「未判定」项时省略该分句。

**另有一种状态不是判定结果，而是判定无法开始：开工输入缺项。** 若开工输入中**缺"用过哪些 AI 工具"这一项**、**且稿件自身亦无 AI 使用的自述**（**稿件自述算队伍自述的书面形态**，有自述则触发成立、A11 照常判），则**不出具任何结论行**，改为输出一行——它**既不是 `未判定`**（那要求证据不在稿件内，且 A11 在封闭集内**禁止**使用 `未判定`），**也不是第三形态的 `待补数据`**（那针对 A1／A2／A6／A7／A10／A14）：**判定表里不该有表达不出来的状态**，分开表达比塞进任一形态都准确，也避免使用者把"缺输入"误读成"没发现问题"；**补齐后重走判定**。`[社区]`（操作纪律：判定前置条件；官方无对应原文）

```
前置条件未满足：需先确认 AI 工具使用情况（含 LLM／翻译软件／数学软件／代码补全；未用请明确答"无"）
```
