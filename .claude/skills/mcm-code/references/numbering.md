# numbering —— 结果文件名与论文编号对齐

**上位**：`SKILL.md` 的指针（② 落结果）。本文件写**结果文件名带论文编号**这件事，以及它与**结果清单**（`assets/result-manifest.md`）的关系。
**依据标注**：本文件全体 `[社区]` —— 本套件自订工程口径，官方**没有任何明文**。
**不声称穷尽**：命名风格可自定，**唯一硬要求**是"文件名里的编号能与正文的 图 X / 表 Y / 式 Z 对得上"。

---

## 为什么要编号

论文里的每张图 / 每张表 / 每个式都有一个**正文编号**（图 1、表 2、式 (3) …）。结果文件若叫 `out.csv` / `result_final_v2.csv`，到了排版阶段**没人说得清它喂给哪一处**。⇒ **落盘时就把编号写进文件名**，让"文件 ↔ 正文编号"一眼可查。

---

## 命名建议（**可自定，保持自洽即可**）

| 正文对象 | 建议文件名形态 | 例 |
| :--- | :--- | :--- |
| 图 X | `figure-<X>-<短名>.<ext>` | `figure-1-samples.csv`（图 1 的绘图数据） |
| 表 Y | `table-<Y>-<短名>.<ext>` | `table-1-estimate.csv`（表 1 的结果） |
| 式 Z | `eq-<Z>-<短名>.<ext>` | `eq-3-coefficients.json`（式 (3) 的系数） |

★ **编号用正文里的**（不是数组下标 / 循环序号）；短名**全 ASCII**（避免跨工具乱码）。

---

## 与结果清单的关系（**一一对应**）

- 每个**落盘结果**在 `assets/result-manifest.md` 的 `## 结果清单` 里占**一行**；
- `结果文件` 列 = 文件名（相对路径）；`对应正文编号` 列 = 它喂给正文的**哪一处**（`图 X` / `表 Y` / `式 Z`）；
- ⇒ **文件名里的编号** 与 **`对应正文编号` 列** 必须**对得上**（这是本条的机械判据：文件名带编号、且与清单 / 正文对得上）。

| 结果文件 | 对应正文编号 | 生成脚本 | 代码来自 | 确认 |
| :--- | :--- | :--- | :--- | :--- |
| `build/figure-1-samples.csv` | `图 1` | `build/run_model.py` | `本人` | `已核（张三 2026-02-01）` |
| `build/table-1-estimate.csv` | `表 1` | `build/run_model.py` | `AI` | `已核（李四 2026-02-01）` |

（上表两行是**示例**；你的清单里替换为**实际结果**。）

---

## 常见坑（**不声称穷尽**）

- **改图序 / 表序后忘了改名**：正文里"图 2"改成"图 3"了，文件还叫 `figure-2-*` ⇒ 对不上。改序时**同批**改文件名 + 清单。
- **一图多数据源**：一张图的多个输入各是一个文件（如 `figure-1-line-a.csv` / `figure-1-line-b.csv`）⇒ 每个文件都在清单里**各占一行**，`对应正文编号` 都写 `图 1`。
- **中间产物**：不进正文的中间文件**可以**不带编号，但**别与带编号的成品混在同一目录**，以免误引。

★ **本文件不判"正文编号排得对不对"** —— 只要求"结果文件名带编号、且与清单 / 正文对得上"。
