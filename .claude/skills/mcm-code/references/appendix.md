## `[官方]` 规则（**本 skill 唯一的官方依据**）

> **程序 / 软件 / 数据库 / 其他文件，不得随解答提交。**
>
> 原文其一（`corpus/official/instructions.html:1227`）：
> *"… Do not send additional non solution files such as data or computer programs."*
>
> 原文其二（`corpus/official/instructions.html:1305`）：
> *"E. Do not include or send programs, software, databases, and/or other files with your solution, as they will not be used in the judging process."*

★ 即：**提交物 = 论文本体（正文 / 图 / 表 / 支撑材料写在论文里）**；**代码、数据、软件、数据库不随解答提交**。
⇒ **论文附录里不放程序正文**（源码清单 / 脚本全文都不放）。

## 那代码放哪（**过程产物要留存**）

官方**不提交**代码 ≠ **不保留**代码。代码要**自己留着**，用于：复算、被问到时能说明、团队交接。建议：

| 产物 | 放哪 | 进论文吗 |
| :--- | :--- | :--- |
| **求解代码** | 工作仓（如 `build/` 或你的项目目录），**带路径留痕** | **不进**（不提交） |
| **结果文件** | 工作仓；文件名带编号（见 `references/numbering.md`） | 不进（图 / 表本身按 M3 排版进正文） |
| **结果清单** | `assets/result-manifest.md` 落地成一份文件 | **可摘要进正文**（说明结果与来源） |

★ **`build/` 是本仓约定的临时 / 构建产物落点（已入 `.gitignore`）** —— 过程产物放这里，**不污染主干**。
★ **路径写相对**、别写死机器绝对路径（见 `references/reproducibility.md`）。

## 论文里怎么交代"用了代码"这一事实

**要在正文里说明的（`[社区]` 工程口径）**：
- **算法 / 求解方法是自写还是用现成库**（`求解部分用 <语言> 实现，见附录说明`一类**文字交代**，不是贴代码）；
- **可复现信息**：随机源种子、软件版本（便于别人复算）——**写在方法节或附录的说明段**，不是贴在源码里；
- **结果来源**：结果清单里每个结果 ↔ 正文 图 X / 表 Y / 式 Z 的对应（可在附录给一张**摘要表**）。

**不写 / 不做的**：
- **不把源码贴进附录**（官方明文，见上）；
- **不交代"用了什么 AI 工具"** —— 那是 **`mcm-ai-disclosure`** 的活（AI 使用披露），**本 skill 只管代码的处置与可复现**，**不管工具披露**。

---

## 常见坑（**不声称穷尽**）

- **把"代码"和"AI 披露"混成一件事**：两者受众与位置不同 —— 代码处置是**工程 + 官方提交禁令**，AI 披露是**官方 AI 政策**。分开写。
- **附录里贴了 `\begin{verbatim}` 源码块**：这违反 `corpus/official/instructions.html:1227` / `:1305` —— 删掉，改成**文字交代**。
- **只写"使用了代码"却不给复现信息**：种子 / 版本 / 命令至少要有一处，否则别人复算不了。

★ **本文件不判"附录排版好不好看" / "AI 披露写得对不对"** —— 只要求"论文附录里不含程序正文"，并给代码与过程产物的**处置去向**。
