# mcm-code —— 求解代码的可复现工程规范（三跳：从代码到论文）

**一句话**：求解代码从**写**到**进论文**只有三跳 —— **写代码**（固定随机源 / 环境 / 路径）、**落结果**（落盘 + 文件名带编号）、**进论文**（附录处置）；每跳只说"该干什么 + 该看哪份 `references/`"，**不复述**其中的内容。

## ★★ 边界声明（必读）

> **本 skill 给出数据来源与代码规范；最终判断与结论由队员负责。**

> **凡由 AI 写的代码，队员必须自己跑通并核对结果后方可采信** —— 同一节把「辅助写代码」列在建议谨慎侧。

★ 这两句不是口号：结果清单里 `代码来自 = AI` 的**每一行**，`确认` 列都必须记「已核（跑过人 + 日期）」。

## 什么时候用 / 不用

- **用**：要写**求解代码**、要**固定随机源**让结果可复现、要把**结果落盘**、要让**结果文件名与正文编号对齐**、要填**结果清单**、要处理**论文附录里的代码**（放哪 / 怎么交代 "用了代码"）时。
- **不用（边界，各归各）**：
  - **选模型 / 给算法** ⇒ M4 的 `mcm-model-select`（本 skill **不给算法**）；
  - **找数据 / 来源表 / 清洗与口径对齐** ⇒ M5 的 `mcm-data`；
  - **出图 / 出表 / 示意图** ⇒ M3 的绘图类 skill（本 skill 只保证**喂进去的结果文件**来源清楚、可复现）；
  - **写论文正文某一节** ⇒ M2 的 `mcm-section-writer`；
  - **交代"用了什么 AI 工具"** ⇒ `mcm-ai-disclosure`（本 skill 只管**代码的处置与可复现**，**不管工具披露**）。

## 三跳（**从代码到论文**）

| 跳 | 触发（赛期你看到的） | 指向 |
| :--- | :--- | :--- |
| **①** | **要写求解代码**：入口固定随机源、记环境、路径不写死 | `references/reproducibility.md` |
| **②** | **结果要进论文**：落盘、文件名带编号、与 图 X / 表 Y / 式 Z 对齐 | `references/numbering.md` |
| **③** | **代码怎么随论文交代**：附录处置、代码放哪、怎么说明"用了代码" | `references/appendix.md` |

★ **三跳各自独立、可单用**：只写代码不落盘也要过 ①；落了盘但还没进正文就用 ②；论文不附代码但过程产物要留存就用 ③。
