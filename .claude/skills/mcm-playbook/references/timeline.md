## 3. 北京时间换算（本支现算 · ★ 只对 UTC+8 成立）

这个换算**不是常量，是本支当场用 `zoneinfo` 算出来的结果**。
复算命令（**一字不改地跑**）：

```bash
python -c "from datetime import datetime; from zoneinfo import ZoneInfo; est=ZoneInfo('America/New_York'); bj=ZoneInfo('Asia/Shanghai'); [print(l, s, 'EST ->', datetime.strptime(s,'%Y-%m-%d %H:%M').replace(tzinfo=est).astimezone(bj).strftime('%Y-%m-%d %H:%M'), '北京') for l, s in [('报名/缴费截止','2027-01-28 15:00'),('开赛','2027-01-28 17:00'),('停止修改','2027-02-01 20:00'),('提交截止','2027-02-01 21:00')]]"
```

本机实测输出（Python 标准库 `zoneinfo`，2026-10-03）：

```
报名/缴费截止 2027-01-28 15:00 EST -> 2027-01-29 04:00 北京
开赛 2027-01-28 17:00 EST -> 2027-01-29 06:00 北京
停止修改 2027-02-01 20:00 EST -> 2027-02-02 09:00 北京
提交截止 2027-02-01 21:00 EST -> 2027-02-02 10:00 北京
```

- ★ **边界**：这条换算**只对 UTC+8（`Asia/Shanghai`）的队伍成立**。
  别的时区要自己推，**本 skill 不替别的时区推**。
- ★ **不要写死"北京时间 = EST + 某小时"这类常量**：那是把一个**观测**升格成**规律**；
  正确写法是"**跑上面那条命令**"（先例：本仓"写测量协议，不写预期值"）。

## 4. 我们的：阶段表（★★ 全是构造）

★★ **下表每一刀都是本支的构造，不是官方口径**——官方**只有** §1 那几个硬时刻，
**没有任何内部里程碑**。⇒ 逐刀写明"为什么切在这"，并逐条标「构造」。

**两个端点**：起点 = **开赛**（官方硬时刻）、终点 = **停止修改**（官方硬时刻）。
中间的小时跨度（99 小时）是 §2 的**推算值**；下面各刀的小时数是**本支的构造**。

| 阶段 | 小时（自开赛起） | 在干什么 | 该调哪个 |
| :--- | :--- | :--- | :--- |
| **0 选题** | 0–5 | 通读六题、定题；想清"这题最后能不能给出一个清晰结论" | `mcm-topic-select`——本阶段只给"选题要看哪四件事" |
| **1 破题** | 5–14 | 重述问题、立假设并论证、定模型方向 | `mcm-section-writer`（逐节写作范式）——M2 的 `mcm-paper-architecture`（页数预算）**仍未建** |
| **2 建模与求解** | 14–50 | 主体；★ **图和表要尽早出第一版** | `mcm-figure-choose` → `mcm-plot-python` / `mcm-plot-matlab` / `mcm-plot-origin` / `mcm-table` / `mcm-schematic` |
| **3 写作主体** | 50–80 | 按页数预算写正文与摘要 | `mcm-section-writer`（逐节写作）· `mcm-latex-format` · `mcm-abstract` · `docs/mcm-writing-discipline.md`（M2 的 `mcm-paper-architecture` **未建**） |
| **4 收口与自查** | 80–99 | 合规 · AI 声明 · 格式 · 打包提交 | `mcm-selfreview` · `mcm-ai-disclosure` · `mcm-latex-format` |

**每一刀的理由**（★ 逐条标「构造」）：

- **为何终点是"停止修改"而不是"提交截止"**：★「构造」——"停止修改"是**不能再动论文**的那条线，
  写作用的是论文；"提交截止"（比它晚一点）留给**打包与上传**，归阶段 4 的尾巴。
- **为何切在 0 / 5**：★「构造」——选题是一个**有限时长**的独阶段（六题通读 + 定题，§2.6.3
  六题任选其一、只交一题）。过了这个点还没定题，后面全是返工。
- **为何切在 5 / 14**：★「构造」——破题（重述 / 假设 / 方向）**必须先于**建模：
  没有假设与方向，建模无从下手。这是**依赖**，不是经验。
- **为何切在 14 / 50**：★「构造」——建模与求解是**主体**，给它最大的一块时间。
- **为何切在 50 / 80**：★「构造」，且背后是**依赖**——写作要有主体结果可写 ⇒
  **第 3 阶段必须在第 2 阶段之后**；★ 同理，**第 2 阶段里"图和表要早出"也是依赖**——
  写作阶段要引用它们，拖到最后做会一起返工（且图 / 表 / 附录都计入页数上限，§2.1.4）。
- **为何切在 80 / 99**：★「构造」——**第 4 阶段不可压缩**：`mcm-selfreview` 的**合规组是一票否决**
  （没过合规，内容再好也无效）⇒ 必须留够它 **+ 打包提交**的时间。
- ★ **99 本身是硬的**（"开赛 → 停止修改"这条跨度）⇒ 一切**倒推**；
  被标「构造」的只是**内部切点**，不是那条硬线。

## 5. 覆盖机制（边界可覆盖；不一致时明说）

- ★ **边界可被用户覆盖**：这张表是**构造的默认值**，不是规则。赛程该按你的实际切，工具不拦。
- ★ **"按表"与"按进展"不一致时，明说**：本 skill 的输出契约要求**两个位置都报**
  （表上的阶段 + 实际的阶段），并**按进展**排动作——因为"该调哪个 skill"取决于
  **手里有没有可用的产物**，不取决于钟点（见 `SKILL.md` 的双驱动一节）。
- ★ **如实交底**：整个人工覆盖机制、以及双驱动里"**按进展**"的那一半，
  **依赖用户如实自报**，本工具**核不了**（设计 §8-5）。
- ★ **不声称穷尽**：上面这张表的每一刀都是**构造**，官方**没有**任何内部依据能改进它
  （设计 §8-1）——它是**默认建议**，不是"官方赛程"。
