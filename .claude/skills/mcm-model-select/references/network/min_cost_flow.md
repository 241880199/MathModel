# 最小费用流（`min_cost_flow.m`）

> **要在满足给定输送量的前提下花最小代价时用**：在带容量的网络上，求把指定流量从源送到汇的**最小总费用**方案（运输调度 / 指派 / 带价网络）。

**归属**：类索引 `references/network.md` · 骨架 `assets/matlab/network/min_cost_flow.m` · 参照 `tests/skills/model-select/verify/min_cost_flow.md`。
★ **与相邻方法的边界**：只问"最多能送多少"（无费用）⇒ `references/network/maxflow_mincut.md`；只问"两点最省路径"⇒ `references/network/shortest_path.md`。

## ① 适用判据

- **用**：题面**既要满足输送量、又要最小化总费用**；弧上有**单位费用 + 容量**；可退化为**运输问题 / 指派问题**的图论形式。
- **反面（什么时候不该用 · 会误用的场合）**：
  1. **没有费用、只求最大流** ⇒ 走 `references/network/maxflow_mincut.md`（别给最小费用流强加费用模型）。
  2. **只求单条最省路径** ⇒ 走 `references/network/shortest_path.md`。
  3. **需求量超出网络最大流** ⇒ **无可行流**，须先算最大流判断可行性（凭经验）。
  4. **含凸 / 非线性费用** ⇒ 超出线性最小费用流模型，须另建（凭经验）。

## ② 标准建模步骤

1. **建图**：有向弧 (容量, 单位费用)；定源、汇、**需求量**。
2. **判可行**：需求量 ≤ 最大流，否则无解。
3. **求最小费用流**：**逐次最短路（SSP）** —— 每次在**残量网络**上找**最小费用**增广路（含反向负费用弧），沿路增广。
4. **循环**：直到满足需求量或无可增广路。
5. **数值验证**（见 ⑥）：小网络**手算**逐条增广与总费用。
6. **报告**：总费用 + 各弧流量 + 增量边际费用。

## ③ 参数与假设

| 项 | 说明 |
| :--- | :--- |
| **输入** | 弧表 `E`（`[u v cap cost]`）· 源 `s` · 汇 `t` · 需求量 `demand` |
| **输出** | `cost`（最小总费用）· `flow`（各弧流量）· `demand` |

**显式假设（必须写进论文）**：
1. **线性费用**：总费用 = 各单位费用之和（无规模效应 / 折扣）。
2. **容量约束 + 流量守恒**（同最大流）。
3. **需求量已知且可行**（≤ 最大流）。
4. **静态**：容量与费用不随时间变。

## ④ 常见坑（每条：实测依据 / 或标明"凭经验"）

1. ★★ **上游实现 `corpus/algorithms/src/GraphTheory(图论)/detailed/最小费用流/BGf.m` 有确证的算法性缺陷 —— 在 6 点 10 弧的网络上传入即不终止（>500 s，正常应毫秒级；小实例正确，故非全盘失效）。实测**（`corpus/algorithms/INDEX.md` §10.1 登记；批量运行超时 + 单独复现）。⇒ **本骨架自写正确版（SSP + Bellman-Ford），且不拿该上游实现当参照**；若照抄上游会**挂死**。
2. **残量网络漏建反向负费用弧** ⇒ 无法退流优化 ⇒ 得到"局部最短"而非全局最小费用（凭经验）。
3. **需求量超过最大流不先判可行** ⇒ 迭代不收敛或报错（凭经验）。
4. ★ **拿 MATLAB 内置 / 归档实现当"独立参照"**：同机同实现（或教辅级未验证）不构成独立验证（任务书 B）。本方法参照走**手算小图**（**实测**：min cost = 13）。
5. **费用可为负**：反向弧天然为负费用，须用 Bellman-Ford（本骨架用）而非 Dijkstra（除非配势函数）（凭经验）。
