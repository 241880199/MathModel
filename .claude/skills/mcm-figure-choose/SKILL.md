# mcm-figure-choose —— 图型决策（数据关系 → 图型）

**只回答一件事**：手上这组数据**该画成哪种图**、**为什么**、**落笔时哪些设计要点要落到位**。

**不回答**：图**通常长什么样**（规范在 `references/house-style.md`）；更不回答"像不像获奖论文"（那是判据问题，见规范的 `H13`）。
**不产代码**，也不给"这张图合规吗"的判词——边界见「边界」一节。

## 什么时候用

用：

- 手上有一组数据，问"**这个数据该用什么图**"；
- 已经画了一张图，被评委或队友说"**看不懂 / 读不出重点 / 为什么用这个图**"；
- 在两个候选图型之间做决定（"折线还是柱"）。

**不用**（问了也是换个地方答）：

- 只问**交付形态**——图注怎么写、字号多大、用什么色、图要不要横过来 ⇒ 那是规范条目，指针见「指针」一节；
- 只问"**帮我把它画出来**" ⇒ 见「边界」一节的产代码出口。

## 决策树：先挑**数据关系**，再挑图型

**入口挑的是数据关系，不是题型**——题型是题目的属性，数据关系才是图的属性。
**怎么问用户**——一句话，按这个顺序问：

> 你手上这组数据，**横着排开是什么**？你要回答的是下面哪一个问题：
> **谁大谁小** · **长什么形状** · **两个量一起怎么变** · **一个整体怎么分** · **随时间怎么走** ·
> **在哪儿** · **谁流到谁** · **系统怎么演化（没有数据，只有方程和假设）** · **结论有多稳**？

用户答上哪一个，就进哪一个入口。答得含糊时（"我就是想画个图看看"）**再追一句**："你想让读者**比大小**、**看形状**，还是**看关系**？"

| 入口（数据关系） | 用户的那句话 |
| :--- | :--- |
| **比较** | 谁大谁小 / 差多少 |
| **分布** | 长什么形状 / 有没有双峰 / 尾巴多长 |
| **相关** | 两个量一起怎么变 / 有多强 / 有没有结构 |
| **构成** | 一个整体怎么分 / 各部分占多少 |
| **时序** | 随时间怎么走 / 周期 / 突变 |
| **空间** | 在哪儿 / 多密 / 空间上聚不聚 |
| **流程** | 谁流到谁 / 瓶颈在哪 / 哪条路径的量最大 |
| **机理** | 系统怎么演化 / 参数变了会怎样 |
| **不确定性** | 结论有多稳 / 最坏能坏到哪 |

进了入口之后走三步：**首选 → 备选 → 禁忌**。每个入口的首选图型、备选、禁忌，以及图型名册与题型反查表，全在 `references/chart-types.md`，**本文件不复述**。两条硬纪律（都出自那棵决策树）：

- **首选不成立才翻备选**，并且要**说清首选为什么不成立**（组数太多 / 变量太多 / 要看的不止一层）；
- **落笔前先读禁忌**：禁忌说的是"**这条数据关系 + 这个图型 = 读者会读错**"。用户的意图命中禁忌时**当场说出来**，不能只把图型甩出去。

## 输出契约（每次都给齐这三样）

- **推荐图型**：给**一个首选**；首选不成立时给备选，并写明首选为什么不成立。
- **理由**：这条数据关系**为什么**落到这个图型——指"它靠哪条视觉通道承载"（长度 / 位置 / 面积 / 角度 / 连线 / 颜色深浅…），**不是**"大家都这么画"。
- **设计要点**：逐条写成 `要点 → H<n>`，**只写 ID、不抄规则原文**（规则原文、数值与验证状态都在规范里）。
   要点从哪来：`chart-types.md` 每个入口的正文（数据关系层面的取舍）+ 该入口已经标出的 `H<n>`；**哪条要点归哪个 `H<n>` 以那份文件为准，本文件不另立一份对应表**。

**引用纪律**：设计要点里出现的每一个 `H<n>` 都要能被读者**直接翻到**——规则、数值、来源、验证状态全在 `house-style.md` 里那一条上。**本文件不给任何阈值、占比或样本读数**（写进本文件就是造第二份权威，见「边界」一节）。

## 边界

- **不产代码。** 本 skill 只出"图型 + 理由 + 设计要点"，不写 matplotlib / MATLAB / LaTeX 代码。要落到代码，交给绘图 skill：
  - `mcm-plot-python`
  - `mcm-plot-matlab`
  - `mcm-plot-origin`

  **交接状态**：`mcm-plot-python`、`mcm-plot-matlab` 与 `mcm-plot-origin` 三个绘图 skill **都已建**
  ⇒ "产代码"这一段可以直接交给它们，本 skill **不再有待建载体**。
- **不做合规检查。** 图的机械判据在出货检查器（`check-figure-style.py` 的宽度 / 颜色 / 图注那一族），**不在本 skill**；本 skill 不出"这张图合规吗"的判词。
- **不声明"规范已被全面验证"。** `house-style.md` **逐条**标了验证状态（① 有机械守卫 / ② 只有判断层 / ③ 无验证），而且判断层的**实际射程只有单条规则**——是哪一条、为什么，见 `house-style.md` 的「验证状态三级」那一段与 `H6` 那一条；每条规则自己的验证状态写在它的「验证」行里。**覆盖到哪、没覆盖到哪，一律以那份文件为准**，本文件不把它总结成"可靠"。
- **不重述任何规范数值。** 阈值、占比、样本读数一律在 `house-style.md`；每个数的口径、样本范围、已知偏差与复跑命令在 `provenance.md`。本文件里出现的数只有 `H<n>` 编号与下节声明的那一个数。

## 指针（唯一权威）与本文件的数字

- **规范正文**（图通常长什么样、每条规则的数值与验证状态）：`references/house-style.md`

**机器投影**：`assets/mcm-style.json` 是本规范给**实现方**用的机器投影（由
`tests/skills/figure-choose/gen-style-table.py` 从本规范重放产出）。
**分工**：规范正文（本目录 `references/house-style.md`）是**唯一权威**；那份 json 是它的投影，**勿手改**——
每个载体（`mcm-plot-*` 等）只读它、各自映射成本工具的设置。

- **口径与复跑命令**（每个数的分母、样本范围、已知偏差）：`references/provenance.md`
- **决策树正文**（九个入口的首选 / 备选 / 禁忌 + 图型名册 + 题型索引）：`references/chart-types.md`

**本文件的数字只有两类**：① 指针里的规则编号 `H<n>`；② **结构性计数**——全文只有一处，就是决策树的入口数 **9**（数一数上一节那张表的行数即可复核，与 `chart-types.md` 的入口数一致）。
**除这两类以外，本文件不出现任何数**：规范的阈值 / 占比 / 样本读数一律不写，要说回上面三份文件去说。
