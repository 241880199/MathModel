# schematic-style —— **示意图**的规范（`mcm-schematic` 规范正文）

> **本文件回答什么**：技术路线图 / 机理示意图 / 模型结构图**该长什么样** —— 尺寸 · 配色 · 线型语义 ·
> 节点与箭头的含义 · 分层与节点数的上限。
> **不回答**：你这道题该画哪种图（图型决策在 `mcm-figure-choose`）；也不回答"图里说的话对不对"（那是你的模型）。
>
> **三条纪律**：
> ① **每条规则与它的边界同时写** —— 只写"应当怎样"、不写"什么时候不成立"的条目，本文件里不存在；
> ② **出处两分**：**语料读数**（`tests/m3-schematic-recon/`，Task 0 的侦察）与**惯例**（本支自定的选择）。
>    ★ 本仓硬规矩：**不许把"我们的选择"写成"事实"** —— 一条规则若与语料读数**相反**，它必须把那条读数写在旁边；
> ③ **数值只在本文件与 `assets/schematic-style.tex`**：`SKILL.md` 与 `references/workflow.md` **不复述任何规范数值**。

### 1.1 ★ `H1–H14` 逐条的适用性（**大部分不适用**）

★★ **不许把 `house-style.md` 总结成"它也管示意图"**：那份文件的 `H` 条**多数是为数据图写的**
（坐标轴 / 刻度 / 图例 / 信息密度 / 多面板），对示意图**不适用**。下面逐条点名（**此表不声称穷尽**，
它只是把那份文件今天的 `H` 条**逐条**过一遍）：

| 条 | 对示意图 | 为什么 |
| :--- | :--- | :--- |
| `H1` 图宽 | **适用**（经 `F1`） | 宽度是版面上的事，与画的是什么无关；本支的做法见上表 |
| `H2` 分母口径 | **适用** | 报"图宽占正文多少"必须写分母 —— 这条是**口径纪律**，跨支通用 |
| `H3` 取向与图高 | **不适用** | 那条的默认（横向 / 宽高比常见带）是**画数据图**的观感；示意图的宽高由**内容**定 |
| `H4` 配色密度 | **部分适用** | `F2` 照样在量彩色主色数；但那条讲的是**系列色**的观感，示意图没有"系列"，配色由 `S4` 管 |
| `H5` 默认色序 | **不适用** | 它讲的是**系列色**用没用工具默认色序；示意图没有"系列" |
| `H6` 不用饼图 | **不适用** | 讲的是**构成数据**的画法 |
| `H7` 3D 图 | **不适用** | 讲的是数据的三维表达 |
| `H8` 多面板 | **不适用** | 讲的是子图排布；本支是**一张示意图 = 一个图** |
| `H9` 图注模板 | **适用**（经 `F3a–F3d`） | 图注在版面上是同一件事 |
| `H10` 坐标轴 | **不适用** | 那讲的是**数据轴**（顶右框线 / 刻度方向 / 轴标签带单位）。本支 `mechanism-block` 里的"坐标"是**示意轴**（一根方向 + 一个高度标注），没有刻度语义 |
| `H11` 网格 / 图例 / 双 Y 轴 | **不适用** | 数据图件 |
| `H12` 字号 / 线宽 / 字体族 | **部分适用** | **字体族同源**那半适用（`F6` 在量）；字号与线宽的**那条数值**是数据图的、**本支不回引**（本支的线宽与字号在 `assets/schematic-style.tex` 里另有取值） |

| `H14` 显式色序 | **适用**（经 `F5`） | 本支只要有非灰的色，就必须取自那条色序 |

## 2. 第二层 · 本支新增的 `S` 条（**示意图特有**）

★ 设计稿里 `S1`–`S5` **全部标着〔待读数〕**。Task 0 之后**逐条处置**如下：
**能升格为实测的升格（附读数与边界）**，**拿不到读数的如实降为惯例**。**处置结果与 Task 0 的读数逐条对得上**。

### `S1` 语义 —— **惯例**

- **规则**：**节点 = 动作或状态；箭头 = 有方向的因果 / 流转**；不用无向连线。
- **出处**：**惯例**（本支自定）。★ Task 0 **没有**产出"示意图里节点 / 箭头表示什么"的语料读数
  ⇒ 这一条**如实降为惯例**，**不冒充实测**。
- **边界**：**无向关联**（"这些因素互相影响"）**没有好画法** ⇒ 该场景**劝退，不硬画**。
  依据是侦察件「不做清单」里那条网络 / 拓扑图（`#44`）—— ⚠️ 那是 **n=96 的人眼抽样判断**，不是机械读数。
- **落点**：`assets/schematic-style.tex` 的 `mcmarrow` 家族（全部带箭头）。

### `S2` 线型 —— **惯例**

- **规则**：**实线 = 主流程；虚线 = 回环 / 可选 / 反馈**；同一张图里**线型语义只许一种解释**。
- **出处**：**惯例**（本支自定）。★ 语料那侧**量不到**：80.6% 的图是位图，线型语义没有可量的对照
  ⇒ 这一条**如实降为惯例**。
- **边界**：需要**第三种**语义时**加图例**，**不许**再借线型。
- **落点**：`assets/schematic-style.tex` 的 `mcmarrow`（实线）/ `mcmdash`（虚线）。
  ⚠️ **例外登记**：`mechanism-block` 另有一维"**流的粗细**"语义（`mcmflow` / `mcmflowthin`）——
  那是**粗细**、不是线型，**不与本条冲突**；但它同样**只许一种解释**，且**一次只编码一个量**。

### `S3` 尺寸 —— **惯例**

- **规则**：**节点尺寸由文字内容决定**，**不写死**固定的宽高（格子可以定死，**框跟着字走**）。
- **出处**：**惯例**。
- **边界**：长文本节点会挤爆版心 ⇒ **缩字号或改断行**，**不许溢出**。
- **机械兜底只管一半（写清）**：出货 `F1` 兜的是**整图宽**（页盒 ÷ 版心），
  **兜不住"节点里的字被压成几行 / 小到读不下去"** ⇒ 那一层靠**渲图看一眼**（见 `workflow.md`）。

### `S4` 配色 —— **★ 产物规范，与语料相反（这条必须连读数一起读）**

- **规则**：默认**单色系深浅 + 至多一个强调色**，不用彩虹。
- **出处**：**本支的选择**。★★ **语料不是这样** —— Task 0 **读数 3**：
  语料里"单色系（彩色主色 ≤1）"只占 **38.0%**（793 / 2085），**中位 3 个彩色主色**（p90 = 13）。
  ⇒ 本条**是我们的规范，不是对获奖论文现状的描述**。**不许**把它写成"获奖论文都这么配色"。
- **边界**：
  ① **强调色超过一个就没有"强调"了** ⇒ 需要第二个时**改用形状 / 线型区分**；
  ② **非灰的色必须落在 `house-style.md` 的显式色序里** —— 机械兜底 = 出货 `F5`（显著色**精确命中**那条序列）；
    彩色主色数的上限另有 `F2` 兜底。
- **落点**：`assets/schematic-style.tex` 的 `mcmInk` / `mcmLine` / `mcmFaint` / `mcmFill` / `mcmFillAlt`（近灰）
  ＋ `mcmAccent`（唯一非灰）＋ `mcmaccent` 样式（**整图至多一处**）。

### `S5` 分层 / 节点数 —— **★ 惯例，无读数背书**（设计稿在这里要一个"具体数字"）

- **规则（惯例）**：**单行并列 ≤ 5 个节点**；**分层 ≤ 4 层**；**全图节点 ≤ 15 个**。
- **出处**：**本支自定的可读性惯例**。
  ★★ **Task 0 拿不到这条的语料读数**：读数 6（形态粗分类）**做不到机械定稿**（明文降级，
  见侦察件「骨架表定稿规则」）⇒ "获奖论文的示意图通常几个节点 / 几层"**根本没有读数**。
  ⇒ **不许**把上面三个数说成实测，**也不许**为它们编一个"出处"。
- **只有"单行并列 ≤ 5"这一个有算式**（**算式不是读数**）：本支把整图宽写死为一个固定值
  （见 `assets/schematic-style.tex` 的 `\mcmscfigwidth`）。一行并排 `n` 个节点时，按**样式层自己的并列间距
  `\mcmscgapcross`（4mm）**摆 —— `n` 个框 + `n−1` 个间隙铺满整图宽 ⇒ **框宽 = (图宽 − (n−1) × 4mm) ÷ n**：
  `n = 4` 约 1.49in、`n = 5` 约 1.16in、`n = 6` 约 0.94in、`n = 7` 约 0.78in、`n = 8` 约 0.66in。
  框宽降到 0.75in 以下**要到 `n = 8`**（`n = 6` 是 0.94in —— **订正**：早先那句"`n = 6` 起节点框就降到
  0.75in 以下"没写明用的是哪个间隙，**照它算不出来**；那个结论只在一个未声明的约 0.33in 间隙下才成立）
  ⇒ 取 **5** 为界，比那条可读性下限早三格。（0.75in 是**可读性经验值**（`\small` 的英文词开始被压行的那一档），
  **不是量出来的**；**这一串是在写死的宽度上做的算术**，不是量语料量出来的。）
  余下两个数（层 ≤ 4 / 全图 ≤ 15）**连算式都没有**，就是惯例 —— 照实说。
- **边界**：**超限 ⇒ 拆成两张**，或**改用文字描述**，**不硬塞**。

### 原语兜底宏的调用形态（**至少一处真跑作证**）

骨架族之外**回落到原语**时，样式层给了分组框宏 `\mcmgroup`（定义在 `assets/schematic-style.tex`）。
它的签名是 **`\mcmgroup[<额外样式>]{<fit 列表>}{<分组名>}`**：第二个参数是 **`fit` 库的节点列表**
（形如 `(a)(b)(c)`），**不是**分组名 —— 分组名在**第三个**参数。真实调用例（本文件即这一处真跑）：

    \mcmgroup[mcmgroupfill]{(a1)(a2)(a3)}{layerBox}

★ 这条路径原本**零覆盖**（五份骨架没有一个走它）⇒ 上面这一例在 `pdflatex` 下**真跑过一次**作证：
照**本签名**写 ⇒ `rc=0` 出页；照**旧注释**的 `\mcmgroup{框名}{节点名,…}` 写 ⇒ 第二个参数被当成 `fit` 列表、
tikz 报 `Cannot parse this coordinate`、**编译失败**。**分组框的常规画法仍走 `mcmgroup` 样式**
（见 `model-layered` 骨架的 `\draw[mcmgroup] … rectangle …`），宏只留给"把一组**已命名**节点框起来"这一路。
