# mcm-schematic · 出图流程

本文件是 `SKILL.md` 的流程正文。**本文件与 `SKILL.md` 一样，不复述任何规范数值**；
尺寸 / 配色 / 线型 / 分层上限一律回 `references/schematic-style.md` 与 `assets/schematic-style.tex` 去说。

★ 文中出现的阿拉伯数字**逐处都不是规范值**，它们只是：**判据编号**（`F<n>` / `A<n>` 这类指针型 ID）、
**退出码**（`rc=0`）、`\usepackage` / `\usetikzlibrary` 这类**宏包名里的版本无关字面**、
命令里的**计数读数**、仓内文件**行号**（`<file>:<line>`）、`pdflatex` 的命令行开关、
以及临时目录名；**这一列表不声称穷尽**。
（★ 本文件"不复述规范数值"这半句**靠人读与复核守**：实测把规范数值写进本文件，现有的几个检查器照样 PASS
—— 先例见 `mcm-table/references/workflow.md` 的同一段；**哪个检查器读本文件、判什么，以它自己的扫描面为准**。）

## 前置条件（**环境事实**，不是规范）

- **`pdflatex` 要在 PATH 上**（本机 TeX Live 2026 实测在）。**本 skill 不自动安装**，也不代管宏包。
- **本机没有 `standalone` / `preview` / `pdfcrop`**（`kpsewhich` 实测）⇒ 页盒靠 `geometry` 的 `paperwidth` 钉死。
- **路径含空格 / 非 ASCII 时不把路径直接塞给 `pdflatex`** ⇒ 先复制进**仓内 `build/`（已 gitignore）**再编。
- **网页端未验 · 跨机未验 · 干净检出复跑不相容**（没有本机的 TeX 发行版就跑不出编译读数）。

流程：**定类别 → 挑骨架并说出为什么 → 改 → 编译 → 渲图看一眼 → 交付**。
最后一步与前几步一样是**固定环节**，不许省。

## 第一步 · 定类别（**一句话，不成体系**）

先把这段描述归进**三类之一**：

1. **技术路线图** —— 有**先后 / 分支 / 汇合**的过程（数据怎么流、方案怎么分叉）；
2. **机理示意图** —— 有**实体与耦合**的结构（储罐 / 流 / 场 / 控制器）；
3. **模型结构图** —— 有**层次或并列**的组成（输入层 / 隐藏层 / 输出层；模块并列）。

★ **为什么本支自带这一小段**：实测 `mcm-figure-choose` 的入口树里，与示意图沾边的只有"流程"入口的一条首选，
**机理示意图与模型结构图在那棵树里没有位置** ⇒ 这是**如实补位**，不是越界。
★ **本支不重述那棵决策树的任何内容**；要选"画成图还是排成表""该用哪种图型"，回
`mcm-figure-choose` 去问。

## 第二步 · 挑骨架，**并说出为什么挑它**

骨架在 `assets/skeletons/`。**挑最接近的一份**（与决策树"首选不成立才翻备选"同形）：

| 骨架 | 画什么 |
| :--- | :--- |
| `pipeline-linear` | 直线流程（一串阶段，＋一条回环虚线） |
| `pipeline-branch` | 判定菱形 + 多路 + 再汇合 |
| `model-layered` | 分层结构（每层若干并列单元 + 跨层连线） |
| `loop-feedback` | 反馈回路（存量-流量、正 / 负反馈环） |
| `mechanism-block` | 机理块图（储罐 / 流 / 示意坐标 / 耦合箭头） |
| `banded-flow` | 分层带 + 小图形编码（分组靠**背景带**而非框；重复单元 / 占比**画成图形**） |

★ **"为什么挑它"是交付物的一部分**（见下面「产物契约」第 ③ 件），**不许省**。
差别大时**明说差在哪**，**不许**"凑合着改"。
★ **骨架族为何是这六份**：**前五份**的成员由 Task 0 的**判断**保留（那份侦察里的**形态粗分类
做不到机械定稿**、已明文降级）—— 逐份理由见 `tests/m3-schematic-recon/README.md`
「起步五份的逐个去向」。**读完那份再去挑**，别把"我挑的"当成"读数挑的"。
★ **第六份 `banded-flow` 不在那份侦察件里**：它是 **2026-10-10 随视觉语言改版新增的**
（`S4.1` / `S6` / `S7` 三条的落地演示），**不是** Task 0 抽样得出的 —— 那三条规范
**同样没有本仓语料读数背书**，照实说。

## 第三步 · 改（**只动内容与结构**）

每份骨架的文件头都带一张**「改哪儿」对照表**，分三类：

- **内容**（改文字）—— 直接改；
- **结构**（加删节点 / 层 / 环）—— 照表里的算式重算坐标；
- **不许动**（颜色 / 线宽 / 圆角 / 字号）—— 那些是**规范**，要改得走 `assets/schematic-style.tex`。

★★ **样式只有一个来源**：产物样式 = `assets/schematic-style.tex`（骨架一律 `\input` 它）。
**骨架里不许出现样式字面量** —— 你一旦在骨架里写死一个颜色，这张图就与其余图脱钩了。

## 第四步 · 编译（**固定环节**）

```
pdflatex -interaction=nonstopmode -halt-on-error <复制到临时目录里的 .tex>
```

- **`rc=0` 是硬门**。
- **把 `Overfull \hbox` 计数报出来**（换行 / 越界的第一手信号）。
- ★ **骨架文件 `\input` 的是 `../schematic-style.tex`** ⇒ 编译时**保持这个相对位置**
  （把 `schematic-style.tex` 与该骨架放在同一层级里），或把 `\input` 那行的路径改到你实际放它的地方。
- ★ **粘进论文时**：把 `\input{schematic-style.tex}` 一行放进**论文的导言区**，
  把 `tikzpicture` 环境放进正文。**`\documentclass` / `geometry` / `\begin{document}` 那几行不要粘**——
  它们只是为了让骨架**能自己编出一个页盒等于图框的 PDF**（判据 `F1` 量的是页盒）。

## 第五步 · 渲图看一眼（**固定一节，不许省**）

把编出来的 PDF **渲成 PNG，agent 自己看一眼**，并写下**从这张图读到了什么**。

机械层判的只是**能机械化的那几层**：图宽（`F1`）· 配色与色序（`F2` / `F5`）· 图注（`F3a–d`）·
底色（`F4`）· 字体（`F6`）。它**判不了**：

- **两个节点框有没有压在一起** · **箭头端点有没有戳进框里**；
- **两条线分不分得清哪条是主流程** · **图例丢没丢** · **标注有没有落到画外**；
- **节点里的字有没有被压成好几行 / 小到读不下去**。

★ **本支必看的那几点**（写进"从这张图读到了什么"）：① 箭头有没有压住字；
② 主流程与回环/反馈**一眼分得开**吗；③ 图例（若用了第三种线型语义）在不在；
④ 标注有没有落到图外；⑤ 节点内文字有没有溢出。

- **谁看**：**出图的 agent 自己先看**（不是"交给用户看"就算数）。
- **路径怎么给**：产物写到仓内一个**被 git 忽略的固定目录**（`build/` 下本模块的子目录），
  把**仓内相对路径**连同那句话一起交给控制者与用户。

**为什么这一步不可省**：`A` 族判据**只落地了三条**（`A1` 节点框不重叠 · `A3` 文字不越页框 ·
`A4` 描边线宽；见 `schematic-style.md` §3.1），而 **`A2`（箭头端点）降级、且它本就是"看一眼"那类**。
⇒ **"箭头有没有戳进框里 / 两条线分不分得清 / 图例丢没丢 / 字有没有被压成几行"仍然只能靠眼睛**。
先例：origin 那支的粉边与图例压数据、表格那支的超长表题，**判据一条都不报**。

★ **要机械判时怎么跑**（判据的家是**同一把尺**）：带 `--schematic` 调
`tests/skills/figure-choose/check-figure-style.py`，它会追加 `A1`/`A3`/`A4` 三行；
**不带这个旗标**只打 `F1–F6`（数据图那条路，一字未动）。`A4` 的允许线宽是
`assets/schematic-style.tex` 的**转写**（改样式层要同批改检查器里那个集合）。

## 第六步 · 交付（**产物契约：四件，逐件给形态**）

| # | 产物 | **形态（照着交，不许含糊）** |
| :--- | :--- | :--- |
| ① | **TikZ 源码** | 一段可直接粘的 `\begin{tikzpicture}…\end{tikzpicture}`，**含 `\input` 样式层那一行**（注明它属于导言区） |
| ② | **宏包清单** | 一行 `\usepackage{tikz}` ＋ 实际用到的 `\usetikzlibrary{…}` 名单（骨架里用到的库见 `assets/schematic-style.tex` 顶部）。★ **论文骨架里一个 TikZ 宏包都没有**（实测：`mcm-latex-format` 的骨架 `grep -c 'tikz'` ⇒ **0**）⇒ **必须给**，否则粘进去编不过 |
| ③ | **选型回显** | ① 用了**哪份骨架**；② 归**三类里的哪一类**；③ **为什么挑它**（与备选差在哪）。**回落原语时明说"我没用骨架"** 并说明为什么骨架兜不住 |
| ④ | **验收记录** | 编译读数（**`rc`** · **错误行** · **`Overfull \hbox` 计数**）＋ 第五步那句 **"从这张图读到了什么"** |

★ ③ 里的"回落到原语"是允许的（样式层里有节点 / 箭头 / 分组框 / 泳道 / 回环 / 标注的宏），
**但回落后有一条硬要求**：**自己保证整图宽度** —— 见下。

## ★ 调用方纪律（**本支实测出来的几条**）

1. ★★ **宽度：骨架替你写死，原语路线你自己算**。
   骨架把整图宽钉在 `assets/schematic-style.tex` 的 `\mcmscfigwidth` 上；
   **一旦回落到原语**（自己画 tikzpicture），**没有任何东西替你算这个宽度** ——
   `F1` 只会在你编完之后**告诉你红还是绿**，**它不告诉你该设多少**。
   ★ **点明射程**：`F1` 判的是**页盒 ÷ 版心**；**它过不过，与你把内容画得多松 / 多挤毫无关系** ——
   宽度对了但图挤成一团，`F1` 照样 `PASS`。
2. ★ **判据过不过 ≠ 图对了**。`F1–F6` 全绿只说明"图宽 / 配色 / 图注 / 底色 / 色序 / 字体"这六件事没毛病；
   带上 `--schematic` 后再加 `A1`/`A3`/`A4`（节点框重叠 / 文字越页框 / 线宽）三条。
   **仍有一条它不报**：**箭头压住字、箭头戳进框里**（`A2` 已降级）—— 
   ⇒ **第五步"渲图看一眼"是必经，不是礼节。**
3. ★ **不写死任何样式字面量**：颜色 / 线宽 / 圆角 / 间距 / 字号一律走 `assets/schematic-style.tex`。
   在骨架里写死一个颜色 ⇒ **那张图与其余图脱钩**，而**判据不会报**（`F5` 只在色不在允许集合里时才红）。
4. ★ **别在节点文字里用数学模式**：实测会引入数学字体 ⇒ **`F6` 判红**（机械证据见
   `tests/skills/schematic/fixtures/negative-control-math.tex` 与其 `.check.txt`）。
   下标用 `\textsubscript`。**这条挂在判据上，不是本支的偏好**（见 `references/schematic-style.md` §3.2）。
5. ★ **临时目录落仓内 `build/`（已 gitignore）或 D 盘**，**不落 C 盘 / `%TEMP%`**（用户全局定）。
