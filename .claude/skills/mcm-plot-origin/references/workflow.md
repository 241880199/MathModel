## 建图页、套样式、钉宽度

```python
import originpro as op
from mcmplot_origin import apply_style, figsize_for, save

page = op.new_graph("MyFig")             # ★ 图页（GPage）——下面几个入口都吃它
layer = next(iter(page))                 # 图页的第一个图层（本支通常只有一层）
layer.add_plot(ws, "B")                  # ws = 你的数据表（建表细节用 originpro 常规写法）
layer.rescale()

apply_style(page)                        # 色序（不动底色；值运行时从样式表读）

w = figsize_for(tw_in)                   # tw_in = 正文栏宽分母(in)，由调用方给
page.set_float("width", round(w * page.get_float("resx")))   # 把图页物理宽钉成 w
```

- `tw_in`：**正文栏宽分母**，单位英寸。它是**该用户论文的属性**，必须由调用方传入；
  本 skill 与出货检查器**都不预设**它的默认值。换口径会给出不同的图宽比读数。
- **`resx` 是什么**：`page` 对象的**每英寸像素数**（图页自己的像素密度读数，不是导出用的
  `dpi`）。图页的物理宽 `width` 以**像素**计，所以要把英寸的 `w` **乘上 `resx`** 再取整、
  写回 `page.width` —— 这样 `save()` 再从 `width / resx` 还原出的就是英寸的 `w`（两者互逆）。
  别把它与 `--dpi` / `save(dpi=…)` 混为一谈：`resx` 是**图页自身**的密度，`dpi` 是
  **导出那一刻**的光栅化密度。
- **为什么要把图页物理宽钉成 `figsize_for(...)`**：`save()` 导出时**按图页的物理宽**钉死宽度。
  不钉，导出宽就落到 Origin"上次用的导出设置"上（那是个会跨图残留的旋钮）。
- `apply_style()` 对**底色不做动作**。理由 = **Origin 默认导出即白底**，白底由**产物**证
  （判据的底色那条）—— **不是**"设了也没用"。★ 改底色**分语法**：**Python 属性赋值那条路是哑的**
  （`layer.color = …` / `page.color = …` **不抛错**、却**改不动产物** —— **像素层**成立，PNG 带时间戳块、**别拿逐字节比对当判据**；连读它都 `AttributeError`）；
  **LabTalk 那条路有效** —— `layer.lt_exec("layer.color=…")` 真改产物，实测整层底色
  `(255,255,255)` → `(255,128,0)`（同一条路里 `page.lt_exec("page.color=…")` 则**不改**产物）。
  ⇒ **不**把"Python 路无效"推广成"改底色一律无效"。**色序**是逐 plot 设 `series.color`。

## 出图

```python
png_r = save(page, out_png, dpi)         # PNG：宽按 dpi 换算成像素
pdf_r = save(page, out_pdf)              # PDF：宽按英寸（页盒由 Origin 量化）
print(png_r["actual_width_in"], pdf_r["actual_width_in"])   # ★ 实测的"实际导出宽"
```

- **两种载体都出**：PNG 与 PDF（两条载体上检查器的读数**不保证相同**）。
- **`dpi` 只对 PNG 有意义**：保存时用哪个，送进检查器时就传哪个 —— **两处必须逐字一致**（见下节）。
  PDF 走页盒、**不需要** `dpi`。
- **`save()` 的返回里带"实际导出宽"**：它是**从产物实测**回来的（PNG 读文件头、PDF 读页盒），
  不是 Origin 的返回值 —— **Origin 的返回值不算数**（"设上了"只能由产物证明），用它对一下
  宽度是不是真的钉上了。

## 机械层验（与判据的契约）

图出好后，**原样**调出货检查器（本 skill **不改它**，也不重实现它）：

```
python tests/skills/figure-choose/check-figure-style.py \
    --fig <产物路径> --caption <图注文本，或 @<文件>> --textwidth-in <float> --dpi <int>
```

三条契约：

- **`--textwidth-in` 与 `figsize_for(textwidth_in)` 逐字同名同义**：就是那个分母。
  检查器**不预设**它的默认值，必须由调用方给出；给的口径要与出图时用的**同一个**。
  口径不写明，读数就不可比。
- **`--dpi` 必须与 `save(page, path, dpi=...)` 里的 `dpi` 一致**：PNG **必给** `--dpi`
  （不给则检查器报错退出）；**PDF 不给 `--dpi`**（走页盒）。两处不一致，检查器量到的图宽比
  就不是你交的那张图。
- **`--fig` 与 `--caption` 都是必填**：图注可以给文本，也可以给 `@<文件>` 形式。

判词怎么读（末行恒为 `RESULT:` 那一条）：全绿 ⇒ 机械层过；判红 ⇒ 逐条按判词改，改完重跑；
**参数或参照缺失** ⇒ 检查器**不产生任何判词**、直接报错退出 —— 那时要修的是**输入**，不是图。

⚠️ **本支的字体族那一格：落哪种态依产物而定**。产物的 PDF 里**可能含**一个内嵌的**过程字形**字体
（PDF 规范里写作 `Type<n>` 的那类），检查器按**它的族名**判 ⇒ 主题在导出时施加（族名是 Times 系）判 **`PASS`**、
不施加（宋体族）判 **`FAIL`**、一个内嵌字体都没有时落 **`N/A`**。
★ **不要去猜"什么会让它内嵌"** —— **直接量产物**（读 `F6` 判词，或数产物里有没有那个过程字形件）就知道落了哪一态。
（这条触发条件本线**改过几版、每版都被下一轮推翻或复现不出**；控制者最近那次复现尝试**没成功**，
但那个探针**根本没把文字渲染上去** ⇒ **不构成反证**。**写死一个触发条件 = 又给下一轮留靶子。**）
⇒ **族名有机械判据；字形的观感**（像不像 Times 系）**没有**，仍只靠下节的眼睛。

## 亲眼看图（**固定一节，不许省**）

机械层判的只是**能机械化的那几层**：图宽比、彩色主色数、底色、显式色序、图注形态、**字体族名**。
它**判不了**：这张图**有没有把要说的事说清**；刻度与图例**读起来对不对**；图注与图**说的是不是
同一件事**；中文字与符号**有没有缺字形**；以及**字形"像不像 Times"这个观感**。**尤其**：本支的
**字体族**有**族名**判据（`F6`，见上），但**字形观感没有** ⇒ 眼睛是**观感那一层**的证据。

⇒ 所以**出图之后，agent 必须自己把产物看一遍**，并写下**从这张图读到了什么**。
这一步不许省、也不许只贴判词来代替。

**这一节的操作内容（不是口号）**：

- **谁看**：**出图的 agent 自己先看**（不是"交给用户看"就算数）；agent 看完，再把路径交给
  控制者与用户复核。
- **看什么**（本支这几点必看 —— 有判据兜住的、也有判据射程之外的）：
  ① **底色是不是白** —— Origin 默认是白，但这是"该验的"而不是"设过的"；
  ② **色序是不是 `H14` 的前几色** —— 逐 plot 设的色要落在规范那条序列上，眼睛核一遍与判据的
     显式色序那条**互证**；
  ③ **字体看起来像不像 Times 系** —— 机械层只判到**族名**（见上），**字形的观感没有机械判据**
     ⇒ 眼睛是这一层唯一的证据：主题在导出那一刻施加，写对了应是衬线 Times 系；若出现宋体感
     （方块字 / 黑体感），多半是主题**没在导出时施加**（那正是侦察里"半张图两种字体"的坑）。
- **路径怎么给**：产物写到仓内一个**固定产物目录**（`build/` 下一个本模块的子目录；该目录被 git
  忽略，不进提交），把**仓内相对路径**连同"从这张图读到了什么"的一句话一起交给控制者与用户。

**为什么这一步不可省**：机械判据判不了判断层；字体那一格的**字形观感**连机械判据都没有
（`F6` 只判**族名**，且落哪一态**依产物而定**，见上）。
产物是 PNG / PDF，agent 能直接打开来看 ⇒ "亲眼看图"不是附加礼节，而是判据射程之外那一层的
直接兑现。

## ★ 调用方纪律（**本支实现层实测出来的三条**）

1. **图例要摆到数据之外**。Origin 默认把图例放进绘图区 ⇒ **会压住数据**（实测：堆叠柱 / 堆叠条的顶端被盖住）。
   摆到框外（本项目放在上方），**并逐张看图确认不遮挡**。
2. **次序约束（错了会静默出坏图）**：`page.set_float("width", …)` **必须排在摆图例之前**，
   否则图层随页面宽度移位、图例落回框线上。**实测：次序颠倒时 `check-figure-style.py` 仍然判 `PASS`** ——
   这类顺序约束**没有判据兜底** ⇒ 改脚本后**必须重看图**。
3. **条形 / 柱形构造里的两条实测纪律：边色 与 `-k 0`**：
   - **边色**：**默认模板 + `layer.group()`** 这条组合下，边是**饱和红**（实测 RGB `(241,64,64)`），
     且**细到判据的覆盖率阈值之下**；**另一条路线**下，边是**浅色晕**，会**真的撞** `F2` / `F5`。
     ⇒ **本支采用内建 `column` 模板 + `group` 的统一构造路线**（三张产物一致、边为黑）。
   - **`-k 0`**：**在已选的 `column` / `bar` 模板路线上也是必需的** —— **不是**只有"另一条路线"才用它
     （旧稿把它说成后者，已订正）；且**必须排在 `apply_style` 之前**。
     **实测**（同脚本两侧对比）：**漏设这行** ⇒ G3 的 bar 场景 `F2` 的彩色主色数由 3 涨到 6、`F5`
     多出三个越界色（⇒ 会被判红）；**次序排到 `apply_style` 之后** ⇒ 填充**变黑**（首次在 G2 的
     单系列 bar 上看到）。逐条实测与次序标注见 `green/out-G1/scenario.py:116-126` 与
     `green/out-G3/scenario.py:104-112` 两处注释（两处都标它 load-bearing）。
     ⚠️ **`-k` 这个 LabTalk 选项的语义仍未查明**（随附帮助与网络侧都查不到；实测取哪一档效果相同）
     ⇒ **不声称它是"正确用法"**，登记为**版本脆弱点**（跨版本行为本支未验）。

★ **这三条的性质（覆盖面不一，别一概而论）**：第 1、2 条出问题时，`check-figure-style.py` **照样判
`RESULT: PASS`**（判据够不着）；第 3 条分两半 —— **边色**那半同样够不着（细到覆盖率阈值之下），
**`-k 0` 漏设**那半会撞 `F2` / `F5`、判红（**有机械兜底**）；**次序排在 `apply_style` 之后 ⇒ 填充变黑**
（实测），但**该态下检查器判不判红，本支未实测**（不声称它静默）。
⇒ **机械层过了不等于图对了** —— 所以"亲眼看图"那一节是**必经**，不是礼节。

## `op.exit()` 纪律（**调用方收尾**）

`originpro` 的 `atexit` 在**没走到 `op.exit()`** 时只做 `Detach(releaseonly=True)` ⇒
**Origin 进程会残留**。故：

- **场景脚本必须收尾 `op.exit()`** —— 整个建图到出图的过程包在 `try/finally` 里，`finally` 调
  `op.exit()`。这是**调用方纪律**。
- **`save()` 内部也包 `try/finally`**：**失败路径当场 `op.exit()`**（导出中途出错时别把进程留给
  atexit 的 Detach）；**成功路径不退** —— 因为会话内通常还要出**第二个载体**，而实测
  `op.exit()` 之后图页对象即失效。⇒ 成功路径的收尾仍归调用方那条 `finally`。
- **每次跑完核一次残留**：`tasklist //FI "IMAGENAME eq Origin64.exe"` 的读数必须**为空**。
