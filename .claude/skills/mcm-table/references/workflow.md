# mcm-table · 排版流程

本文件是 `SKILL.md` 的流程正文。**本文件与 `SKILL.md` 一样，不复述任何规范数值**；
规范的表型 / 表宽 / 表题 / 惯例层 / 产物契约一律回 `references/table-style.md` 去说。
文中出现的阿拉伯数字**逐处都不是规范值** —— 它们只是：规则编号（`T<n>` / `D<n>` 这类指针型 ID）、
判据编号（8 条机械判据的编号）、仓内文件行号（`<file>:<line>`）、命令里的计数读数、
本机 `pdflatex` 的版本串、临时目录名、`siunitx` 的列格式串，以及 `\typeout` 行里 `\textwidth` 的
**实测 pt 值**；**这一列表不声称穷尽**。

★ 前半句「不复述规范数值」在本文件上**靠人读与复核守**。**实测**：把规范数值写进本文件，
`check-house-style.py` 与 `check-spec-pointers.py` **照样 PASS**（前者默认只读 `mcm-figure-choose/`
那几件，后者的 `K3` 只扫 `*/SKILL.md`）。
⚠️ **不许把它推广成"本文件不在任何检查器射程内"** —— 本仓另有检查器按 `rglob("*")` 读
`.claude/skills/` 下的**全部**文件（先例：`tests/skills/check-writing-discipline.py`）。
**哪个检查器读本文件、判什么，一律以它自己的扫描面为准，不要凭这一段做推断。**

## 前置条件（**环境事实**，不是规范）

- **`pdflatex` 要在 PATH 上**（本机 TeX Live 2026）。**本 skill 不自动安装**，也不代管宏包。
- **路径含空格 / 非 ASCII 时不把路径直接塞给 `pdflatex`** ⇒ 先复制进一个系统临时目录再编。
- **网页端未验 · 跨机未验 · 干净检出复跑不相容**（没有本机的 TeX 发行版就跑不出编译读数）。

流程：**给数 → 定列与精度 → 生成 → 编译 → 渲图看一眼 → 交付**。
最后一步与前几步一样是**固定环节**，不许省。

## 给数

两个入口（设计 §0.2 的方案 1）：

- ① 直接把数**贴进来**（Markdown 表 / TSV / CSV 片段都接受）；
- ② 或给一个**路径**（CSV / TSV）；
- ＋（可选）一条**覆盖指令**（自然语言）；＋（可选）**论文骨架 `.tex` 的路径**。

输入契约写成"**接受任意一张整洁表**"，**不写死某一种文件格式**（将来立"数据单源"只需加一个读取器，
不动生成逻辑）。

## 定列与精度

读 `references/table-style.md`，按这次的表与数据关系找到相关的那几条。默认照规范走；
用户点名要改哪条，就用自然语言覆盖那一条（**默认 ⊆ 可覆盖**）。规范值**只在那份文件里**，本文件不复述。

## 生成

产出一段可粘的 `\begin{table}…\end{table}`，并**同批**给出 `SKILL.md`「输出契约」那几样
（宏包清单 / 来源回显 / 验收记录）。`siunitx` 的 `S` 列与缺失值的耦合（`--` 要写成 `{--}`）
由**生成器自己处理**，不留给用户。

★ **用户点名"表题放下面"时**（`T3` 的合法覆盖）：必须在 `\begin{table}` **之前**加**一行**

```
% mcm-table-caption: below
```

判据 `C3` **只认这一行**；表题在下而**没有**它 ⇒ **判红**（格式钉死在
`references/table-style.md` §3.1，那里有**可粘的例子**）。**不许**用别的措辞代替。

## 编译（**固定环节**）

把生成的表放进自带模板 `assets/table-template.tex` 编一遍（**每次都自证"表本身编得过"**）：

```
pdflatex -interaction=nonstopmode <复制到临时目录里的 .tex>
```

- **rc=0** 是硬门（对应图表那边"起载体出图"）。
- log 里会有 `MCMLAYOUT textwidth=<实测 pt>` —— **版心宽取这个实测值**，不取推出来的读数
  （它是 LaTeX 自己算的确定数，见 `references/table-style.md` §3.3）。
- ★ **可选加分项**：给一份**论文骨架 `.tex` 的路径** ⇒ 在**那份 preamble** 下再编一遍。
  **这一支只报**：`rc` · log 错误行数 · `Overfull \hbox` 计数 · **未定义控制序列**名单
  （见 `check-table-style.py` 的 `--skeleton` 信息行 `SKEL:`）。
  ★ **它不做**：**不**拿表宽与骨架版心做比较（**"会不会爆版心"未实现**）、**不**逐个宏包点名
  （`siunitx` 等**不在**未定义控制序列的射程里）⇒ **未实现部分已登记**（`docs/mcm-suite-todo.md` §H.2）。
  **不给骨架路径时，这一步不验，且如实说不验。**（★ **别**读成"骨架版心已被读取"——判据的分母
  **恒**是**自带模板**编译时的 `\textwidth`，见 `references/table-style.md` §3.3。）

## 渲图看一眼（**固定一节，不许省**）

机械层判的只是**能机械化的那几层**（编得过 / 三线结构 / 表题位置 / 表宽 / 列数 / 精度 / 缺失值 /
来源回显）。它**判不了**：这张表**有没有把要说的事说清**；表注与表**说的是不是同一件事**；
列**有没有挤爆版心**；`\pm` **有没有掉出来**；小数位**看着**有没有对齐。

⇒ 所以**生成之后，agent 必须自己把产物渲成图看一遍**，并写下**从这张表读到了什么**。
这一步不许省、也不许只贴判词来代替。

**这一节的操作内容（不是口号）**：

- **谁看**：**生成表的 agent 自己先看**（不是"交给用户看"就算数）；agent 看完，再把路径交给
  控制者与用户复核。
- **看什么**（本支这几点必看）：① 列宽**有没有挤爆版心**（含缩过头、字小到读不下去）；
  ② **表题与表离线多远**；③ 数值列的**小数点对齐**看得出来吗；④ 表注 / 表内公式有没有溢出或掉字。
- **路径怎么给**：产物写到仓内一个**被 git 忽略的固定目录**（`build/` 下本模块的子目录；
  该目录不进提交），把**仓内相对路径**连同"从这张表读到了什么"的一句话一起交给控制者与用户。

**为什么这一步不可省**：机械判据判不了判断层；"表讲没讲清 / 缩没缩过头"连机械判据都没有
⇒ 产物是文本与图，agent 能直接打开来看 ⇒ "渲图看一眼"不是附加礼节，而是判据射程之外那一层的直接兑现。

## 交付

按 `SKILL.md`「输出契约」交齐几样；机械层读数逐条贴判词；"看表"那一句不许省。

## ★ 调用方纪律（**本支实现层实测出来的三条**）

1. **来源回显要覆盖到每一格，且放在 `\begin{table}` 之前**。格式钉死在
   `references/table-style.md` §3.2。**漏一格 = 判据 8 判红**（这条**有机械兜底**）。
2. **`S` 列里的非数值要写成 `{--}`**。不写成花括号包起来的样子会**编不过**（rc≠0）——
   这条**有机械兜底**（编译那一条会红）。
3. **"自然宽度"与"版心宽"的关系不是判据能替你判断的**：缩**字号**（如外层 `{\small …}`）能把它压进版心，
   但**压得字太小就没人读得下去** —— 判据只看"超没超版心"，**看不出"缩过头"**。
   ⇒ 必须**渲图看一眼**。★ **`\resizebox` 本支用不了**：自带模板**没有载 `graphicx`** ⇒ 带它的表在判据
   `C1` 上**编不过**（要支持需给模板加 `graphicx`，**未实现**，登记 `docs/mcm-suite-todo.md` §H.2）。

★ **这三条的性质（覆盖面不一，别一概而论）**：第 1、2 条**有机械兜底**（漏了会判红）；
**第 3 条没有** —— 机械判据只看"宽度超没超上限"，**"缩过头 / 列挤得看不清 / 表题离表太远"
它一条都判不了**（先例：origin 那支的图例压数据，**判据一条都不报**）。
⇒ **机械层过了不等于表对了** —— 所以"渲图看一眼"那一节是**必经**，不是礼节。
