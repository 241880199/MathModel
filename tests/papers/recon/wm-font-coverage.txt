判读
====
1. 图表侧（find_watermark_xrefs / strip_in_memory）在全部 201 份上判别完美：
   有水印的 120 份全部命中 1 个 xref，无水印的 81 份全部命中 0 个，零误报。
   两个方向都验到了；无误报这一条尤其关键——误报会让 strip_in_memory
   把正常内容流置空。故 Task 2 的图表侧路径对全语料成立。

2. 正文侧（is_watermark_span / content_text）只在 2025 那 43 份上成立。
   2023 的 42 份与 2024 的 35 份，水印字在文本层里确实存在（「校苑数模」
   「英伽教育」），但 span 字体不是 MicrosoftYaHei：
     2023/2024 校苑数模 -> KaiTi  74.4pt / 76.5pt（共 72 份）
     2023      英伽教育 -> SimHei 83.4pt（5 份）
   于是 is_watermark_span 对这 77 份一律返回 False，content_text 会把
   这些水印字原样带进正文。命中 43/120，漏 77/120。

3. 与文档的出入：设计文档「素材实况」写的是「水印 span 特征唯一：
   MicrosoftYaHei 72pt（正文是 TimesNewRoman 12pt）……按字体+字号过滤后
   0 命中」。这句话对 2025 那批成立，对 2023/2024 不成立——当时取的
   验证样本是 2025 的 2500836.pdf，一个样本的特征被写成了全语料结论。

影响（Task 3 起）
================
Task 3 的正文抽取会跑全量 201 份。若沿用当前的 is_watermark_span，
77 份（2023/2024）的正文会混入「校苑数模」「英伽教育」水印字，且不报错
——是静默污染。因此：
  * 本文件**不推翻** Task 2 的结论：Task 2 的范围就是 2025 样本那一篇，
    其 PASS 依然有效；
  * 但 A2/A3（正文侧）的判据不能假设「过滤后 0 命中」在全语料成立，
    需要按合集/厂商分别取特征，或另找不依赖字体的判据。

本文件是**侦察记录**，不是 Task 2 的通过/失败判据：它记录实测事实，
不参与 verify_wm.py 的 ok 判定。
