# `tests/papers/reports/` 是什么

M6 论文流水线（试点 = 2025 那 43 份）的**判据证据**与**送检样件**。
本目录下的文本证据**入库**；`corpus/papers/` 下的派生产物可重生成、不入库。

## ⚠️ 先读这一节：本目录里的图**不全是**"没水印"的

本目录的用途之一是证明水印被摘干净了，**但有两张图按设计就是要带水印**。
看到带水印的图，先对照这张表，别当成流水线漏水印：

| 文件 | 是什么 | 该不该有水印 |
| :--- | :--- | :--- |
| `a4-2500836-with-wm.png` | **Task 2 的「处理前」对照**（`e3f6f45`） | **有** —— 按设计**就要**有。它与下一张同页、同 `dpi=110`、同一渲染参数，**只差 `strip_in_memory` 这一步**，成对呈现才证明置空真的起作用 |
| `a4-2500836-no-wm.png` | Task 2 的「处理后」 | 无 |
| `c4-*.png`（6 张） | **Task 4 的送检样件**：全库偏红像素占比最高的一批（23.04%–44.44%），即机器筛出的最可疑者 | 无 —— **已经人工目视确认**，见下 |
| `c4-2500836-*.png` | 注意：文件名里也有 `2500836`，但它是 **Task 4 的样件**，与上面那对 a4 图无关 | 无 |

名字里带 `with-wm` 的只有那一张。它是**故意的反例**，不是缺陷。

## 三类文件，别混用

1. **机器生成的报告**（`*-report.txt`、`*-histogram.txt`、`origin-sha256-*.txt` 等）
   由 `tests/papers/verify_*.py` 每次运行重写。**重跑即重写**——所以任何结论都不能只写在这里。
2. **人工文件**（`*-visual-confirm.txt`）
   **由人工撰写，脚本只读**。脚本把它逐字抄进报告，**缺了则判该闸门 FAIL**。
   这样安排的理由：脚本每次运行都会重写报告，结论若只写在报告里，任何一次重跑都会把它抹掉。
   **AI 不得代写目视结论**（它看不了图）；现有的两份均由用户目视后落盘。
3. **图（`*.png`）**
   它们是**第三方论文页面的渲染图**。本地入库作证据可以，**推公开远端不行**——
   根级同步规则按目录排除 `tests/papers/reports/*.png` 与 `tests/papers/recon/*.png`。

## 人工目视的效力边界（不得读大）

- `c4-visual-confirm.txt`（Task 4）只覆盖 **6 张送检样件**，**不是**全部 908 张产出图的普查。
- 它**不**声称「图表抽取的内容框对了」——那需要一个能看图的独立参照，本轮没有。
- 未决：C4 来源层结论只对 **42/43** 份成立（`2507789` 一份为「未验证」，见台账 §D）。
