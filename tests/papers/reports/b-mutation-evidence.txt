## M13 的还原步骤（补记：2026-09-24）

> 补记的原因：变异 M13（把 `report_path()` 的 `limit == 0` 分支改坏）在
> `.superpowers/sdd/task-3-round2-report.md` 里有改法与逐字输出，**却没有写"跑完怎么还原"**。
> 这条缺得要紧——M13 与其它变异不同：**被改坏的全量跑会把一份 FAIL 报告写进入库的放行证据**
> `tests/papers/reports/b-report.txt`（守卫把落点改写回它，"全量跑必须拥有这份证据"），
> 于是**还原分两步：代码一步、入库证据一步，缺一步都留下假事实**。

### 1) 改坏哪个锚点（在 `report_path()` 尾部，全文件唯一）

```python
    if limit > 0:
        return LIMITED_DIR / f"b-report-limited-{limit}.txt"
    return REPORT                                    # ← 锚点：把这一行改掉
```

改法（照抄 `task-3-round2-report.md` §2）：把最后那行换成
`    return LIMITED_DIR / f"b-report-limited-{limit}.txt"  # MUTATION M13`
写入前必须断言锚点在文件里只出现一次（`src.count(anchor) == 1`），否则改坏的地方不止一处。

### 2) 改坏之前先存一份**逐字节副本**（否则还原只能靠记忆）

```sh
python - <<'PY'
import hashlib, pathlib, shutil
p = pathlib.Path("tests/papers/verify_b.py")
print("pre sha256 =", hashlib.sha256(p.read_bytes()).hexdigest())
shutil.copy2(p, "build/verify_b.py.pre-M13")   # build/ 已被 git 忽略，不入库
PY
```

把打印出来的 `pre sha256` **连同一份副本**留住（本节刻意不写死某个摘要值：它会随
每次提交变化，写死在这里就成了过期事实；`task-3-round2-report.md` §2 记了变异当时实测的
`616daa1d…`（改前）/ `a454de9e…`（改后）两串）。**不要**用
`git checkout -- tests/papers/verify_b.py` 还原：工作树里有未提交改动时，那会把改动一起丢掉。

### 3) 跑（全量，无 `--limit`）→ 看红

```sh
python tests/papers/verify_b.py ; echo "EXIT=$?"
```

预期（§2 已逐字记录）：`EXIT=1`、`RESULT: FAIL`（**无 `LIMITED` 后缀**——它是一次真全量）、
43 份判据行全绿（`全部判据通过: True`）、报告第 2 行是落点守卫 FAIL、`reports-limited/` 下
**没有**出现 `b-report-limited-0.txt`；而 `b-report.txt` 被这一次跑**改写成了 FAIL 内容**
（这就是必须还原它的原因）。

### 4) 逐字节还原（两步都要做）

1. **代码**：把 §2 的副本写回去
   `shutil.copy2("build/verify_b.py.pre-M13", "tests/papers/verify_b.py")`
2. **入库证据**：`git checkout -- tests/papers/reports/b-report.txt`
   （`.gitattributes` 的 `tests/papers/reports/**  -text` 保证 blob 与工作树是同一串字节）

### 5) 确认还原成功（四条都要看，任一条不成立就是没还原干净）
