与上一级 `green/` 对照：GREEN 侧 = **用本 skill**（`SKILL.md` 契约 + `references/`）出的同一件事。

- **这件事（权威副本）**：`brief.md` —— **唯一一份**，RED 与 GREEN 逐字共用。
  ★ **它本身不是泄题件** —— 写手要看的就是它。
- **判据**：`../check-playbook.py`，**两侧同一版**（工作树版；与**基线 `e9d8d47`** 的差 = 一处 **arm C 结束标记**，
  **已实证两侧读数一字未变**，见 `../PLAYBOOK-evidence.md` §0 与 §8）。
- **★ RED 是本任务的「自变量」**：`out-R{n}/schedule.md` 是**写手的字节**，本轮未改
  （blob 见 `../PLAYBOOK-evidence.md` §0）。

## 3. 三位写手是谁（派发口径见 `writer-self-reports.md` §0）

- 三个**新起的干净上下文** `general-purpose` agent，**未用 `fork`**。
- 首条 user 消息 = 一条**逐字相同**的提示词（只有 `out-R{n}` 不同）：只给 **brief 路径 + 输出目录**，
  外加一件**环境事实**（"不需要联网"）；末尾一句**隔离句**（"Work only from that brief file"）。
- **未给**：本 skill / `corpus/official/**` / 判据 / 本任务书 / 侦察读数。
- **强度边界（照实）**：写手"只读了那一份 brief"**只有自报、没有沙箱可证**
  （自报件是**转录级**、非机器抽取）。
- **★ 环境旁路的如实披露**：写手是本机 Claude Code 的 agent，会话级共享上下文里另有两处可见面 ——
  ① skill 列表里 `mcm-playbook` 那一行的**类别名**（"赛程、时间线、现在该干什么……"）；
  ② 自动注入的项目记忆 `MEMORY.md`。
  ★ **本次用干净上下文探针查过：这两处没有泄漏那个时长**（旁路泄的是"有赛程这件事"与"2027 这个年份"）。
  全文与**探针自身的边界**见 `writer-self-reports.md` §4。

## 4. ★ RED 的诚实边界（硬要求 7 / 设计 §4.3）

中性 brief **已经限定**"要产出一份赛程表"（三个必答项：关键节点 / 总时长 / 分阶段表）
⇒ 这轮 RED **测不到"连表都做不出来"那一类失败**（写不出表、表里空、没有阶段划分）。
**不声称覆盖全部失败模式。**

★ **不许把 RED 的红读成"赛程做得差"**：三份 RED **都读得懂、都自洽、内容还都正确**
（总长都给了 `99 小时`）。判据红的是**"没按本 skill 的契约产出"**（缺机器可核的表结构、缺 `§id` 出处、
缺「构造」标注、一个 `mcm-*` skill 都没点名 —— 最后这条**恰好**印证本 skill 的真内容 = **依赖图**）。
详见 `../PLAYBOOK-evidence.md` §5、§6。
