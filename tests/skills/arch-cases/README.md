# `arch-cases/` — `mcm-section-writer` 的 RED 阶段材料（"给要点清单，写论文某一节"）

**RED 阶段** = "TDD for skills" 的第一步：**先看没有 skill 时 agent 怎么失败**。
本目录冻结的是那次实验的**输入**、**对照**、**产物**与**判断报告**，全部逐字节复制，未重新排版、未加头注。

**测什么**：把 **题面 + 一份"我们的模型要点"清单**（一条条要点，像队员递给写手的那样，**不是散文**）交给 agent，
让它写出**论文的某一节**；再把它交出的那一节，与**同一篇获奖论文真实的那一节**逐段对照。
被测目标是**尚未建**的 `mcm-section-writer`（"措辞"那一格；`.claude/skills/` 下现无此目录）——
本 RED 的结论用来决定**这个 skill 该写什么**，以及"教人写得好"这一族对当前 agent 是否冗余。

**与 `../abs-cases/` 的关系**

- `abs-cases/` 是 **`mcm-abstract`** 的 RED，测**摘要页**（一页 Summary Sheet）；本目录是**另一格**的 RED，测**写论文的某一节**（正文）。
- **两者共用同一份案例**：2025 MCM **A 题**（获奖论文队号 `2501909`）——题面都是 `../abs-cases/case-A-problem.txt`，
  正文都取自 `../abs-cases/case-A-body.md`。本目录的 `true-S1.md` / `true-S2.md` 就是**从那份正文里切出来的两个区间**（见 §四"来源"）。
- **两处 RED 都叫"写作 RED"，但不是同一次实验**：本目录只装"写某一节"这一次（见 §五"未入库的相邻材料"）。

## 一、文件清单与用途

> ⚠️ **本目录有两份"泄题 / 口径"文件，绝不可给写手看**：**`README-RED.md`**、**`judge.md`**。
> 前者列了节边界与全部"不得判成写手之错"的清单（等于把标准答案的结构交出去）；
> 后者是**判断报告**，逐条列出产物哪里失败、标出真实原文的对应位置。给写手看任何一份，这次对照当场作废。

| 文件 | 类别 | 给谁 | 是什么 |
|---|---|---|---|
| `brief-S1.md` | **输入** | **给写手** | S1（`3.1 Wear Volume Model`，模型建立节）的要点清单，**12 条**中文要点，无成句散文 |
| `brief-S2.md` | **输入** | **给写手** | S2（`Strength and Weakness` + `Conclusion`）的要点清单，**8 条** |
| `true-S1.md` | **对照** | **不给写手** | S1 在论文里的**逐字原文**，供事后逐段对照 |
| `true-S2.md` | **对照** | **不给写手** | S2 在论文里的**逐字原文**，供事后逐段对照 |
| `out-S1.md` | **产物** | — | 写手交出的 **S1 模型建立节**（`# 3. Stair Wear Model` → `## 3.1 Wear Volume Model`） |
| `out-S2.md` | **产物** | — | 写手交出的 **S2 优缺点 + 结论节** |
| `out-S2-p.md` | **产物** | — | 写手交出的 **S2 压力臂**（队长要求"缺点别写太狠"）；*p = pressure* |
| `README-RED.md` | **口径（泄题）** | **不给写手** | 对照口径：节边界、★"不得判成写手之错"清单、两条已裁的事、★结构性损失登记 |
| `judge.md` | **判断（泄题）** | **不给写手** | **判断报告**（340 行）：§1 量出来的标记表 · §2 三层判定 · §3 内容覆盖 · §4 WHO 表专项复核 · §5 结论 / 可写成判据的三条 / 证明不了什么 · §6 第三层文风实测读数 |

**给写手的正式输入 = `brief-S1.md`（或 `brief-S2.md`）** **+** 题面 `../abs-cases/case-A-problem.txt`，**仅此两项**。
（`true-*.md`、`README-RED.md`、`judge.md` 均**不在**写给写手的材料里。）

**产物里另有一段自述**：三份 `out-*.md` 的末尾各有一段 `## 我的做法说明`（起于 `out-S1.md:113` / `out-S2.md:29` / `out-S2-p.md:27`）——
那是采样 agent 的自述（写了什么、没写什么、为什么），**不属于论文节本身**，作论文稿时应整段删掉。
`judge.md` 的纪律明写：说明段**不计入**"论文措辞"的统计，凡引用一律单独标「说明段」。

**这些文件没有生成器。** 与 `abs-cases/` 不同（那边 7 份输入可由 `../make-abs-cases.py` 逐字节复现），
本目录的 `brief-*.md` 是**手写的任务材料**、`out-*.md` 是**agent 的采样输出（不可再生）**、
`judge.md` / `README-RED.md` 是**当时写下的判断与口径** ⇒ **一律按原样冻结，没有脚本可重跑**。

## 二、★ 本次 RED 最重要的一条发现

> **写手在缺数据时把数字反推出来，并挂到 WHO 名下——且正文里没有任何"这是假设值"的标注。**

- **任务书挖的坑**：`brief-S1.md` 第 9 条**要求交出"组别 / 平均体重 / 占比"参考表**、并"由表中数据算出总体平均 `W = 62.8 kg`"，**却不提供任何数据、也不提供来源**。
- **写手交付的**：`out-S1.md:65` 声称 `we adopt the WHO global body-weight references as the default calibration`，`:67` 表题写作 `Reference mean body weights…`，`:69–77` 是六组体重/占比表，`:81` 回代得 `62.8 kg`。**正文里没有一处把它标成假设值 / 待补值。**
- **判断报告的独立复核**：见 **`judge.md` §4「★ 专项复核：`out-S1.md` 的六组体重表」**（`:169–199`）——它**只读正文、不读说明段**，
  比对出产物表与**该论文自己的同表**数字不同，而**两张表算出的加权和都恰为 `62.8`**，故认定数字是**为命中 62.8 反推出来的**。
  同一条在 `judge.md` §5.1 被定为**唯一一条严重度"高"的失败**（`judge.md:216`：*"严重度高的失败**只有一条**（WHO 表）"*）。

> **数字口径的一点出入（本目录落库时复算，如实登记）**：`judge.md:177` 记作"**十二格里九格不同**"；
> 落库时按 `true-S1.md:108–125` 与 `out-S1.md:71–76` 逐格复算，**得 8 格不同 / 4 格相同**
> （相同的 4 格：体重 `af` 65、`om` 70；占比 `mm` 10、`fm` 10）。
> "**两表都恰好等于 62.8**"这一条复算成立。差异细节见 `../arch-red-evidence.md` §3。

## 三、★ 本次登记的两条 brief 侧结构性缺陷（我的设计问题，与写手的错**分开登记**）

这两条是**任务书自身的问题**，**不与写手的失误相互抵扣**——`judge.md:199` 的口径：
*"结构性缺陷 + 写手失误，两条分别登记，不相互抵扣"*。

1. **`brief-S1.md:23` 要表、要数、要命中一个具体值，却什么都不给。**
   它要求给出参考表（组别 / 平均体重 kg / 占比 %）并由表中数据算出 `W = 62.8 kg`，但**不给数据、不给来源**。
   ⇒ 当"必须给出表 + 必须命中一个具体数字 + 不给数据"三条同时成立时，**任何照做的写手都只能反推数字**。
   （`judge.md` §4.2 把它列为**应写进 `README-RED.md` 结构性损失清单**的一条，并写明：**坑只逼它"给数"，没逼它"署名 WHO"，也没禁止它标注"这是假设值"**。）

2. **`brief-S2.md` 的"结论报数值"维度在该论文上不成立。**
   该论文**结论节零数字**（`README-RED.md` §4.2 实测；`judge.md` §3.2 复核两份产物正文数字字符数均为 0）。
   ⇒ **官方"结论应明确报告结果"这条内容项，连获奖作品都只是松着执行**；本次**无法观测**写手"会不会在结论里复述关键数值"，
   评分时**不因没报数扣分、也不因报数加分**。
   `brief-S2.md` 第 7 条已显式告知写手"该节不含数值结果，不要自行编造数字"（避免引入无关的幻觉失败）。

**另有一条不算 brief 缺陷、但必须单列的结构性损失**（`README-RED.md` §5、`judge.md` §3.1 第 1 条）：
**S1 的 3.1.2 里"为什么 Archard 理论适用于台阶"的论证，在 12 条要点上限下被压成了半句**
（原文 `true-S1.md` 对应区间有"位移有限，但每步轻微滑动会造成局部磨损"这一整层让步—化解，brief 只保留了事实点）。
⇒ **写手补不出这层论证属结构性损失，不是它的疏忽**，对照时须单独标出，不得让它污染其余 11 条要点的判定。

## 四、来源与第三方文本的处置

- **`true-S1.md` / `true-S2.md` 是获奖论文的逐字节选**（第三方文本）：
  - `true-S1.md` = `../abs-cases/case-A-body.md` **第 147–296 行**（5910 B，落库时复验逐字节相同）；
  - `true-S2.md` = 同文件 **第 929–973 行**（2375 B，同上）。
  两份文件头部都写明了来源与区间，并有一行标记 `===== BEGIN VERBATIM 以下为逐字原文 =====`，**标记行之后**才是逐字原文。
- **同源关系**：`case-A-body.md` 本身派生自 `corpus/papers/md/2025美赛O奖论文/A/2501909.md`（见 `../abs-cases/README.md` §一）。
  故 `true-*.md` 与 `case-*-body.md` **是同一份第三方文本的不同切法**。
- **用户已就"md 是否上公开远端"做过裁决（保留）**：`corpus/papers/md/**`（43 份获奖论文全文的 md 转换）曾随快照上了公开远端，
  用户裁决**保留、不回退**（口径与理由见 `.superpowers/sdd/progress.md:2265–2276`；该文件不在仓库内，仅本机可查）。
