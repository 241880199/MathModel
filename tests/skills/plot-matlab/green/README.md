## 3. 亲眼看图与实测逼出来的事（**本任务不改模块**）

1. **G2 的两处修图是眼睛发现的，不是判据报的**：初版四个类目名平排**互相压住**、
   ylabel 太长在 2.6 in 图高里**被裁掉顶端** ⇒ 类目名旋 20°、ylabel 缩成
   `Pearson r (dimensionless)` 后重出。这两处**在 F1–F6 的射程之外**（检查器量的是
   图宽比 / 彩色主色数 / 底色 / 色序 / 字体族 / 图注形态，**不量刻度标签的排版**）
   ⇒ 它们是**判断层**发现、判断层修的。
   **初版送检的结果只是自报**：出图时另跑过一次初版送检、**观察到 F1–F6 全 PASS**，
   但**未捕获 stdout、未落盘产物** —— 故这里按**自报**口径写，**不是**可复跑的实测。
   **承重的是结构论证，不是那次观测**：检查器的判据**只有** `F1`/`F2`/`F3a`–`F3d`/`F4`/`F5`/`F6` 九条，
   **没有任何一条**管刻度标签的排版 ⇒ 标签互相压住、ylabel 被裁，机械层**本来就抓不到**。
   **一条命令即可推翻本句**（若它命中刻度标签排版类判据，本句即为假；实测零命中）：
   ```
   grep -nE "TickDir|TickLabel|刻度|标签排版|重叠|overlap|clip" tests/skills/figure-choose/check-figure-style.py   # rc=1，零命中
   ```
   佐证（更强的一版）：下面这条直接列举检查器能产出的**全部**判据 ——
   实测**原始输出 12 行**（`F6` 有四个分支，同名多行），**去重后恰为** `F1 F2 F3a F3b F3c F3d F4 F5 F6` **九条**，
   其中没有一条关于刻度标签排版：
   ```
   grep -nE 'res\.append\(\("F' tests/skills/figure-choose/check-figure-style.py
   ```
   **这是生成脚本层的排版问题，不是模块缺口**（模块不替你排版轴标签）。
2. **本机 MATLAB 的 IDE 主题是深色**（写手 R1/R3 各自报告：仅设 `figure`/`axes` 的 `Color`
   在部分路径下不够、产物仍可能带深色轴区；可行修法 = `figure(...,'Theme','light')`
   或 `theme(fig,'light')` 带句柄）。**这与模块 `new_figure()` 的写法一致**——
   模块本就显式上浅色主题，故 GREEN 三张的 F4 全绿。**不是模块缺口**。
3. **模块行为实测（确认、非缺口）**：`M.apply(fig)` **会**给建图后已有的 artists 重着色 ——
   实测一条默认蓝的 `plot` 线与一个 `bar`，`M.apply()` 后都变为 H14 第一色
   （`get(h,'Color')` 前后：`[0.066 0.443 0.745]` → `[0.902 0.624 0]`）。故
   "建图后、导出前调 `M.apply`"这条契约对**颜色**同样成立。
   **不声称穷尽**：以上三条是本次实际碰到 / 实测的，不是模块缺口的完整清单。
