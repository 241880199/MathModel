## §1 ★★ 预测（**写在前**）

**下面这张表在派任何写手之前就写死**（本文件先于写手产物入库，见 `git log` 的本目录首个提交）。
**落地后逐条照实回填**（含**没发生的**）—— 见 `../MODELSELECT-evidence.md`。

| # | 预测的失败模式（设计 §6 原话） | 先写的预期（RED 侧） | 先写的预期（GREEN 侧，多给本 skill） |
| :-- | :-- | :-- | :-- |
| `P1` | **选错类** | 写手**不按任何"类"的框架**组织，直接跳到某个具体方法（如"回归"或"微分方程"），**说得出模型、说不出它属于哪一类**；且大概率把这道**反问题（从磨损反推人流）**当成**正向**建模 | 走 skill 的两跳（先选类、再选方法）⇒ **能点名类**；漂移风险在**类选得对不对**（本题应落在 mechanism / statistics 一线） |
| `P2` | **用不存在的函数** | MATLAB 代码里出现**一个不存在的函数名**（幻觉函数 / 拼错的工具箱函数）⇒ 运行报 `Undefined function` | 用 skill 的**骨架路径**（`assets/matlab/<类>/<方法>.m`）⇒ 函数名来自**已入库、已过 `MS4` 的骨架** ⇒ **预期不发生** |
| `P3` | **骨架跑不通** | 代码**跑不起来**或跑不完（维度不匹配 / 缺工具箱 / 参数未定）；★ **注意与 `P2` 的区别**：`P2` 是"名字不存在"，`P3` 是"名字对但跑不通" | 骨架**已过 `MS4`**（`feval` 零参可跑）⇒ **预期跑得通**；但★ **本题的骨架未必是"直接能算这道题"的**（骨架是通用件），故"能跑"≠"算对这道题" |
| `P4` | **把假设当已知** | 写手**把一批数值/关系当既成事实写进模型**（如"磨损速率与人数成正比、系数 = X"），**不单列假设**、不标"待定" | skill 的六格第 ③ 格 = **参数与假设**（假设必须显式）⇒ **预期有显式假设节** |
| `P5` | **无参数辨识** | 写手**不提**哪些参数是**从题面给不出来的**（无数据可辨识） | skill 的六格第 ③/④ 格要求写清"需要哪些输入、默认假设是什么" ⇒ **预期会点到辨识问题**；★ 但**是否真的点到**是**判断层**，机械判据判不了 |

★ **两条写在这里的口径**（防事后找补）：
- **`P2`/`P3` 的判定靠"真跑 MATLAB"**（不是读代码）；跑得通/跑不通**以 `matlab -batch` 的读数为准**。
- **预测不等于保证**：上表是**先写死的靶子**，落地后**逐条回填实际**，**含"没发生的"**。
