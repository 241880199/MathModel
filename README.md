# MathModel

2027 美赛（MCM/ICM）自用 **skill 套件** 与 **语料流水线**。

## 这个仓库里有什么

| 目录 | 内容 | 状态 |
| :--- | :--- | :--- |
| `.claude/skills/` | 三个 skill：`mcm-ai-disclosure`（AI 使用披露）、`mcm-latex-format`（LaTeX 骨架与格式合规）、`mcm-selfreview`（提交前自查） | 已完成，各经多轮复审 |
| `tools/papers/` · `tests/papers/` | M6 语料流水线：**水印处理**（内存置空水印 XObject 流，不产出清洗版 PDF）+ **正文抽取**（PDF → 可检索 markdown）。配套判据脚本 `verify_io/wm/b.py`，判据证据逐字入库 | 试点（2025 年 43 份 O 奖论文）**已跑通**；图表 / 公式 / 索引三个阶段**未开工** |
| `corpus/algorithms/` | 算法语料索引、**20 个已实测缺陷**的登记，以及 **6 个净室重写版**（`fixed/`） | 主体完成 |
| `docs/` | 设计文档、实施计划、既得教训、待办清单 | 随开发更新 |

## 两条贯穿全项目的硬约束

- **语料产物一律字节级写入**（`write_bytes`），并配 `.gitattributes` 的 `-text`。
  起因：本项目踩过 `core.autocrlf` 把 883 个文件写成 `\r\r\n` 的事故，一度误判为上游代码问题。
- **判据不得"看起来能失败"就算数**：每条新增判据都必须用一次**变异证明它真的会红**
  （改坏被测代码 → 跑一次 → 看它红不红）。本项目已出现六次「判据在什么都没验的情况下报绿」，
  其中两次是在立下"必须变异证明"这条规矩**之后**写下的。
