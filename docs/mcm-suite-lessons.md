## 一、给 skill 作者的硬约束（通用则）

第一期 4 个任务、15 轮任务级审查/复审反复暴露的问题。**每条都有真实代价，写进后续模块的派发指令，不要让新 subagent 重新踩。**

1. **`[官方]` 只用于官方原文确实如此表述的断言。** skill 自订的阈值、默认方向、取舍、操作纪律，一律标 `[社区]`（操作纪律）＋官方指针。
   代价实例：曾写「官方点名 MATLAB」并标 `[官方]`——实际 `corpus/official/` 的 AI 政策文件里 `MATLAB` **0 命中**，政策只写 "mathematics software"，不举产品名。
2. **官方外延 ≠ 判据外延**时（判据收窄或放宽了官方口径），须**并挂** `[社区]`（推算自何处）。
   **这类缺陷的官方原文确实存在**，故"有没有出处"式的自查查不出来——必须专门做**外延比对**。
3. 官方用 **"for example"** 引出的示例文字**非强制**。
   代价实例：`Team # 0000000, Page 6 of 25` 是示例，`of 25` 不是要求。这一个坑踩了两次。
4. **不得引用 `corpus/official/` 之外的包内机制或第三方文档。** 代价实例：曾断言社区宏包 `mcmthesis` 的内建环境名，全目录 grep 只命中索引自己。
5. **输出契约必须包含清单要求它产出的每一个要素**；**清单不得否证契约自身的输出**。
   代价实例：`mcm-ai-disclosure` 首版按自己的检查清单自检，**自己的参考输出就不合格**（清单要求代码补全条目有 Query/Output，而契约允许它只给陈述式）。
6. **环境类陈述一旦写进判据就成了负债——环境一变，必须回头把全库搜一遍，不能只改被问到的那一处。**
   本机**原无** LaTeX 工具链；**2026-09-24 已装 TeX Live 2026**（`D:\Software\texlive\2026`，免管理员、已入用户 PATH）：
   `pdflatex`/`xelatex`/`lualatex`/`latexmk`/`kpsewhich` 齐（`tlmgr` 在 Git Bash 下须写 `tlmgr.bat`）。**仍缺** `pdfinfo`、`pandoc`（页数用 `PyPDF2` 读）。用户**提交仍走网页端编译器**。
   纪律：**可以真编译，故不得再以"本机无法编译"为由跳过验证；凡声称编译结果须附真实命令与输出**。
   **但页数、体积这类与引擎版本相关的量，权威口径仍是用户提交的那一次编译**——本地只作预检、**不得**代填。
   代价实例：装完 TeX 后，`mcm-latex-format`／`mcm-selfreview`／`mcm-ai-disclosure` 三个 skill 判据里的"本机无 TeX"**同时变成假的**；
   更正时又**险些只改那三个 skill、漏掉本通则本身**——而本通则与待办会被写进**以后每一个新模块的派发指令**，
   漏掉它就会把**已失效的环境事实持续传播**给新模块。**故：改环境事实时，`docs/`＋`.claude/` 要一起回扫**（`tests/results/` 属历史运行记录，不改）。
7. **验证证据须归档进受版本控制的 `tests/` 下，逐字原文**，非汇总描述。
   代价实例：`mcm-latex-format` 的 GREEN-1 证据只写进 `.superpowers/`（gitignore），**已永久丢失**。
8. 派 **RED 基线**的 subagent **只收场景正文**（不得带简报、背景、期望答案，不得用 `fork`——fork 继承上下文）。
   隔离用**复制** fixture 到仓库外临时目录；**移动**既有文件会被权限拒绝，**被拒不要绕过，如实报告**。
9. **把第三方文件搬进本仓库时，先排除搬运环节，再去解释"上游代码差"。**
   代价实例：首版算法归档有 883 个文件被写坏成 `\r\r\n`（双 CR）——`git core.autocrlf` 把检出内容写成 CRLF，转码脚本又用 Python **文本模式**写入、把每个 `\n` 再翻一次。MATLAB 在行首读到游离 CR，报"解析错误"。我据此**一度认定上游有 47 个文件语法错误，复核后其中 46 个是我的锅**。
   对策：转码一律**字节级读写**（`write_bytes`，不用 `write_text`），并为归档目录加 `.gitattributes`（`-text`）锁死字节；事后跑一条独立校验（本次是"数双 CR" + 复跑静态检查）。
   详见 `corpus/algorithms/PROVENANCE.md` §5.1。

10. **派发指令里凡断言"某件东西已入库 / 可复跑 / 已登记"，派发前必须在仓里核一次。**
    代价实例（2026-09-27，M3 Task 6）：任务书写"Task 1 的生成器已入库"，实际 `.superpowers/sdd/.gitignore` 是 `*`（整个目录被挡），
    **那个生成器从未入库、且已过期**（只能重放出修复轮之前的旧版）⇒ 实施者只能新写一个**入库的**重放式生成器，证据件从 774 行涨到 967 行。
    这与**通则 4.7**（派发里的**命令**必须先确认真实存在）同族，但这一条的对象是**断言**而不是命令；
    而"`.superpowers/**` 已被 gitignore"这件事本项目**明知**（通则 7、"证据放那里等于丢失"），**却仍从任务书写回了流程里**。

11. **改了任务书里的某一条差异之后，必须回头扫同一份任务书里与它耦合的其他行。**
    代价实例（2026-09-29，M3 Task 7）：同一份增量任务书同时钉死
    ① **射程 = 绘图家族名正则**（`mcm-plot-*` / `mcm-table` / `mcm-schematic`），
    ② 假 skill 的目录名**照抄原书**的 `fake-ok` / `fake-nopointer` / `fake-restate`。
    **这两条不可能同时满足**：`fake-*` 不在家族射程内 ⇒ 整目录判"家族 0 个"⇒ 判绿，
    于是 `M43` **永远不可能红**，`M44` 也证不到"家族 ≥1 且全绿"这条**唯一**的绿路径。
    实现者当场按家族前缀改名（**角色与内容一字未改**），复审判"成立且被逼"——**未造成返工，但属派发缺陷**。
    与**通则 10**同族，都是**派发前的自核**：10 核的是"我断言的入库状态是否属实"，
    这一条核的是"我新定的差异与同一份文件里的旧行是否相容"。
    **形态**：新裁的差异会**静默地**让早先抄来的 fixture 名 / 路径 / 期望值失效——
    这类矛盾**读得出来、看不出来**（两条各自都合理），只有把差异**逐条与全文对撞**才逼得出来。

12. **凡"按槽位默认落盘"的工具，调用时必须显式给输出路径。**
    代价实例（2026-09-29，M3 规划期）：`task-brief` 漏第三个参数时**不报错**，默认写到
    `.superpowers/sdd/task-<N>-brief.md`——那次 `task-1-brief.md` 这个槽位已被**第二期 M6 试点**的同名过程件占着
    （9138 B，2026-09-23）⇒ **被静默覆盖**。该目录**整棵被 gitignore**（通则 7）⇒ **git 无从恢复**，
    只能从受版本控制的计划重建（重建件 14753 B，文件头逐字写明"这是重建件、不是原件、两者不逐字节相同"）。
    同型的还有"任务书把**报告**落点写成被旧件占用的槽位"（那次实现者自己识别出来并让路了）。
    **形态**：默认槽位按**名字**匹配，而名字会重号（每个模块都有 `task-1`）⇒ 覆盖发生在派发者看不见的地方、且不报错。
    **与通则 10/11 同族**（都属"派发前的自核"），但这一条的对象是**输出路径**：
    它不需要核实任何断言，只需要**每次把路径写全**——是最便宜的一条。

13. **拿两个数比对（判"不符 / 有出入 / 是错的"）之前，必须先确认它们说的是同一个对象。**
    代价实例（2026-09-30，M3-plot Task 6）：任务书断言计划那句「同一张图 `PNG=2 / PDF=0`」是**错数**，
    依据是侦察实测 `2/1`——**当场实测证伪：那两个数是两张不同的图**。
    设计件 `docs/superpowers/specs/2026-09-29-m3-plot-python-design.md:132` 的 `2/0` 属 **`science+no-latex` 那张图**
    （带机制：PDF 走 `RASTER_DPI=150` 栅格化 ＋ 底座把 `linewidth` 压到 1.0 ⇒ 彩色占比落到 0.5% 地板下）；
    `2/1` 属**侦察那张朴素图**（`tests/m3-plot-recon/out-d11-red-loop.txt`，头部明写"不 import 任何 SciencePlots"）；
    而 Task 5 交付的那 12 张图又是 **PNG=PDF**（4/4、12/12、15/15）。
    **根因**：待办台账那一条当初**就没核过**这两个数说的是不是同一张图，控制者**照抄台账**、并把它升级成一条"订正指令"。
    **形态**："两个数不相等"这个**判断**本身是对的（`2/0 ≠ 2/1`），错在把它们当成**同一对象的两次测量**。
    ⇒ 比对前先写下"这两个数各自的**主语**是什么"；主语不同就**不许相减**（正确的写法是**带着图名**引用，如"侦察朴素线图 `2/1`"）。
    与既有「计划里写死的行为口径，落地前必须实测复算」（`docs/mcm-suite-todo.md` §H.1）同族。

14. **自核时，"核了"的范围必须覆盖被改动物的语义，而不只是关于它的一些元数据。**
    代价实例（2026-09-30，M3-plot 终审修复轮）：控制者自核了**范围 / 提交数 / 树干净 / 值池 delta**（全过），
    **独独没读那份被重新生成的证据件的正文** ⇒ 漏掉了随后由独立复核抓到的一条 Important：
    `tests/skills/plot-python/plot-style-verify.txt` 里印着 `exit=1`、一行"应为空"底下躺着**脏文件**、汇总 **`非零退出 1 条`**
    ——而它在**干净 HEAD 上复现不出来**（真跑得的是 `exit=0`）。
    **根因是节奏**：上一轮在**该文件自己还脏着**的时候重生了它。
    已修（`0ce008d`），且由控制者**亲跑生成器证不动点**：`exit=0` · `git status` 空 · `git diff` 空 · blob 不再变。
    **对策（可机械执行）**：凡"**证据件记录自身所在工作树状态**"的生成器，必须
    **先干净 → 再捕获 → 再提交 → 再跑一次证不动点**；
    而"核"这一步必须包含"**读一遍被改动物的正文**"，不是只核它的哈希 / 行数 / 出现次数。
    **与通则 13 同族**——那条是"核了，但核的不是那件事"，这条是"核了，但核的不是那件东西的那一面"。

15. **凡写颜色距离数，必须写明是哪把尺子；不许把两套尺子的数并置比较。**
    代价实例（2026-10-01，M3-style Task 6）：本仓在用的"颜色距离"**至少有两把**——`check-figure-style.py` 的 `F5` 注释用的是 **RGB 欧氏距离**，
    而色彩学通用的另一把是 **CIE76（CIELAB ΔE）**。**同一对色**在两把尺子下**差好几倍**，更糟的是**会翻转结论**：
    H14 八色里，**欧氏 RGB 最紧一对 = `#E69F00`–`#D55E00`（67.19）**，**CIE76 最紧一对 = `#0072B2`–`#7570B3`（22.15）** —— **不是同一对**。
    **形态**：一个"色差"数**不带尺子名就无从判真假**——两个都叫"距离"、都算得出来、都不是假的，但**说的不是同一件事**。
    **与通则 13 同族**（那条是"两个数说的是不是同一个对象"，这条是"两个**同名**的量用的是不是同一把尺"）；
    ⇒ 正确写法：**"欧氏 RGB 距离 67.2（本仓 `F5` 的口径）"** / **"CIE76 ΔE 22.1"** —— **两套不并置**。复跑命令见 `docs/mcm-suite-todo.md` §H.5.5。

## 二、流程教训（比通则更根本）

1. **审计问什么问题，决定审计能查出什么。** "这句有没有出处" ≠ "出处是不是这个意思"。第一期一次自查 9 处分级问题全部修对，却**系统性漏掉**了外延比对那一类——因为它的自查问题里没有这一层。
2. **修复不是单调改进，每轮都可能引入新错。** 实例：修复者把「出版者不详」写进出处栏，而同目录文件白纸黑字写着出版者是 `COMAP Inc.`。**复审不能省。**
3. **局部正确不会自动组合成系统正确。** 全分支终审的三处 Important 全是接缝上的洞：
   - `latex-format` 正确地保留占位符 + `selfreview` 正确地只查队号栏 → **题号栏无人查**
   - `ai-disclosure` 正确地把触发定义为"用过" + `selfreview` 正确地把判定操作化 → **整篇翻译不留痕迹会被判通过**
   - `latex-format` 正确地重编页码 + `selfreview` 正确地计入摘要页 → **页眉页码比实际少 1 的陷阱**
4. **隔离标签必须实测，不得由 flag 推断。** `isolation: "remote"` 在本环境**无隔离作用**（判据：subagent 能写本地绝对路径）。此前有一处"冷启动基线"是**由 flag 推断的，不是测量的**。
5. **通则能防"不知道这个坑"，防不住"以为自己没踩"。** 通则 7 已明确写进派发指令，Task 4 仍违犯。**后者只能靠独立审查。**
6. **当测试失败时，默认假设应该是"我的样本有问题"还是"我的判据有问题"——选错方向会把 skill 越改越松。**
   正面实例：反向验证判出对照稿 A11 不通过，实现者复核后认定那是**对照稿自身的真缺陷**，处置是**去修对照稿**而非放宽清单。
7. **实跑只能证明"不崩"，证明不了"算得对"；两类缺陷要用两套手段。**
   2026-09-23 对算法归档做完整验证（7 批、50+ 项，`tests/algorithms/`）得出的结论：
   - **工程性缺陷**（语法错误、接口错配、废弃 API、数据错配）→ **实跑一遍就暴露**。首轮 68 个脚本跑出 16 个失败，全属此类。
   - **算法性缺陷**（算的不是它声称的东西）→ **不报错、不崩溃，实跑永远看不见**。必须拿**独立参照**逐个对照：手算、换一个数学表述、用 MATLAB 内置的另一套实现、或穷举局部状态。这类缺陷在"能跑通"的脚本里又挖出 **4 个**。
   我一度据"全跑通了"写下"未发现静默算错"——**那是错的**，只因当时只覆盖了 20 个算法。**"跑通了"与"算对了"之间没有蕴含关系，别把前者当后者的证据。**
   配套做法：每个数值检查都要能说清**参照是什么、它为什么独立**。参照与被测实现共用一个函数（比如两边都调 `pcacov`）等于没验。

## 四、第二期（M6 语料流水线）的教训（2026-09-23）

来源：M6 前置流水线试点（43 份）的 7 任务执行 + 每任务独立审查。**开新模块前与 §一、§二 同读。**

### 4.1 错误的位置会**逐层上移**——加固一层，下一层露出来

这是本期最值得记的一条。同一类毛病（"验证看起来在工作，其实没有"）在三个层各出现一次：

| 层 | 表现 | 例 |
| :--- | :--- | :--- |
| **判据层** | 判据恒真／空过／过宽 | 六例，见 4.2 |
| **证据层** | 证据文件陈述了**不成立的语料事实** | `b-report.txt` 称"30 份论文没有 Contents 页"，实测 **42/43 都有** |
| **验证层** | **验证"判据会不会红"的那套机制自己假绿** | `watermark.py` 磁盘 CRLF vs 新建文件 LF，三个变异锚点没匹配上，脚本会报"3 条已验证"而**一次都没跑过** |

> **含义**：每立一道新防线，都要问"**这道防线自己会不会假绿**"。本期在验证层栽了一次——
> 而那一层本该是最后一道防线。

### 4.2 "判据在什么都没验的情况下报绿"——**六例**，两道防线都没拦住

1. A1 判据比较同一个文档的页数 → **恒为真**
2. `sha256_tree` 对错误合集名返回 `{}` → 两个空表相等，**零哈希也报绿**
3. 校验脚本崩溃时留下**已提交的** `RESULT: PASS`
4. `n_strip > 0` 被自己的样本筛选蕴含 → **恒真**；它声称会抓的情况会让样本**被排除出集合**
5. A3 的 `not bad_removed` 在"零移除"时差集为空 → **strip 完全失效也绿**
6. 证据文件里的假事实（4.1 第二行）

**防线演进**（记下这个顺序，下期直接用最强的那个）：
- 第一道："写出它在什么情况下会失败" → **拦不住第 4 例**（判据可以**看起来**可失败）
- 第二道（现行）：**"必须用一次变异证明它真的会红"** —— 改坏被测代码 → 跑一次 → 看红不红。
  **改不红就是假判据。** 只写"我认为它会因 X 失败"不算数。这条在 Task 2 已被证明有效。

### 4.3 单样本观察不能写成通则——而且**试点会掩盖它**

spec 曾写"水印 span 特征唯一：`MicrosoftYaHei` 72pt"。**那是从一份论文得出的**。
实测全 201 份有**三种**字体（`KaiTi`/`SimHei`/`MicrosoftYaHei`），字体启发式只覆盖 **43/120**。

**最阴险的一点**：**试点那 43 份恰好全在命中范围内**——试点的 43 份与全量的 120 份用的是同一批 2025 论文。
所以**试点会绿着通过，问题只在全量时才炸**。

> **含义**：试点的作用被高估了。它验证的是"**流水线能跑通**"，**验证不了"结论能推广"**。
> 凡"某特征唯一/恒定/总是"的断言，必须在**全语料**上量过才可写进设计——不是在全量跑过之后，
> 而是**在设计阶段**。

### 4.4 优先用**结构性**判据，别用会随输入变化的特征

同一件事：认"字体名"会随厂商更换而静默失效；认"XObject 的流是否为空"不会——
**流空了就画不出东西，与字体无关**。改用结构性机制后 120/120、81 份无水印件零误伤。

**同一个道理在别处又出现一次**：`HEADING_MIN_SIZE = 13.5` 是**全局绝对常量**，
而正文字号**逐篇不同**——42 份正文 12.0pt，`2522820` 正文 **10.9pt**、小节标题 12.0pt，
于是小节被降级、层级丢失。**全局绝对常量遇到逐篇变化的量，就是这类错误的温床。**

### 4.5 **"我没找到" ≠ "它不存在"**

我查了 `comap.com` 主域的三个页面，没看到历年题目入口，就写了"官网没有系统性的历年题目存档"。
**实际官方存档在 `contest.comap.com` 子域**，覆盖 2000–2026 共 27 年。

> 检查范围的声明放在结论**之后**没有用——**结论必须与已查范围等强**。
> 正确写法是"我查了 A/B/C 三处，均未见 X"，而不是"没有 X"。

### 4.6 速度：变异演示与发布校验要**分样本量**

Task 3 一轮修复的**墙钟 85 分钟**，根因是我要求"演示 4 条判据会红"却没说演示可以只用子集——
每条演示都跑了全量 43 份 × 约 7 分钟。

- **变异演示**：证明判据**能**失败，机制与样本量无关 → `--limit 3`，秒级
- **发布校验**：认证语料 → 必须全量跑一次，作为该阶段放行依据
- 故**每个校验脚本必须提供 `--limit N`**

这条会随任务放大：图表要渲染约 860 张 PNG、汇总要依次跑完所有校验脚本（单次可能 40 分钟以上）。

### 4.7 派发指令里的命令必须**先在仓里确认真实存在**

我在派发里写了 `python -m tools.papers.cli text …` 作为覆盖命令——
而 `cli.py` 是**第 7 个任务**才交付的，当时并不存在。被派发的 agent 自己发现了这点。

> 同理：**删掉一个符号时，影响面不止 import 它的代码，还包括把它写进文档的命令。**
> 本期有两次踩到——一次是删 `is_watermark_span` 弄坏了已入库文件所引用的复现脚本；
> 一次是我派发了不存在的命令。

### 4.8 政策/口径类文字**只允许一处权威表述**；文件里不写会随编辑过期的自指量

Task 6b 阶段 2 收尾时连续四轮修复，**功能层从第二轮起再没被挑出问题，所有缺陷都在"证据里的话与实测不符"这一层**。
据此立三条规矩（2026-09-26 用户裁定采纳）：

1. **政策/口径类文字只允许一处权威表述，其余文件只给指针**，不各自重述一套。
   反面实例：`models.txt` 与 `growth_triage.txt` 各自重述了 M-12 的逐字口径，其中一处还写着"口径只写在判据消息那一处"——
   **那句话字面为假**（三处都在写）。后果：改口径的人只改一处，另两处留旧（正是本文件 4.2 的错误族）。
2. **文件里不写"本文件有 N 行""本次新增 N 个"这类自指量**：它们在写入的那一刻就开始过期。
   实例：`types-recon.txt`/`ids-recon.txt` 的自引用行数被"订正"过两次，**两次的新值在落地同一刻就又过期了**。
   修法是**只给命令**（`wc -l < <path>`），数字留给读者当场量。
3. **凡证据/任务书/产物注释里出现数字或引用，必须同处给出复现口径**（命令或 blob）；做得到就给命令，做不到就标明"待核实"。
   实例：`coverage-recon.txt` 三个数（85 / 104·27 / 61）**按记录在案的脚本复现不出来**，而另五个数有整段说明——**同一文件里待遇不对称**。

**派发方（controller）的义务**（本期 7 次踩到，比实施方的错更根本）：任务书里**凡引用、转述、预期都必须标注"我量过"或"待你核实"**，否则实施者会照抄。
七次实例：编号型 `##` 915 条（量不出）· 样板里 D 题 "0/4 篇有 Key words"（实为 4/4）· 把复核员的口头概括写成对 `map-recon.txt` 的**引文**（grep 零命中）·
对"反面变异"效果的**预期**（把退化机制想错了）· 给复核员的 M-9 探针**例子**（实测打红的是别的判据）· R-3 的**缺口数**（说漏一个文件，实际漏两个）·
一条**自相矛盾**的指令（同时要求"写明理由"与"写明只有一处写理由"，逼实施者写出一句假话）。

## 六、skill 编写期的教训（2026-09-27）

### 6.1 别把 RED 的覆盖面当成 skill 的覆盖面——**机械可判的那一层会挤掉判断题那一层**

**事件**：`mcm-abstract` 的初稿（231 词）**几乎只有形式契约**——页数、官方三栏页眉、LaTeX 安全（未转义 `%` / 裸 `_` / `<sub>` / 裸 Unicode / 裸 `|` `~`）、外加一个能编译自检的脚本。
**质量与措辞层是空的**。用户一眼指出：*"似乎只是限制摘要的字数，对摘要的质量、措辞等的要求在哪"*。

**三条成因（都要记住）**：

1. **RED 的场景设计决定了它能发现的失败类型**。我的探针是"给一份**结果齐全**的正文 → 让 agent 写摘要"，
   ⇒ **"摘要不写结果"这类失败在结构上不可能被诱发**。我把"没观察到"误读成"不需要写"。
   **测试的覆盖范围，悄悄变成了 skill 的覆盖范围。**
2. **`writing-skills` 的"没观察到的失败不写指导"被我用过头**：那条针对的是**反理性化话术**（不为不存在的借口准备说辞），
   **不是"不写规格"**。规格与质量层**不需要失败的基线**，它需要的是**来源**（官方原文、判分表、评审导向）。
3. **机械可判的东西好写、好验、好演示**（编译、正则、页数都能当场证明），于是它**挤掉了难写的那层**——
   "什么叫写得好"。**一份只覆盖机械层的 skill 只能让人"别做错"，不能让人"做得好"。**

**规矩（写任何 skill 之前先过一遍）**：

- **先列交付物的全部维度**（例：**形式 × 内容完整性 × 措辞 × 判断/取舍**），**每个维度至少一个落点**：
  规格、REQUIRED 槽位、清单、指针，或一个可执行的工具。
- **每条质量要求都要有来源**：官方指针 / 标 `[社区]`（本项目口径）/ 判分表。**没有来源的要求不许写**。
- **RED 只负责"防坑"，不负责"定规格"**。交付前问一次：
  **"用户拿着它，能做出*好*产物吗？还是只能*别做错*？"**


## 七、M3 图表层与"可复算规范"的教训（2026-09-27）

> 背景：M3 的第一份 skill `mcm-figure-choose` 首次把**设计规范**做成**可被机器复算**的产物
> （规范正文 + 162 条守卫 + 46 条变异 + RED/GREEN 对照 + 逐数可复跑）。以下六条由它暴露，**都属于"判据与验证"这一层**。

### 7.1 计划/任务书里给的**代码也是代码**——恒真判据**三次出在计划里**

**事件**：三处"看着能红、实则恒真"的判据，**全部是我写在计划或任务书里的**：
① `0.005` 噪声地板——在原 6 张 fixture 上把地板改成 0，读数**一模一样**（3/1/4/1/1/6）⇒ 我设计的变异**不可能红**；
② `F3d` 写成 `words > 0`——`"Figure 4:".split()` 有 2 个词 ⇒ **恒真**，永远抓不到它要抓的空图注（当时那 17/662 条）；
③ `S3` 用全文正则扫 `radar`×`低频`——"构成"入口**顺带也标了低频** ⇒ 删掉 radar 定义行上的标注**照样命中**。

**规矩**：派发指令/计划里给的示例代码**必须同样接受变异检验**，不能因为"是我写的"就跳过；
派发时**明说"这段也要证它会红"**。**只有"改坏一次、看它真红"逼得出来——读代码看不出来，它们看起来完全能失败。**

### 7.2 "我推翻了别人的数"这个结论本身也要先被审（**归因即风险**）

**事件**：M3 Task 3 判定"上一轮评审给的 `57.2%` 复现不出来"，并把它写进**三份交付物 + 一条守卫**。
独立复核实测：**57.2% 完全可复现**（用入库证据里那段转写代码逐位重跑即得）——
实施者跑的**不是那支转写**（它那支去掉了 `//16` 分箱），**却把自己的读数写成了"那支口径"的结果**。
正确答案**就在仓内、一 grep 可得**。

**规矩**：前几轮的教训是"**转抄即风险**"；这条更进一步——**归因也是风险**。
凡"我发现别人的 X 是错的"，先回原文件核**参照到底是什么**，再下结论；**推翻性结论与判据同等对待**。

### 7.3 "**声明比事实大**"比"功能缺失"更值得抓

**事件（四次，同一型）**：`(r"\d+", "@TODO-整数兜底")` 让文档里新写的整数**自动豁免**，而文档同时宣称"每个数都有守卫"；
"覆盖率 91%"只在已登记名册内成立；中文数字写的规范值两道闸一起放行而文档写"完整"；
`--json` 时末行不是它声称的 `RESULT:`。

**为什么更该抓**：功能缺失**看得见**；**过大的声明会让下一个人以为已经覆盖**——它把"没有"伪装成"有"。
**规矩**：凡覆盖率/守卫/口径的**声明**，都要能指到一次**真的变红**；**没有变异证明的覆盖率数字不许写进交付物。**

### 7.4 隔离是**实测**命题，不是结构性断言

**事件**：我在派发里写"此刻 `.claude/skills/mcm-figure-choose/` 还不存在 ⇒ 写手读不到规范是**结构性成立**的，不靠 flag"。
**三个 RED 写手全部自报读了规范来源并反向设计产物**——规范在这份仓里**至少有 6 个可读落点**，
**其中一个是我预切、躺在盘上的后续任务 brief**（`.superpowers/sdd/task-m3-t3-brief.md`，里面有完整的 H1–H13 表）。
处置：作废整轮、brief 搬到仓外、提示词只加一句隔离句，并**把两轮提示词逐字并排入证据供审计**。

**规矩**：与既有教训（"`isolation:"remote"` 无隔离作用"）同族，但这次踩的是**自己的仓库布局**——
**隔离要连"我自己顺手放在盘上的东西"一起算**；可证的只有"未用 `fork`"，**其余只能自报，必须如实登记**。

### 7.5 仓内仓外不同规矩：`git hash-object` 的 `core.autocrlf` 差异

**事件**：`git hash-object <仓外路径>` 会施加 `core.autocrlf` 规范化，而 `<仓内路径>`（`tests/**` 已标 `-text`）**不会**
⇒ **同一份字节给出两个 blob**（实测某图注含 1 个 CRLF：仓内 `8948e039…`、仓外 `92882193…`、`--no-filters` 回到仓内值）。
差点据此误判"两份文件不同"。

**规矩**：判"逐字节相同"**一律用 `read_bytes()` 直接比**；`hash-object` 只在**同一侧**（都在仓内或都传 `--no-filters`）才可比。
与"判字节别用裸工具（`sha256sum`）"同族，但这是**同一个工具在两处行为不同**的新面。

### 7.6 证据件不得与**共用临时目录**的驱动器并发；"口径未落文 = 负债"

**事件**：生成证据件与变异驱动器**并发**跑（两者共用 `fixtures/_mut*`）⇒ 撞出**截断件**（不是报错，是安静地写出半个文件）。
**规矩**：凡是"生成器 ↔ 驱动器共用临时目录"的组合，**串行跑**，并在收工自证里核行数/字节与非零退出计数。

**同族的一条**：**口径未落文 = 负债**。图注词数那条口径**本来就登记在 `provenance.md`**（还写明"两口径不可互换"），
**我却只 grep 了 `*.md/*.py`、漏了 `.tsv`**，就下了"仓内没有记录"的结论。
⇒ **凡"没有记录/查不到"的结论，必须写明查了哪些面**（通则 4.5 的加强版）。
