## Global Constraints（**每个任务的复审都要拿到这一份**）

1. **两份权威各管一段**：**表**的规范只在 `.claude/skills/mcm-table/references/table-style.md`；**图**的规范只在

   `mcm-table/SKILL.md` **必须**含字面量 `references/house-style.md`（`K2`，判**双向**：缺指针红、点了名的 skill 存不存在也对）。
2. **`SKILL.md` 零数字字面量**（`K3` 只扫 `*/SKILL.md` —— 前提是**别在 `SKILL.md` 里复述规范数值**；`K3` 是**子串**判据，普通写法会意外触发）。
   ★ **`references/table-style.md` 是规范正文 ⇒ 数字按规范写**（它**不受**零数字约束 —— 先例：`house-style.md` 本身满是数）。
   ★ **`references/workflow.md` 不复述规范数值**；若**必须**出现数字（如行号、判据编号），
   **同批在文件头写清它们的类别并声明"不声称穷尽"**（先例：origin 的 `workflow.md`）。
   ★ 先例（origin 终审反复栽过）：**凡"本文件与 X 都…"的跨文件合取断言，必须把 X 也跑一遍**；
   收工前 `grep -cE "[0-9]"` 是**必跑项**，且**文件的数字自我声明要与实际逐处对得上**。
3. **不许出现第二份表的样式来源**：表的规则值只在 `table-style.md`，`SKILL.md` 与 `workflow.md` **只给指针**。

## 质检记录（**写计划时查出来的九处陷阱**，不是事后补的）

### P1 ★★ **家族落地涟漪 + 六个生成器之间的时序** —— 本支最容易出事的一处

`mcm-table` 在 `check-spec-pointers.py` 的**家族正则**里 ⇒ **一落地，全库普查读数就变**：
`扫到 8 个 skill` → **9 个**、`绘图家族 3 个` → **4 个** ⇒ **一批证据件过期，须按各自生成器重生成**。

★ **而这里有不可交换的时序**（origin 那支实测确立）：`gen-plot-style-verify.py` 与 `gen-plot-matlab-verify.py`
**都内嵌跑驱动器、都读全仓 `git status --short`** ⇒ **先跑的写脏树、后跑的当场撞红**（origin 曾因此**烤进一次假红**）。
⚠️ **订正（Task 1 实测，2026-10-02）**：我原先写"**六个生成器都读全仓 status**"—— **不成立**。
**只有两台读**（`plot-python/mutate-plot-style.py` 与 `plot-matlab/mutate-plot-style.py`）；
四台 figure-choose 与重放式基线**只做 `git hash-object`**。⇒ **次序约束只落在那两台之间**（"中间必须提交"）。
**实测取证**：在脏树上跑 plot-matlab 的驱动器 ⇒ 判据变异全达标但末行 clean 断言撞红、**exit=1**。
**今天的内嵌生成器一共六个**（实测清点）：

| 生成器 | 内嵌的驱动器 |
| :--- | :--- |
| `figure-choose/gen-{chart-types,house-style,pointer,skill}-verify.py` | `mutate-figure-style.py` |
| `plot-python/gen-plot-style-verify.py` | `plot-python/mutate-plot-style.py` |
| `plot-matlab/gen-plot-matlab-verify.py` | `plot-matlab/mutate-plot-style.py` |

**归 Task 1**：① **先实测确立"六个生成器的正确顺序"**（判据：任何一步跑完树为空；且**每个生成器重跑 ⇒ 捕获件逐字节不变**）；
② 把顺序**写进 `tests/` 下的一份 README 或既有 README 的例外段**（**别只活在报告里**——报告不进 git）；
③ 本支新增的 `gen-table-*`（若有）**同样要进那张顺序表**。

### P2 ★ `K2` 判**双向** ⇒ 建目录与"进射程"必须同批

`check-spec-pointers.py` 一建 `mcm-table/` 就把它扫进家族 ⇒ **`K2` 立刻开始判它**（必须含 `references/house-style.md` 字面量）。
⇒ **建目录那一次提交里 `SKILL.md` 就必须已经带指针**（先例：matlab/origin 的 Task 1 都是"建目录 + 摘标记同批"）。

### P3 ★★ **判据 #4 的分母（版心宽）从哪来 —— 设计件留的口子，本计划钉死**

设计 §5.1 判据 4 = "**编译后实测表宽 ≤ 版心宽**"。**但版心宽必须是确定的数**，否则这条判据的分母又是"推的"
（侦察的读数 2 就是"版心由文本行 2%/98% 分位推"，它自报**未与 PDF 自身页边距对照**）。
⇒ **归 Task 2**：**从编译本身拿**——在模板/骨架里插一句 `\typeout{MCMLAYOUT textwidth=\the\textwidth}`，
**解析 log** 得到 pt 值，再换算英寸。**这是确定的数**（LaTeX 自己算的），不是推的。
★ **验收**：这条读数必须**可复跑**，且在**给了骨架路径**时读的是**骨架的** `textwidth`（§5.3 加分项）。

### P4 ★ **"来源回显"的格式 —— 设计件留的口子，本计划钉死**

设计 §4.3 要求"每个数取自哪里"，判据 #8 要**机械判它**。⇒ **必须有一个格式**，否则判据落不了地。
⇒ **归 Task 1**（写进 `table-style.md` 的"产物契约"一节）：在 `\begin{table}` **之前**放一行注释，形如
`% mcm-table-src: r3c2 <- pasted:r3c2`（粘贴入口）/ `% mcm-table-src: r3c2 <- file:data/x.csv#row5:slope`（文件入口）。
**判据 #8 判的就是"这一组注释存在且覆盖到每一格"**。

### P5 ★ **`siunitx` 的 `S` 列与缺失值耦合**

`S` 列里放非数值（`--`）必须写成 `{--}`（花括号包起来），否则编不过。
⇒ `D8`（siunitx 当默认）与 `D6`（缺失值 `--`）**在实现上耦合**：**生成器必须自己处理**这个包装，
**不许把这个坑留给用户**。归 Task 2。

### P6 ★ **RED 写手的隔离与"数据要给它"**

本支的 RED 写手**不许看规范**，但**表格的 brief 必须含数据**（否则无从写表）。
⇒ brief 里放**数据 + 一句"做一张表"**（**不给**：本 skill、`table-style.md`、判据、侦察读数）。
★ 并**如实披露**：写手看得到 skill 列表那行描述与 `MEMORY.md`（先例口径，两轮都这么写）。

### P7 ★ **文本产物 ⇒ 对照可以逐字 diff**

与图不同，**生成的 `.tex` 是文本** ⇒ RED/GREEN 对照**可以直接逐字 diff**，比图那支的"渲成图靠眼睛"更硬。
⇒ **归 Task 3**：对照表**机器抽取**之外，**再加一层"两侧 .tex 的并排 diff"**（人工看一遍差异是不是"规范导致"）。

### P8 ★ **编译的确定性与"看"**

`pdflatex` 的 PDF 带时间戳 ⇒ **PDF 不可字节比**（GC11）⇒ 判据**一律基于文本/几何读数**（如 `\typeout` 的 log、
或用 `fitz` 量渲出来的 PNG）。**"看"那一层**：**渲成 PNG**（`pdftoppm` 或 `fitz`）+ agent 亲眼看。归 Task 2/3。

### P9 ★ **`gen-style-table.py` 的 `--check` 会看 `mcm-style.json`** —— 与表的规范**无关**

`gen-style-table.py --check`（15 条一致）是**图**的样式表（`mcm-style.json`）的守卫。
本支**不改那张表**（设计 §0.6：不动样式单源线）⇒ 这条门**应当一直是绿的**；
**若它红了，说明误动了图那条线** ⇒ **停手报控制者**。
