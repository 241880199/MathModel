# `mcm-schematic` 设计（2026-10-03）

**本设计件是 `mcm-schematic` 的最高依据。** 每条规则都带**出处**（实测读数 / 惯例），并**与出处同时写明它的边界**。

**读数来源**：`tests/m3-schematic-recon/` —— ★ **本设计写就时侦察尚未做**（那是 Task 0）。
凡标 **〔待读数〕** 的条目是**候选规则**：Task 0 之后必须**逐条**处置成"**升格为实测（带边界）**"或"**如实降为惯例**"，
**不许留着不处置**，也**不许**在没有读数的情况下把它们写成实测。

## 0. 已裁（**用户 2026-10-03 拍板，不要再问**）

1. **覆盖范围 = 三类全做**：技术路线图 · 机理示意图 · 模型结构图。
   理由：三者在 TikZ 里**共用同一套原语**（节点 / 箭头 / 分组框 / 分支汇合 / 标注），原语是主要工作量；
   机理示意图按**原语组合 + 常用构件**做，**不追求专用图形库**。
2. **产出方式 = 骨架族 + 原语兜底**（见 §3）。
3. **载体 = TikZ 单一载体**（**2026-09-27 已裁**，判据 = **载体选择以"agent 能否看见产物"为准**：
   本机端到端实测 `pdflatex` 编译 → `fitz` 渲 PNG → agent 可读图；证据 `build/m3-carrier/`，
   该目录**由 `.gitignore` 忽略、不入库**，故此处只留判据与结论）。
4. **验收 = 复用同一把尺**：`F1–F6`（`check-figure-style.py`）**直接复用**；示意图专属判据（`A` 族）
   **加进同一个检查器**（见 §5.1）。
5. **RED = 给中性骨架、不给规范与禁忌**（见 §5.3）。
6. **做全量侦察**（Task 0），**骨架表由读数定稿**。
7. **骨架的份数与成员不写死在本设计里** —— 只留位置与纪律（见 §3.4 的接缝）。
8. **不动**：`mcm-table/references/table-style.md`（YAGNI）· **不擅动**已收口的 `mcm-latex-format`（只登记，见 §7.3）。
9. **中文排版不在射程**：美赛论文是**英文**（论文骨架用 `article` + `newtxtext`，见 §7.3 的实测）。
   本 skill **自带的文档是中文**——那是给 agent 读的，不是产物。
10. **编译基准 = 本机 TeX Live 2026**；**网页端未验**（如实标为边界，见 §6）。

## 1. 定位与形态

| | |
| :--- | :--- |
| **是什么** | **实现半**：你给一段**「过程 / 结构 / 机理」的文字描述** → 它给**可直接编进论文的 TikZ 源码** + 编译过的 PDF/PNG **让你看一眼** |
| **不是什么** | ① **不选图型**（见下）② **不管数据**（它画**不是数据**的东西）③ **不管"图里说的话对不对"**（那是你的模型的事） |
| **与三个 `mcm-plot-*` 的根本差别** | 后者画**数据**、从 `chart-types.md` 的入口进来；**它画结构与过程** |

### 1.1 ★ 一处明确的偏离（**与 `mcm-table` 不同**）

`mcm-table` **不做选表型** —— 因为它上面有决策层接着。示意图这边不是这样：

**实测**：`mcm-figure-choose` 的 9 个入口里，与示意图沾边的**只有入口 7「流程」的一条首选 `flow chart`**；
而**入口 8「机理」的首选是 `line chart` / `phase portrait`** —— 那是**画模型解的曲线，属 `mcm-plot-*`**，
**不是**机理示意图。**机理示意图与模型结构图在那棵树里没有位置。**（复跑：读
`.claude/skills/mcm-figure-choose/references/chart-types.md` 的入口 7 与入口 8 两节。）

⇒ 所以 **`mcm-schematic` 自带一小段「先定是三类里的哪一类」**（一段话即可，**不成体系**）。
这是**如实补位**，不是越界；**不重述**决策树的任何内容。

### 1.2 文件结构

```
.claude/skills/mcm-schematic/
├─ SKILL.md                     # 短契约（零数字字面量；含→house-style.md 指针 ⇒ K2）
├─ references/
│  ├─ schematic-style.md        # ★ 本支的规范（每条带出处与边界）
│  └─ workflow.md               # 流程 +「★ 调用方纪律」
└─ assets/
   ├─ schematic-style.tex       # ★ 样式层单源（字体 / 色 / 线宽 / 圆角 / 间距 / 箭头宏）
   └─ skeletons/                # 骨架族（一份一文件，各自完整可编译；成员由 Task 0 定稿）

tests/skills/schematic/         # RED / GREEN 对照与变异样本
                                # ★ 判据本体**不在这里** —— 进 check-figure-style.py（§5.1）
```

**两处要点**：

1. **样式层单独成一个 `.tex`** —— 这样"图与示意图共用同一套视觉标准"这句话才**可机械核对**：
   骨架一律 `\input` 它，判据查的是**产物**。
2. **`SKILL.md` 里不写任何尺寸 / 颜色 / 字号字面量** —— 全在 `schematic-style.tex` 与 `schematic-style.md`。

## 2. 规范：`schematic-style.md` 的内容

规范分**两层**。

### 2.1 第一层 · **复用**（**只指过去，不重述**）

示意图与数据图**共用**的那些，一律指向 `house-style.md`：

| 复用哪一条 | 说明 |
| :--- | :--- |
| **字体与论文同源** | `newtxtext` 那套 —— **图与正文同源**（`F6` 已在量） |
| **图注写法** | `H9`（`Figure N:` 起 · 词数上限 · 句末不加句号 —— `F3a–F3d` 已在量） |
| **底色 / 显式色序** | `H14` + `F4` / `F5` |
| **宽度不溢出** | 版心为上限（`F1` 已在量） |

★ **同时写明不适用**：`H1–H14` 里**大部分是数据图的规矩**（坐标轴 · 刻度 · 图例 · 信息密度），
**对示意图不适用**。**不许**把该文件总结成"它也管示意图"。

### 2.2 第二层 · 本支新增的 `S` 条（**示意图特有**）

★ **下列全部是候选**（〔待读数〕）：Task 0 定稿时**逐条**处置。**每条必须与它的边界同时写。**

| 代号 | 默认（候选） | ★ 同时写明的边界 |
| :--- | :--- | :--- |
| **`S1` 语义** | **节点 = 动作或状态；箭头 = 有方向的因果 / 流转**；不用无向连线 | **无向关联**（"这些因素互相影响"）**没有好画法** ⇒ 该场景**劝退**，不硬画 |
| **`S2` 线型** | **实线 = 主流程；虚线 = 回环 / 可选 / 反馈**；同一张图里线型语义**只许一种解释** | 需要第三种语义时**加图例**，**不许**再借线型 |
| **`S3` 尺寸** | **节点尺寸由文字内容决定**，**不写死**固定宽高 | 长文本节点会挤爆版心 ⇒ **缩字号或改断行**，**不许溢出** |
| **`S4` 配色** | 默认**单色系深浅 + 至多一个强调色**，不用彩虹 | 强调色超过一个就**没有"强调"了** ⇒ 需要第二个时**改用形状 / 线型区分** |
| **`S5` 分层 / 节点数** | 层数与节点数**各有上限**（**具体数字〔待读数〕**） | 超限 ⇒ **拆成两张**或改用文字描述，**不硬塞** |

**这五条为什么现在只能标候选**：本仓硬规矩是**不许把惯例冒充实测**，而语料里**关于示意图我们一条读数都没有**
（表格那支有 `tests/m3-table-recon/`；示意图这边是空白）⇒ Task 0 补上。

## 3. 骨架族

### 3.1 形态

每份骨架**完整、可编译**，且**都 `\input` 同一份 `assets/schematic-style.tex`**。
五份**起步**（**成员与份数由 Task 0 定稿**，见 §3.4）：

| 骨架 | 画什么 | 它替你定死的东西 |
| :--- | :--- | :--- |
| `pipeline-linear` | **直线流程**：数据 → 预处理 → 建模 → 验证 → 结论 | 节点等距 · 主箭头方向 · 回环虚线画法 · **整图宽度** |
| `pipeline-branch` | **分支与汇合**：判定菱形 + 多路 + 再汇合 | 菱形尺寸 · 分支角度 · 汇合处对齐 · 路线线型 |
| `model-layered` | **分层模型结构**：输入 / 隐藏 / 输出，或 数据层 / 模型层 / 决策层 | 层间距 · 层内并列间距 · 跨层连线捆扎 |
| `loop-feedback` | **反馈回路**：存量-流量、正 / 负反馈环 | 回环出入点 · 环半径 · 正负号标注位 |
| `mechanism-block` | **机理块图**：储罐 / 流 / 坐标系 / 耦合箭头 | 块的最小尺寸 · 流的粗细语义 · 标注落点 |

**高概率候补**（**押注，不是承诺** —— 是否入库**由 Task 0 的读数定**）：**系统边界图** · **状态转移图** · **泳道图**。

### 3.2 三条纪律（写进 `workflow.md`）

1. **挑最接近的一份，并说出为什么挑它** —— 与决策树「首选不成立才翻备选」同形。
   差别大时**明说差在哪**，**不许**"凑合着改"。
2. **骨架兜不住就回原语** —— `schematic-style.tex` 里同时给出**宏**（节点 / 箭头 / 分组框 / 泳道 / 回环 / 标注）。
   回落时有一条硬要求：**自己保证整图宽度**（`F1` 的通过条件靠骨架写死，原语路线得自己算）。
3. **每份骨架带一张「改哪儿」对照表** —— 写明哪些是**内容**（改文字）· 哪些是**结构**（加删节点）·
   哪些**不许动**（间距 / 圆角 / 线宽 / 颜色 —— 那些是规范，要动得走 `schematic-style.tex`）。

### 3.3 骨架的自证

五份骨架（**加上 Task 0 定稿后新增的**）**入库前各编译一遍**，并作为 **GREEN 控制组**常驻
`tests/skills/schematic/fixtures/` ⇒ "**骨架自己就该全绿**"这件事**有机械证据**，不是声明。

### 3.4 ★ 接缝

**Task 0 的读数会改写本节的骨架表** ⇒ 因此：

- **本设计不写死骨架清单**（只写起步五份 + 候补三名 + 纪律）；
- **实施计划里也不写死**，只写"**由 Task 0 定稿**"——写在计划里 = 给它一个**必须回填的位置**；
- 骨架是 `assets/skeletons/` 下的**独立文件** ⇒ **加一份骨架不动任何判据与规范**（将来补骨架是加文件，不是改架构）。

### 5.1 判据：**同一把尺**（`F` 复用 + 新增 `A` 族）

  ★ **该命令依赖那份 scratch 目录仍在**（`caption.txt` 是跑这条命令时随手造的、不是采集件）；
  **scratch 一旦被清，命令即失效** —— 到那时按本段的**读数结论**复现即可，**不要**把这条命令当成永久可跑的东西引用。
- **新增 `A` 族**（示意图专属）。★★ **本表已于 2026-10-03（Task 2）按探针读数订正** ——
  **候选四条只落地三条，`A2` 如实降级**（探针：`tests/skills/schematic/fixtures/probe-a-measurability.py`

### 5.3 RED / GREEN 对照

- **RED** = 三个隔离写手各拿**同一份场景描述 + 一份中性最小骨架**（**能编译、能放节点与箭头，不含任何美赛样式决策**），
  **不给规范、不给禁忌**；各自产出 TikZ。
- **GREEN** = 用本 skill 出**同场景同内容**的图。

  **测不到"连图都出不来"那一类失败**。**不声称覆盖全部失败模式。**

### 5.4 「看一眼」层（**不许省**）

**把图编译出来、渲成 PNG、agent 自己看**：机械层判"结构对不对"，**眼睛判"读起来对不对"** ——
箭头压住字 · 两条线分不清哪条是主流程 · 图例丢了 · 标注落到画外。
先例：origin 那支的粉边与图例压数据、表格那支超长表题，**判据一条都不报**。
