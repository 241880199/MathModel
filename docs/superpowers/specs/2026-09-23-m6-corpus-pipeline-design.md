## 1. 背景与目标

素材已就位：`corpus/历届优秀论文/` 收到 **201 份获奖论文 PDF、9,397 页**。这是设计文档里 M6 语料索引的硬阻塞项，阻塞解除，主线 M6 → M2 → M3 可开工。

本流水线做的是 M6 的**开工前置**：把原始 PDF 变成"可检索、可引用、图能直接看"的语料库，并产出 `INDEX.md` + `TAGS.md`。

**目标不是"什么都抽"，而是让 M2（论文写作）与 M3（科研图表）能立刻检索到可用的原文与图。**

### 消费者决定范围

| 消费者 | 要什么 | 不需要什么 |
| :--- | :--- | :--- |
| M2 论文写作 | 结构、摘要写法、章节组织、措辞、公式在行文中如何引入与解释 | 公式本身的 LaTeX |
| M3 科研图表 | 图怎么画、图注怎么写、配色与排版 | 公式内容 |
| M4 数学模型 | 模型的数学表述 | **语料是 `corpus/algorithms/`，不是获奖论文** |

**结论：没有哪个消费者需要获奖论文里公式的 LaTeX。** 故公式一律不转 LaTeX（见 §5 阶段 4）。即便 M4 要数学内容，从 PDF 里 OCR 公式也比直接从已跑通、已验证的 `corpus/algorithms/` 取代码更差——获奖论文该提供的是**呈现方式**，不是**实现**。

### 2.1 水印形态（已确证）

水印是 **Adobe 标准水印对象**：

- 独立 Form XObject，带 `/PieceInfo << /ADBE_CompoundType << /Private /Watermark >> >>` 标记
- 另有独立 `/OC` 可选内容图层
- 红色（`1 0 0 rg`）72pt 微软雅黑
- **以覆盖层形式压在正文与图表之上**，不是烤进图像里
- 水印文字**存在于文本层**（`get_text()` 会抽到，故会污染文本语料）

因是覆盖层，摘除后**文本与图表同时变干净**。

### 2.2 一处必须澄清的前提

「每页都有水印」**只对 2023/2024/2025 这 120 份成立**。2022 那 44 份是真·原版，无任何水印（已渲染 `2200289.pdf` 确认：无 OCG、无 PieceInfo、首页 2741 字）。UMAP 的 37 份也无标准水印。**无水印的 81 份不得被本流水线改动**（判据 A5）。

### 2.3 数学符号的渲染方式（决定阶段 4 的取舍）

抽样 2025 十篇：**4 篇矢量数学 / 6 篇文本数学**。

- **文本数学**：数学字形在文本层，有 Unicode 映射
- **矢量数学**：数学符号以**填充矢量路径**绘制，**不在文本层**。已确证实例：`2025美赛O奖论文/A/2500836.pdf` p14 的公式符号是 items=76/65/34 的贝塞尔路径，位置与文本行对齐；该行文本层只剩一个空格（`' is the number of people who passed…'`）

**这直接否决了"用字形层给 OCR 公式做交叉校验"的方案**：对矢量数学的论文，字形层给不出符号，两边都空反而会报"一致"——假阴性。该方案已整体废弃。

## 3. 范围

### 3.1 做什么

1. 去水印 → **内存中过滤，不落盘**（见 §4.1）
2. 正文抽取 → md
3. 图表抽取 → PNG + 图注
4. 公式 → **裁图 + 编号/引述句抽取**（无 OCR）
5. 索引 → `INDEX.md`（稳定 ID）+ `TAGS.md`（三层）

### 3.2 明确不做

- **32 份扫描件本轮不碰**（试点是 2025，全电子版；UMAP 那批要不要 OCR 另议）
- **不做版面还原**（不重排成 LaTeX，只抽内容）
- **不引入向量库**（设计文档已定）
- **不做公式转 LaTeX、不做符号校验**（§1）

## 4. 目录布局

**原件原地不动**在 `corpus/历届优秀论文/`；派生物全部落到 `corpus/papers/`。路径映射写入 `PROVENANCE.md`。

```
corpus/papers/
├─ md/<合集>/<题号>/<原名>.md              # 正文（水印已在抽取时滤除）
├─ figures/<…>/<原名>/fig-03.png
│                     fig-03.caption.txt
├─ formulas/<…>/<原名>/eq-07.png           # 仅裁图，无 .tex
│                      eq-07.context        # 编号与引述句
├─ INDEX.md                                # 人读，每条带稳定 ID
├─ TAGS.md                                 # 机读，三层
└─ PROVENANCE.md                           # 来源/水印厂商/处理步骤/可复现命令
```

**没有 `clean/` 目录**——见 §4.1。

原件不搬的理由：教训记载**移动**既有文件会被权限拒绝；且原件的"水印出自哪家"本身是证据。

### 4.1 不产出清洗版 PDF —— 去水印只在内存中做

**修订（2026-09-23）**：初版设计要"去水印后另存清洗版 PDF"。实测证明**这一步是多余的**——需要的是**抽取出来的内容**，不是一份清洗过的 PDF。

于是 `clean/` 整个目录取消。**附带好处**：不再有约 270MB/试点（全量约 1.7GB）的派生 PDF 需要入库。

**三条路径共用同一个机制：在内存里置空水印 Form XObject 的流。**

| 需要的内容 | 办法 |
| :--- | :--- |
| 正文 | 内存置空水印流 → `get_text()` |
| 图表 | 内存置空水印流 → 渲染 |
| 公式 | 内存置空水印流 → 裁图 |
| 原件 | 全程只读，sha256 前后不变 |

#### 4.1.1 正文侧**不得**用字体/字号启发式（2026-09-23 修正）

初版写"水印 span 特征唯一：`MicrosoftYaHei` 72pt"。**那是从单份论文（`2500836.pdf`）得出的结论，被当成了通则——这是错的。**

实测全 201 份（证据 `tests/papers/recon/wm-font-coverage.txt`）：

| 厂商 | 份数 | 水印字体 | 字体启发式 |
| :--- | ---: | :--- | :--- |
| 校苑数模公众号（2025） | 43 | `MicrosoftYaHei` 72pt | 命中 |
| 校苑数模（2023/2024） | 72 | `KaiTi` 74.4/76.5pt | **不命中** |
| 英伽教育（2023） | 5 | `SimHei` 83.4pt | **不命中** |
| **合计** | **120** | —— | **仅 43/120** |

**字体启发式会静默漏掉 77 份。** 而置空 XObject 流是**结构性**的——流空了就画不出任何东西，不认字体，实测 **120/120** 全过、81 份无水印件零误伤。

**判定**：正文侧改用与图表/公式同一个 `strip_in_memory` + `get_text()`。字体启发式整体废弃——它是一套会随厂商更换字体而静默失效的机制，而全语料共三种字体已经证伪了"唯一"这个前提。

> **教训**：把单样本观察写成通则，是"过度声称已验证"的另一种形态。凡"某特征唯一/恒定"的断言，必须在**全语料**上量过才可写进设计。

> 若日后需要"无水印的可读 PDF"，那是**另一个一次性需求**，按需生成、不入库，不属于本流水线。

### 4.2 换行符与字节保真（硬要求）

本仓库 **`core.autocrlf = true`**，现有根级 `.gitattributes` 只保护了 `corpus/algorithms/`。

**`corpus/papers/` 下的 md 与图表 PNG 必须显式禁止换行转换**，否则会重演教训通则 9 的代价实例——那一次有 883 个文件被写坏成 `\r\r\n`，且我**一度误判为上游代码的问题**。

实施时须在根级 `.gitattributes` 追加：

```
corpus/papers/**   -text
```

**不得依赖 git 的二进制自动检测**——教训原文即"先排除搬运环节，再解释上游代码差"。抽取脚本的写入一律走**字节级**（`write_bytes`／二进制句柄），不用文本模式。

> 这条要在阶段 6 归档：换行转换造成的破坏会冲垮 A3（正文逐字比对），故 A3 天然覆盖此风险。

## 5. 六个阶段与验收判据

每步都配**独立参照**。理由见教训二.7：**实跑只能证明"不崩"，证明不了"算得对"。**

### 阶段 1｜去水印（内存中，不落盘）

两条路径，都不产出新文件：

- **正文**：抽 span 时按 `字体 == MicrosoftYaHei` 且 `字号 >= 60` **过滤掉水印 span**
- **图表 / 公式**：渲染前在内存里把水印 Form XObject 的流置空（`update_stream(x, b"")`），**不保存**

| 判据 | 独立参照 | 抓什么 |
| :--- | :--- | :--- |
| **A1 原件 sha256 前后不变** | 跑流水线前记录的哈希（全 201 份） | **一个字都没动原件**——最强的一条 |
| **A2 正文 md 水印字 0 命中** | 水印字表（3 个厂商名） | 漏滤 |
| **A3 被移除的文本必须全是水印碎片** | 逐 span 比对「裸 `get_text`」与「置空流后 `get_text`」；**每一个消失的 span 都必须是某个已知水印字串的子串** | **只滤了水印、没伤正文** |
| **C4 产出图表 PNG 无水印** | 结构化断言（strip 后水印流长必须为 0）+ 人工目视 | 图表带水印 |

> **A3 为什么这样定义**（2026-09-23 修正）：初版 A3 是"剔除水印字串后两边逐字相同"，但那个比对是**在整段文本上做字符串替换**——若水印把正文切碎（2023 那批每页拆成 8 个片段），替换法既可能多替也可能少替而不易察觉。
> 现在的 A3 直接问："**移除的东西是不是全都是水印？**" 只要有一个非水印片段消失就 FAIL。
> 这条判据**能回答"它在什么情况下会失败"**：stripping 吃掉任何正文 → 失败。
> 实测 2023 样本：移除 1,150 字，全部是 `校苑数模`/`校`/`模`/`校苑数` 一类碎片，零正文损失；无水印对照组三种方法字数分毫未变（43,178）。

> **A1 是骨干**：它把"原件没被碰过"从"我保证没写"变成**可验证的事实**。这比初版 A5（要逐份证明 81 个无水印件未被改动）强得多——**不改动原件，就不存在"改动错对象"这一类风险**。
>
> **A4 的偏红像素占比只是代理指标**，不单独作为结论依据。实测 2025 A 题 `2500836.pdf` p3：带水印 1.873%、去水印后 0.402%——**残余的 0.402% 是照片本身的暖色石质，不是水印**。故 A4 的结论以目视确认为准，数值仅用于筛出可疑页。

### 阶段 2｜正文抽取

PyMuPDF 字形层直接抽 → md（保留章节层级、图注表注文字）。**全程无 OCR、无推断**，故正确性可证。

| 判据 | 独立参照 |
| :--- | :--- |
| **B1 非空且量级相符** | 与 `pdftotext`（**另一引擎**）的输出做字数对照；**字符数差异 > 2% 的逐篇登记**，且每条差异须给出解释（换行/连字符/水印残留）。差异**不得静默通过** |
| **B2 章节结构完整** | 论文自己的 **Contents 页**——识别出的标题数 ≥ 目录条目数 |
| **B3 图注文字在** | 图注计数与阶段 3 对照 |

B2 的价值：论文自己声明了有几章，抽出来的必须对得上——参照来自作者，与抽取实现无关。

### 阶段 3｜图表抽取

**按图注定位**：找 `Figure N:` / `Table N:` 文本块，取其上方内容区**整区渲染**成高分辨率 PNG。矢量图与位图统一处理（逐图判断矢量/位图会漏）。

| 判据 | 独立参照 |
| :--- | :--- |
| **C1 图注计数 = 图片数** | 全文 `Figure N:` 出现次数与产出图片数**差额为 0**。差额非 0 时**不得静默通过**——须逐条登记解释（预期来源见 §8 风险 2） |
| **C2 非空白** | 非白像素占比；**阈值取 `< 0.5%` 判为空图**（初始值，试点后按实测分布校正并记录校正理由） |
| **C3 图注随图落盘** | 每张图配 `.caption.txt`，可逐条核对 |

### 阶段 4｜公式（无 OCR）

抽两样东西，都零推断：

1. **公式区域裁图** `eq-NN.png`（高清）
2. **编号与引述句** `eq-NN.context`：`Eq. (7)` 一类引用、`where n is …` 一类符号解释句——这是 M2 要的**写作模式**样本

| 判据 | 独立参照 |
| :--- | :--- |
| **D1 公式裁图数 = 编号出现次数** | 计数型判据，同 C1 |
| **D2 引述句可指回原文** | 每条引述句在 md 中能字面定位 |

### 阶段 5｜索引

**`INDEX.md`（人读）**：年份 / 题号 / 奖项 / 主题 / 亮点 / **稳定 ID**。

各栏的**来源与标级**必须写死在表头：

| 栏 | 来源 | 标级 |
| :--- | :--- | :--- |
| 年份 / 题号 / 奖项 / 队号 | 目录名与 PDF 首页摘要页 | `[客观]` |
| 主题 | 摘要页 `Key words` 行的字面摘录 | `[客观]` |
| 亮点 | 模型摘读 | **`[社区]`**，每条须附页/行指针，可复核 |
| 稳定 ID | 规则生成 | `[客观]` |

**「亮点」是判断栏，不得与客观栏混排而不标级。** 若某篇给不出可指回原文的亮点，该栏留空，**不填推测性内容**。

**稳定 ID 是本期的硬要求**（教训三.1 建议与 M6 一并做）：现有 `tests/check-index-pointers.py` 只能抓**悬空**指针，抓不到"条号重排后仍存在、却指向了另一条事实"的**静默失效**。故每条给一个不随重排变化的内容无关 ID（形如 `P2025-A-01`），并写一个能双向解析的校验脚本。

**`TAGS.md`（机读）**：三层，标级分明——见 §6。

### 阶段 6｜证据归档

全部判据的**逐字原文**落到 `tests/papers/`（受版本控制）。教训通则 7 的代价实例：证据写进 gitignore 目录，**已永久丢失**。

## 6. TAGS.md 三层设计

### 第一层｜客观（无判断成分）

```
year · problem(A–F) · award · team_no · n_pages · n_figures · n_tables · n_equations
sections: 章节标题字面清单
has_contents / has_assumptions / has_notations / has_sensitivity / has_extension
keywords: 摘要页 Key words 行的字面摘录
```

`n_figures` / `n_tables` 取自阶段 3 的 C1 计数；`n_equations` 取自阶段 4 的 D1 计数——**同一份事实不在两处各算一次**。

`has_*` 是**标题里字面出现了该词**这个事实，不是语义判断。

### 第二层｜判断（标 `[社区]`，逐条带出处指针）

模型/方法关键词：建**受控词表**（AHP、TOPSIS、PSO、Monte Carlo、Navier-Stokes、灰色预测、ARIMA、遗传算法、元胞自动机…），在正文里**字面匹配**，命中的才打标。每条附「词 + 文件 + 页码 + 上下文片段」。

**为什么用受控词表字面匹配而非自由生成**：字面匹配能指出命中位置，可复核、不虚构。由模型自由生成的标签是判断而非事实，无法复核——这正是第一期反复踩的坑。

### 第三层｜词表缺口自曝

**零命中的篇目单列**——要么真没用模型，要么用了词表外的模型。这是**已知漏检，登记而非假装没漏**。

### 局限（写死在文件头）

词表匹配抓不到"用了但没写名字"的模型，也抓不到词表外的模型。**`TAGS.md` 是检索入口，不是完备清单**——M2/M3 用它定位候选，再读全文。

## 8. 已知风险与局限

1. **去水印是本期唯一的高危环节**——已实测有效，且有 **A1（原件 sha256 不变）+ A3（正文逐字相同）** 双向判据锁住：A1 锁"没碰原件"，A3 锁"滤干净了但没伤正文"。**这是仅剩的高危环节。**
2. **图注定位法对"无图注的图"会漏**（如摘要页装饰图）。C1 判据会把差额暴露出来。
3. **`TAGS.md` 第二层含判断**，属 `[社区]`，不是客观事实（§6 局限）。
4. **32 份扫描件未处理**，其正文不可检索。这是**已知缺口**，不是遗漏。
5. **`has_*` 是标题字面命中**，不等于"论文确实做了敏感性分析"——只等于"章节标题里有这个词"。
