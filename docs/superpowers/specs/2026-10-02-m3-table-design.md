# `mcm-table` 设计（2026-10-02）

**本设计件是 `mcm-table` 的最高依据。** 每条规则都带**出处**（实测读数 / 惯例），并**与出处同时写明它的边界**。
**读数来源**：`tests/m3-table-recon/`（侦察证据，已入库；复跑命令见该目录 `README.md`）。

## 0. 已裁（**用户 2026-10-02 拍板，不要再问**）

1. **交付物 = 直接生成表格** —— 它是**实现半**（与三个 `mcm-plot-*` 同构），**不是**"只给设计要点"那一半。
2. **接口 = 方案 1**：贴数（对话）/ 给路径（CSV·TSV）。**设计里留接缝**（见 §4.3），**但今天不立"数据单源"**。
3. **做全量侦察**（不是抽样、不是只按惯例写）—— **已做**，六读数入 `tests/m3-table-recon/`。
4. **编译基准 = 本机 TeX Live 2026**；**网页端未验**（如实标为边界）。
5. **数值呈现 = 带默认规则的执行**：默认就合规，**每一条用户都能覆盖**（见 §3.2）。
6. **规范的家 = 本 skill 自带 `references/table-style.md`**；`SKILL.md` **仍带指向
   `mcm-figure-choose/references/house-style.md` 的指针**（`K2` 判据要求，且是有意义的交叉引用："图在那边、表在这边"）。
   ⇒ **不动**已收口并已推送的样式单源线。
7. **覆盖范围** = 普通三线表 **+** 合并单元格 / 多级表头 **+** 表注 **+** 表内公式。
   **不做**（**已裁**）：长表跨页、显著性标记（`***` / 上下标）。
8. **`siunitx` 当默认**（真正的小数点对齐）；降级成右对齐是**一句覆盖**（见 §3.2 的 `D8` 覆盖法）。
9. **加分项已纳入**：**可选**接收论文骨架 `.tex` 的路径，**在用户自己的 preamble 下再编一遍**（见 §5.3）。
10. **伪代码框不算表**：侦察在"表区"里检出 **6.2%（36 张）其实是 `Algorithm N` 伪代码框**，
   而获奖论文作者**自己的口径就不统一**。⇒ 本规范的"表"**不含伪代码框**；该 6.2% **如实记在读数旁**，不当成表。

## 1. 定位与形态

| | |
| :--- | :--- |
| **是什么** | 表格的**实现半**：**你给数 → 它给可直接粘进论文的 LaTeX 表格代码** |
| **不是什么** | ① **不选表型**（"该用什么表"属决策层，本支说到"这张表怎么排"为止）② **不管数据从哪来**（方案 1 的接缝）③ **不管"数对不对"**（今天套件里没有任何数字对账机制，见 §7.4） |
| **两半** | **判断层** = 数值呈现纪律（**有默认、你能逐条覆盖**）· **机械层** = 生成代码 + **编译一遍 → 渲成图 → 自己看一眼** |

### 1.1 文件结构

```
.claude/skills/mcm-table/
├─ SKILL.md                  # 短契约（零数字字面量；含指向 house-style.md 的指针 ⇒ K2 满足）
├─ references/
│  ├─ table-style.md         # ★ 表格的规范（每条规则带出处与边界）
│  └─ workflow.md            # 流程：给数 → 定列/精度 → 生成 → 编译 → 看图 → 交付
└─ assets/
   └─ table-template.tex     # 最小可编译模板（**只为"编译验收"用**；不是样式来源）

tests/skills/table/          # 判据 · 变异驱动器 · RED/GREEN 对照（**不带 `plot-` 前缀**：它不画图）
```

**为什么 `assets/` 里没有 helper 代码**：表格的产物就是**一段文本**，包一层 Python API 反而把
"你能直接看懂产物"变远（且用户偏好短契约式 skill）。模板存在的唯一理由是**编译验收需要一个能独立编的最小 `.tex`**。

## 2. 规范：`references/table-style.md` 的内容

### 2.1 由语料读数推出的三条（**每条与它的边界同时写**）

| 代号 | 规则 | 出处（读数） | ★ 同时写明的边界 |
| :--- | :--- | :--- | :--- |
| **`T1` 表型** | 默认**三线表**：`\toprule` / `\midrule` / `\bottomrule`，**不画竖线** | 读数 4：**恰 3 条横线 = 78.6%**（456/580）· 读数 5：**纯三线 = 69.0%** | ① **21.4%** 不是 3 条线（4/5/6/7/8/9 条各有）；② **31.0%（180/580）有长竖线** ⇒ **"不画竖线"是本规范的选择，不是"获奖论文都这样"**；③ `580` 读作**上界**（假阳性只逼到"未量化"）；④ 含 **6.2% 伪代码框未扣**（见 §0.10） |
| **`T2` 表宽** | **不拉伸**：默认取 `tabular` 自然宽度，**上限 = 版心宽**；超了就**缩**（缩字号 / `\resizebox`），**不许溢出** | 读数 2：n=580 · min **0.505** · p10 0.626 · **中位 0.893** · p90 1.022 · max 1.429 | ① **15.9%（92 张）的获奖论文表超版心，其中只 1 张被页框裁掉** ⇒ 这句是**"我们选的做法"**；② **版心是推出来的**（文本行 x 的 2%/98% 分位，两遍迭代），**未与 PDF 自身页边距对照** ⇒ 分母误差**未量化** |
| **`T3` 表题位置** | 表题默认**在表上方**（`\caption` 在 `tabular` 之前） | 读数 3：**上 57.8%** · 下 12.9% · **未定 29.3%** | **29.3% 未定**（未标号的表；探针**不硬塞**）⇒ **不许把那 29.3% 读成"上"** |

**读数只用于立规则的语境、不当作规则值**：读数 1（普及度 132/164 = **80.5%**）与读数 6
（论文层 **164/164 全部可量**）用于说明"**表格在获奖论文里普遍存在、且语料可量**"。
⚠️ 读数 1 **强依赖写死的阈值**（长线 ≥版心宽×0.50 / 对齐容差 2pt / ≥3 条），**未做阈值敏感性分析**
⇒ **80.5% 不是"与判据无关的事实"**，引用时必须带这句。

### 2.2 惯例层（**标"惯例"，不冒充实测**）

> **编号从 `D4` 起**：`D1`–`D3` 是草案里最初的"表题位置 / 三线表 / 表宽"三条，
> 它们**有语料读数支撑**，已**升格为上表的 `T1`–`T3`** ⇒ 这里不重复编号，也不留空号占位。

| 代号 | 默认 | 说明 |
| :--- | :--- | :--- |
| `D4` | **同列同精度**：同一列小数位数一致 | **不替你决定有效数字**（那是你的模型的判断） |
| `D5` | **单位进列头**（`Temperature (K)`），不在每格重复 | |
| `D6` | **缺失值写 `--`** | |
| `D7` | **默认不加粗**；你点名"哪个数是答案"才加粗 | |
| `D8` | 数值列用 **`siunitx` 的 `S` 列**（小数点对齐） | 覆盖法 = "别用 siunitx"⇒ 降级成右对齐 |

**这四条为何不标"实测"**：它们是**排版惯例**（书上有答案），量了也是同一个答案。本仓规矩是
**不许把惯例冒充实测**，故如实标"惯例"。

## 3. 接口与「默认 + 覆盖」契约

### 3.1 入口

```
① 直接把数贴进来（Markdown 表 / TSV / CSV 片段都可以）
② 或给一个路径（CSV / TSV）
   ＋（可选）一条覆盖指令（自然语言）
   ＋（可选）论文骨架 .tex 的路径        ← §5.3 的加分项
```

### 3.2 覆盖机制

**自然语言覆盖**（它是 agent 驱动的 skill，不需要形式化语法）。例：
"表题放下面" · "第 3 列 4 位小数" · "要竖线" · "别用 siunitx" · "把第 2 列最大的加粗"。
⇒ **默认 ⊆ 可覆盖**：**凡 §2 里的每一条，都必有一句覆盖法**；写不出来的默认不许进规范。

### 3.3 输入契约（**接缝 1**）

契约写成"**接受任意一张整洁表**"，**不写死某一种文件格式**。
⇒ 将来若立"数据单源"（`results.json` 之类），**加一个读取器即可，不动生成逻辑**。

## 5. 验证方案

### 5.1 三层（本套件惯例）

1. **机械层判据** `tests/skills/table/check-table-style.py`（对生成的 `.tex`）：

| # | 判什么 | 备注 |
| :--- | :--- | :--- |
| 1 | **编得过**（`pdflatex` rc=0） | **硬门**（对应图表那边的"起载体出图"） |
| 2 | **三线结构**：三件齐 + **无竖线** | `T1` |
| 3 | **表题在 `tabular` 之上**（默认；可覆盖） | `T3` |
| 4 | **编译后实测表宽 ≤ 版心宽** | `T2`；**量的是编译产物，不是读源码猜** |
| 5 | 列数一致、无空列 | |
| 6 | **同列精度一致** | `D4` |
| 7 | 缺失值形态一致 | `D6` |
| 8 | **来源回显在** | 接缝 2；**缺 ⇒ 判红** |

2. **变异驱动器** `mutate-table-style.py`：把上面每条**逐条打红**（改坏 → 跑 → 看它红 → 还原并自证字节相同）。
   **判据只能从失败方向证明**（本仓硬规矩）。
3. **RED / GREEN 对照** `tests/skills/table/red|green/`：
   - **RED** 由**没看过规范**的隔离写手产出（只给 brief + 输出目录；照 origin 那支的三写手口径），
     **证的是"没看规范 ⇒ 表上若干条判据红"，不是"写手笨"**；
   - **GREEN** 用本 skill 产出，**同场景同数据**；
   - 两侧**同一把尺**、**对照表机器抽取**（不手抄）。

### 5.2 「看一眼」层（**不许省**）

**把表编译出来、渲成 PNG、agent 自己看**：机械层判"结构对不对"，**眼睛判"读起来对不对"**
—— 列挤爆版心、表题与表离得太远、`\pm` 掉出来、小数位看着没对齐。先例：origin 那支的粉边与图例压数据**判据一条都不报**。

### 5.3 加分项：**在用户自己的 preamble 下再编一遍**（§0.9）

**可选**接收论文骨架 `.tex` 的路径 ⇒ 在**那份 preamble** 下编一次 ⇒ 报 **`rc` / log 错误行数 /
`Overfull \hbox` 计数 / 未定义控制序列名单**（信息行 `SKEL:`，**不进 RESULT**）。
★ **明确区分两件事**：**(a) 表本身编得过**（在自带模板里，**每次都自证**）· **(b) 嵌得进你的论文**（取决于你的 preamble）。
**不给骨架路径时，(b) 不验，且如实说不验。**

> **2026-10-03 订正（全分支终审修复轮 I-3，收窄声明）**：本节原写"直接报『缺哪个宏包 / 会不会爆版心』"、
> `table-style.md` §3.3 原写"给了骨架路径时读的是**骨架的** `\textwidth`" —— 两处**都未落地**：
> `--skeleton` **不做宽度比较、也不逐宏包点名**（`siunitx` 不在未定义控制序列的正则射程里），
> 判据 `C4` 的分母**恒**取自带模板。**收窄为上文口径**；未实现的两半登记在
> `docs/mcm-suite-todo.md` §H.2（`M3-table-FR2`）。**默认链（(a) 自证 + `C4` 用自带模板编译时
> `\textwidth`）不变。**

## 7. 与其它 skill 的关系

1. **`mcm-figure-choose/references/house-style.md`**：**图的**规范。本 skill 的 `SKILL.md` **带指向它的指针**（`K2`）。
   两者**分工**：图在那边、表在这边；**本 skill 不重述 house-style 的任何数值**。
2. **`mcm-latex-format`**（**实测的接缝**）：其骨架 `assets/mcm-2027-summary.tex`（`article` 12pt，101 行）
   加载的是 `geometry` / `newtxtext` / `amsmath` / `graphicx` / `xcolor` / `fancyhdr` ——
   **`booktabs` / `siunitx` / `multirow` / `threeparttable` 一个都没有** ⇒ **表格代码粘进去编不过**。
   ⇒ 本 skill 的产物**必附宏包清单**（§4.2）；并**登记一条归 `mcm-latex-format`**（"骨架若要用表，需补这几行"），
   **不擅动已收口的 skill**。
3. **家族涟漪（**已知工作量，不是风险**）**：`mcm-table` 在 `check-spec-pointers.py` 的**家族正则**里
   （`^(?:mcm-plot-.+|mcm-table|mcm-schematic)$`）⇒ **它一落地，全库普查读数就变**：
   `扫到 8 个 skill` → **9 个**、`绘图家族 3 个` → **4 个** ⇒ **一批证据件过期，须按各自生成器重生成**。
   ★ **硬约束（origin 那支踩出来的）**：**两个 `gen-*-verify.py` 不可背靠背跑**（顺序错会烤进假红）——
   **python 先、matlab 后，中间各提交一次**。
4. **数字对账：今天没有**。`mcm-abstract/check-summary.py:14` 明文写着"一份**数字是编的**的摘要**同样能拿到 `RESULT: PASS`**"
   ⇒ 图的数、表的数、正文的数彼此对不对，**全凭用户**。本 skill **只留接缝**（§3.3 + §4.3），**不承担**这件事。
5. **将来的 `mcm-schematic`**：届时若它也需要表格式的规则，再决定要不要把 `table-style.md` 升格成"家族共享"。
   **今天不做**（YAGNI）。

## 9. 已知缺口（**不声称穷尽**）

1. **长表跨页 / 显著性标记**：**本轮不做**（§0.7）。
2. **表以位图贴进正文的论文**：侦察探针无判据 ⇒ 会被当"无表"计入分母；**未量化**。
3. **跨页续表**：侦察里被记成两张、**未合并、未量化**（`B12`）。
4. **"表"里那 6.2% 伪代码框**：§0.10 已裁"不算表"，但**读数本身未扣**。
5. **版心是推出来的**：**未与 PDF 自身页边距对照**（§2.1 `T2` 边界）。
6. **读数 1 无阈值敏感性分析**（§2.1 末）。
7. **`mcm-latex-format` 骨架缺表格宏包**：只登记，未动（§7.2）。
8. **三处环境事实**：需 `pdflatex` · 网页端未验 · 跨机未验（§6）。
