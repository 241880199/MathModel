## 4. 单源机制（本设计的核心）

### 4.1 为什么不能手写样式件

`house-style.md` 是唯一权威（lessons 4.8）。手写一份带数值的 `.mplstyle`/`mcmplot.py` 就是**造第二份权威**。
而侦察实测：**今天没有任何守卫会去扫非 `SKILL.md` 的载体**——`check-spec-pointers.py:89` 的 `census()`
只 glob `*/SKILL.md`；把 `6.31` / `0.8` 放进 `references/style.md`、`style.mplstyle`、`style.py`，全扫器**一次都不扫**
（**手工**用 `--skill` 指过去时 `K3` 判得到，且 `K2` 会假红）。
⇒ **这条缝不许用手写件去撞**（那正是"声明了但没人守"）。

### 4.2 派生件

**样式件不是写出来的，是 `house-style.md` 派生的**：入库一个**生成器**，用**逐条锚定正则**从规范里取值，
写出 `assets/mcm.mplstyle` 与 `mcmplot.py` 的常量区。**锚点表沿用既有 `GUARDS` 的 fail-closed 惯用法**：
每条正则必须在文档里**恰命中 1 处**，否则 FAIL（防止锚点被挤到别处 / 被删）。

**可抽性边界（侦察 §C10 实测，必须照实写在生成器头部）**：

- **只有 H1 / H3 / H4 / H12 四条**的规则行里有**能机械抽出的阈值**；
- **H2 / H6 / H8 / H10 / H11 / H13 六条根本没有数可抽**；**H9 的可操作数在「依据」段**、
  与同段的 43 个分布读数**同形**，无法只靠正则区分"阈值"与"读数"；
- **朴素的 `\d+\.\d+` 会把非阈值抽成阈值**：实测误抽 `tab10`→`10`、`3D`→`3`、`p90`→`90`、`§7.2`/`§7.3`→`7.2`/`7.3`、
  `S1`/`G-H4-*` 里的数字。⇒ **一律用锚定正则，禁止全文档扫数**。
- **抽不到的那几条不许硬凑**：H10（去框线/刻度朝内）是**语义**，由底座与覆盖键落实；
  H9/H2/H6/H8/H11/H13 由 `SKILL.md` 的散文指回规范。

### 4.3 新鲜度守卫（**必须能真的红**）

`tests/skills/plot-python/` 下入库：

- `gen-mcm-style.py`：生成器（**重放式**：命令原地重跑、散文原样保留——沿用 `gen-figure-style-baseline.py` 的先例）。
- `check-style-freshness.py`：**重跑生成器 → 与入库件逐字节相等**；不等即 FAIL，并**打印出差异处的上下文**。
  锚点任一不命中 / 命中 >1 ⇒ FAIL（fail-closed）。
- **变异**（`mutate-plot-style.py`）：① 改 `house-style.md` 的某个锚点值 ⇒ 派生件落后 ⇒ **红**；
  ② 改派生件的某个常量 ⇒ **红**；③ 删掉一条锚点正则的目标行 ⇒ **fail-closed 红**。
  ★ 本仓纪律（记忆 [[declared-coverage-needs-a-real-red]]）：**声明了覆盖就必须有一次真的红**，读代码看不出来。

### 4.4 `SKILL.md` 的硬纪律：**零数字字面量**

`K3` 的**子串**匹配（`b in txt`）实测会让普通写法**意外**触发（清单见侦察 §B6，可复跑）：

- **红的写法**：`6.31` · `1.8` · `0.5` · `2.6` · `0.8` · `10.0`（因 `0.0` 子串）· `figsize=(6.3, 2.6)`；
  中文侧：`三色`/`两色`（单位词臂）· **任意位置的 `四`/`七`/`十二`/`十七`/`二十`**（裸值臂）⇒ `四川`、`第四版` 都会误红；
- **不红的写法**：`dpi=200` · `0.7777` · `no-latex`。
- ⇒ 本模块的 `SKILL.md` 与 `references/**` **一个数字字面量都不出现**（除 `H<n>` 编号与契约型计数，见下），
  这是**唯一**能长期存活于该判据下的写法。**要说的数一律回规范去说。**

## 9. 实测补充（2026-09-29，**在系统 matplotlib 3.10.7 上**，侦察那条未验项的落点）

侦察的一切 rcParams 读数取自**隔离装出来的 3.11.2**，并把"没在 3.10.7 上验"列进未验清单。
装好 SciencePlots 后补测（探针 `build/_env-probe/bbox_override_probe.py`，`figsize=(6.31, 2.6)` · `dpi=200` ·
分母 `6.31`），三条读数：

| 构型 | F1（PNG） | F1（PDF） |
| :--- | :--- | :--- |
| 朴素 matplotlib（对照） | 1.000 | 1.000 |
| `science+no-latex` **原样**（底座自带 `bbox='tight'`） | **0.870** | **0.871** |
| `science+no-latex` + **`savefig.bbox` 覆盖回 `standard`** | **1.000** | **1.000** |

⇒ **本设计的核心机制在系统版上成立**：覆盖 `savefig.bbox` 后输出宽重新 == `figsize` 宽，且 **PNG 与 PDF 逐位一致**。
（`tight` 那行的 0.870/**0.871** 与侦察在 3.11.2 上读到的 0.872/0.873 **不完全相同** ⇒ 印证了"换版本可能变"，
故**以本机 3.10.7 的这一组为准**。）

**两条必须写进实现的操作事实**：
1. **`import scienceplots` 是必需的**——它靠 **import 的副作用**把 `science`/`no-latex` 注册进 style 库；
   只 `import matplotlib.style` 然后 `plt.style.use(["science", …])` 会 **`OSError: 'science' is not a valid …`**。
2. **图内元素溢出时用 `layout='constrained'`（或 `fig.tight_layout()`），不要用 `bbox_inches='tight'`**：
   实测两者都**不影响 F1**（图宽恒定 1.000，它们只在固定画布内挪坐标轴），
   而 `bbox_inches='tight'` 正是那个**会把输出宽改掉**的键。

## 11. 字体与"绘图 / TeX 分离"的一致性（2026-09-29 用户裁）

### 11.1 分离是必然，但差异是分块的

matplotlib 与 LaTeX 是两个排版引擎 ⇒ **绘图与 TeX 天然分离**；"不分离"的唯一形态是 `usetex=True`（用户裁：不实现）。
不一致风险**分三块**，各自能不能对齐**实测过**：

| 部位 | 默认状态 | 能不能对齐 |
| :--- | :--- | :--- |
| **罗马字**（轴标签 / 刻度 / 图例 / 标题） | 字体族回退到 DejaVu Serif ⇒ **与论文不同** | **能，而且可以是同一份字体**：实测论文嵌的是 `TeXGyreTermesX-Regular`，而那份 OTF 在本机 TeX Live 里 |
| **数学**（`$…$` / 上下标 / 希腊字母） | `mathtext`（默认 DejaVu） | **不能完全对齐**：论文的数学是 `NewTXMI` + `txexs`，`mathtext` 是另一套实现。逐字形的同一做不到 |
| **字号 / 字重** | 规范 `H12` 是〔社区〕值、自标 **③ 无任何验证** | 只能设，**没有"证明对"的依据** |

**已载图佐证**（`build/_env-probe/side_by_side.png`，同一串文字上下对照）：罗马字**看着一致**；
数学有**可见差异**，最明显是 `\sum` 的上下限排法（`mathtext` 排显示式、上下标在正下方；newtx 排行内式、`i` 在右侧）。

### 11.2 随 skill 入库的字体（**用户裁**）

- **入库哪几份**：TeX Live 里 `fonts/opentype/public/newtx/TeXGyreTermesX-{Regular,Italic,Bold,BoldItalic}.otf`
  —— **论文实际嵌的就是这一族**（实测嵌的是 `TeXGyreTermesX-Regular`）。
  （`texgyretermes-*` 是同一设计的上游发布；本模块**取 newtx 那一份**，因为论文用的是它。）
- **许可（实测自 `tlpkg/tlpobj/*.tlpobj` 的 `catalogue-license`）**：`newtx` = **LPPL 1.3** ·
  `tex-gyre` / `tex-gyre-math` = **GFL**。两者**都允许再分发**，但 **GFL 要求许可原文随字体一起分发**
  ⇒ **许可全文必须与字体一同入库**（本机 TeX Live 的 `doc/` 树是精简的、没有这些文件 ⇒ 需另取，见 Task 2）。
- **代价（如实记）**：仓里多一份第三方二进制（4 份合计约 **0.86 MB** 量级）；与项目一贯"不把第三方语料搬进仓"的尺度
  **有张力**——用户已明确选它，换掉的是"依赖本机 TeX Live 路径"这一环境耦合（通则 6：环境事实写进判据就是负债）。

### 11.3 字体回退必须能被判据抓住（**用户裁：加**）

今天 `F1`/`F2`/`F3` **一个字都不判字体** ⇒ 字体回退是**静默**的：换机、字体没找到，就悄悄变成 DejaVu，
**没有任何判据会红**。这条要补：

- **判据形态**：渲染后核**实际用的字体**是否为预期那一份。两条可选的机械途径（实现者择一并说明理由）：
  ① 产出的 PDF 里 `fitz` 的 `get_fonts()` 所报 basefont 集合 ⊆ 预期集合（**强**：验的是产物本身）；
  ② 渲染后对每个用到的族跑 `font_manager.findfont(...)` 并与预期文件路径比对。
- **必须有一条真红**（本仓纪律）：**把入库字体改名/移走 ⇒ 判据红**（而不是静默回退成 DejaVu 仍然绿）。
- 顺带把这条的**射程写实**：它证明的是"用的是这份字体文件"，**不证明**"这份字体与论文观感一致"——
  后者没有机械判据，属判断层。
