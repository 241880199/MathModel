# M3 跨载体样式**单源** · 设计（2026-09-30）

> **这份文件回答什么**：同一篇论文用了**不同绘图 skill**（python / matlab / origin）时，
> **字体、表现形式、风格怎么才能保证相近** —— 用什么机制保证、保证到什么程度、哪些今天保证不了。
> **不回答**：具体图型怎么选（在 `chart-types.md`）；各载体自己的任务怎么写（在各自的实施计划里）。
>
> **它取代什么**：本设计**不是**新模块，而是**把"设计半 / 实现半"之间的那一层补上** ——
> 今天规范（`house-style.md`）只对人说，对机器只说了一半（3/13 可机械抽取），
> 于是 **N 个实现 = N 套解释**。本设计把中间那层做成**一份可被机器复算的共享样式表**。

## 2. 为什么今天不能保证（**实测，不是推论**）

### 2.1 硬实例：同一篇论文、两个 skill、两种字体

| 载体 | 出图内嵌字体 | 衬线？ |
| :--- | :--- | :--- |
| `mcm-plot-python`（已收口） | **`TeXGyreTermesX-Regular`**（随 skill 入库的 OTF） | **衬线**（Times 系） |
| `mcm-plot-matlab`（今天） | **`ArialMT`** | **无衬线** |

⇒ 同一篇正文里**肉眼就不一样**，而 **F1 / F2 / F3 一个字都不报**。

### 2.2 按"能不能保证"分三层

- **第一层 · 真有保证**：只有 **F1 图宽比 / F2 彩色主色数 / F3 图注形态** 三条
  （判据落在**产物**上、**载体无关**）。
- **第二层 · 规范写了、但无判据且各工具能力不同**：
  - **H12**（字号 / 线宽 / 字体族）：python 侧打死 **5 个键**（`savefig.bbox: standard` · `mathtext.fontset: stix` ·
    `font.family: serif` · `font.serif: TeX Gyre TermesX, …` · 去顶右框线 + 只留主刻度）；
    **matlab 侧一个都没有**（侦察：16 个 `.m`，绘图 API 命中 **0**）。
    H12 自标 **"③ 无任何验证"**；其 `0.8–1.0×` / `≥7 pt` 是**社区值、非实测**，
    守卫只是"数没被改掉"、**不是"实测对得上"**。
  - **H10**（去上右框线 / 刻度朝内）自标 **"③ 无任何验证"**（"本样本量不到刻度朝向"）。
- **第三层 · 规范明确不覆盖**：**H11**（网格线 / 图例 / 双 Y 轴）白纸黑字"**本规范暂不覆盖**"
  （图例判据一致率仅 15.8%）⇒ **本就不承诺一致**。

### 2.3 根因（结构性）

规范机械可落地只 **3/13**（H1 / H4 / H9）；每个实现 skill **各自**把 H1–H13 解释成本工具设置。
规范本身**不生成**任何跨工具的样式表 ⇒ **N 个实现 = N 套解释**。

### 2.4 两条同型缺口（本轮实测新发现，一并收）

- **★ 底色**：无头 MATLAB 默认出**深色底图**，而 **F1/F2/F3 对它全 PASS**（实测四载体满分通过）。
  量化：**78/84** 张产物底色是那层深灰；`theme('light')` **不带句柄是静默空操作**（图仍深色 84.8%）；
  `get(ax,'Color')` **会骗你**（设过白仍回深）。**python 侧也没人管** ——
  `mcm.mplstyle` 与 `mcmplot.py` **都没有 `facecolor` 条目**，白底全靠 matplotlib 默认值。
- **色序**：MATLAB 侧 **F2 抓不到默认色序**（7 条默认色序序列只读 **3**），
  因为 `color_count` **先剔近灰**（`max−min<24`）⇒ 深底与默认色序在它眼里都"等于不存在"。

## 3. 目标与非目标

**目标**：把"**1 套样式表 + N 个映射**"落地，使跨载体一致性**成为结构上可见、可被一条命令核**的东西，
而不是靠纪律约定。任何新载体（含人读的 origin 步骤）都能照着同一张表实现。

**非目标**：
- **不追求逐字同值**（见 §1.1）—— 今天做不到（MATLAB 用不了入库 OTF），且没必要。
- **不覆盖 H11**（网格 / 图例 / 双 Y 轴）。
- **不新建模块**：本设计改动的是**已有的**设计半（`mcm-figure-choose`）、已有的共享判据（`check-figure-style.py`）、
  已有的 python 实现（`mcm-plot-python`）—— 并把 matlab / origin 接上。

## 4. 规范侧改动（动已收口的设计半）

### 4.1 §0「交付形态前提」新增一条：**底色 = 论文底色（白）**

### 4.2 新开 **H14「配色：显式色序」**

**规则**：给出一份**载体无关的显式色序**（N 色 hex 列表），供各载体落地。

### 4.3 H12 补默认值

今天只有社区值区间（`0.8–1.0×` / `≥7 pt`）。补一组**明确的默认倍数与默认值**，来源如实标〔社区〕。

## 5. 载体无关样式表（**本设计的核心**）

### 5.1 为什么必须是**派生件**

与 python 侧同一套纪律：手写的样式件会静默漂。表由生成器**从规范重放产出**，并由守卫证明"它没被手改"。

### 5.2 表的 schema（每格含什么）

**一格 = 一个载体无关的样式量**，含：

| 字段 | 含义 |
| :--- | :--- |
| `id` | 稳定标识（如 `bg`, `font.family`, `series.color`） |
| `条目号` | 来自规范哪一条（如 `H12` / `H14` / `§0`） |
| `值` | 载体无关的值（hex / pt / 字体族名 / 布尔）—— **必须可人工转述** |
| `来源性质` | ① 实测 / ② 社区 / ③ 交付形态（§4.4） |
| `落地状态` | 逐载体一格：`能同值` / `按族等价` / `今天落不了地（原因）` |
| `各载体怎么落地` | python / matlab / origin 三列（见 §6） |

**★ 表里不许出现无主的数**：每个 `值` 必须能追到规范某条；追不到的**先补进规范**，不许留在表里。

### 5.3 生成器

`tests/skills/figure-choose/gen-style-table.py` —— **重放式**（沿用既有那套"锚点逐条恰命中 1 处"的 fail-closed 抽取）。
对规范里**抽不到**的量（只有规则没有数，或规则本身就是文字），**由生成器的常量区持有**，
并逐条标 `来源性质`；**这些常量本身也要有守卫**（防被悄悄改掉）。

### 5.4 新鲜度守卫

`tests/skills/figure-choose/check-style-table-freshness.py` —— **重放 ⇒ 逐字节等于入库件**。
⚠️ **必须遵守本项目已立的节奏**：凡"证据件记录自身所在工作树状态"的生成器，
**先干净 → 再捕获 → 再提交 → 再跑一次证不动点**（M3-plot 终审就是这么吃了一次亏）。

### 5.5 存放位置

- **表**：`.claude/skills/mcm-figure-choose/assets/mcm-style.json`（受版本控制，随设计半交付）。
- **生成器 + 守卫**：`tests/skills/figure-choose/`（与规范的其他机器件同处）。
- `mcm-figure-choose/SKILL.md` 说清分工：**规范 prose = 唯一权威；表 = 它的机器投影，勿手改。**

## 6. 各载体映射

### 6.1 `python`（改动既有实现）

`tests/skills/plot-python/gen-mcm-style.py` **改为读表**（不再自己抽规范），产出 `mcm.mplstyle` + `mcmplot.py`。
**新增 `facecolor` 系列键**（`figure.facecolor` / `axes.facecolor` / `savefig.facecolor` = 白）—— 今天一个都没有。
**线宽 / 字号的乘数**从表的"默认值"那一格取。

### 6.2 `matlab`（**待建**，本设计只定它的生成器契约）

`mcm-plot-matlab` 的生成器**只读同一张表**，产出 `mcmplot.m`（派生件）。

已由侦察钉死的三条硬约束（写进它的设计输入）：
- **每张 figure 必须显式上浅色主题**：`figure(...,'Theme','light')`（实测 98.1% 近白）或 `theme(fig,'light')`+显式设色；
  **`theme('light')` 不带句柄是静默空操作**，`get(ax,'Color')` **会骗你** —— 判据只能落在**产物像素**上。
- **导出载体 = `print` 家族**（用户裁）：`print -dpng` 跟 **`PaperPosition`**、`print -dpdf` 跟 **`PaperSize`**；
  设 `6.31 in` ⇒ F1 **1.000 / 1.001**。`exportgraphics` 的宽是**内容包围盒的函数**（实测 F1 0.861/0.865），
  **不作为权威交付载体**，只在文档里给用法与风险。
- **字体 = 系统 `Times New Roman`**（点名即内嵌 `TimesNewRomanPSMT`）。

### 6.3 `origin`（**2026-09-30 更新：脚本为权威**）

**★ 本支的输出形状在 2026-09-30 被实测推翻并改判**（原 `design.md:208` 写"GUI 软件，不产出脚本"）：
两轮独立侦察证明它**能完全脚本化**（`originpro` 1.1.15 + LabTalk + X-Function），
且 **导出宽度可精确设定**（PNG 像素逐值命中；PDF 页盒按英寸、量化 1/144 in）、**无隐式裁剪**、**实测 F1 = 1.001**、
**默认底色就是白**、**显式色序可设**、**PDF 是矢量**。⇒ **判定：与 python / matlab 同级，脚本为权威交付物 + 步骤为辅。**

**origin 列每一格必须含**：① 载体无关值（hex / pt / 字体族名）；
② **可照做的脚本命令**（LabTalk / X-Function 原文）；③ **可照做的操作步骤**（菜单路径 + 控件名 + 要填的值）作为**辅路**；
④ **针对哪个 Origin 版本**（`10.300197` = Origin 2026 / OriginPro 教育版）——菜单名与主题名随版本变。

**★ 四条实测出来的实施约束（必须写进 skill，否则会踩）**：
- **字体族走 `expGraph … theme:="Times New Roman Font";`**（实测产物字体名 `SimSun → TimesNewRomanPSMT`）。
- **★ 次序坑**：主题**必须在导出那一刻施加**。`themeApply2g` **只作用于施加那一刻已存在的对象** ⇒
  之后新建的文本注释**回到 SimSun**（实测：半张图两种字体）。**主题在导出时施加则可覆盖导出前加好的注释**。
- **★ 失败静默**：给**不存在的主题名**，`themeApply2g` 与 `expGraph theme:=` **两条路都静默成功**（`exec_ok=True`、产物毫无变化）
  ⇒ **"设上了"只能由产物证明**。另：`page.font$=`/`layer.font$=`/`sys.font$=` 返 **`False`**（属性真不存在），
  而 `xb.font$=…` 静默返 `True` 却什么都没做 ⇒ **`False` 能当"不存在"用，`True` 什么都不能当**。
- **进程卫生**：`originpro` 的 `atexit` 在没走到 `op.exit()` 时**只卸连接不退进程**（实测漏过进程）
  ⇒ **包装必须 `try/finally: op.exit()`**。

**★ 落地状态 = `"scriptable"`，但附两条已知缺口**（见 §10）：
~~**PDF 不内嵌字体**（34/34 个产物 `/FontFile*` = 0）⇒ 最终呈现**取决于打开它的机器**；~~
★ **订正（2026-10-03 批量清 `M3-origin-T1i`）**：上面这个负向全称**已被 `mcm-plot-origin` 支实测证伪** ——
Origin 产物**落哪一态依产物而定**（含内嵌 `Type3` 过程字形件 ⇒ `F6` 按族名判；不含才 `N/A`），
且 **`/FontFile* = 0` ≠ 没内嵌字体**。"最终呈现取决于打开它的机器"这半句**仍对**（只引用未内嵌时）；
且**依赖本机已授权的 OriginPro** ⇒ **干净检出复跑不相容**，复跑前置必须写明。

## 7. 判据改动（共享的 `check-figure-style.py`）

### 7.1 背景判据（**新**）

判"**背景色是否是论文底色（白）**"。**载体无关**：PNG 直接读像素、PDF 走既有 `raster_rgb()` 同一支仪器。

**★ 口径必须钉死，不许留"看着差不多"**：
- **量哪个区域**：**不能用角落单像素** —— 实测（MATLAB）出现"外围白、轴区仍深"（众数底色 `(18,18,18)` 占 75.9%）。
  ⇒ 取**众数底色**（最高频颜色）**或**轴区内区的区域统计；**具体取哪个、取样区怎么定，由计划定，并附实测依据**。
- **什么算"白"**：**阈值不许拍脑袋** —— 必须**由实测的两端标定**（已实测的两端：
  MATLAB 深色底画布 `(16,16,16)` / 轴区 `(18,18,18)` vs 浅色配方 `(255,255,255)`），
  阈值取在两端之间并**在计划里写明这个数是量出来的、不是选的**。
- 判据不通过要能报**实测到的底色值**（便于定位），不许只报"不白"。

### 7.2 颜色 / 显式色序判据（**新**，对应 §1.9）

今天 **F2 数的是"颜色占画布比例"**，因此**默认色序抓不到**（实测：7 条默认色序序列只读 3；MATLAB 侧同型）。
新判据按 **H14 的显式色序**判"图上出现的系列色是否落在允许集合内"。
⚠️ 与 F2 **并存而不替代**（F2 判"配色密度"，新判据判"色是不是那套"）。

### 7.3 字体判据的"族 → 可接受名"表（**新**）

按 §1.1 的"按族等价"：读**产物内嵌字体名**，映射到族，判"是不是允许的族"。
允许集合至少含 `TeXGyreTermesX-*`（python）与 `TimesNewRomanPSMT`（matlab）。
⚠️ **这条判据只能落在"产物内嵌字体"上**，不能落在"属性设上了没有"——
实测：MATLAB 侧 `set(...,'FontName','不存在的名字')` **不报错、`get` 还回声**、产物静默回退。

★ **订正（2026-10-03 批量清 `M3-origin-T1i`）**：该负向全称**已被实测证伪**（见本节下方 §7.3 与
`plans/2026-09-30-m3-style-single-source.md` 的订正块）—— Origin 产物**依产物**落 `PASS`/`FAIL`/`N/A` 三态；
`fitz` 报的名字在**只引用未内嵌**时确实是引用名，但**内嵌 `Type3` 过程字形件**时就是内嵌事实。
⇒ 判据必须能区分三态：
- **`PASS`**：内嵌了、且族在允许集合内；
- **`FAIL`**：内嵌了、但族不在允许集合内；
- **`N/A`**：**产物不内嵌任何字体** —— 判词里必须写出**这个事实**（"本 PDF 未内嵌字体 ⇒ 本判据不适用"），
  **不许写成 PASS**（那会让"读不到"冒充"读到了且是对的"）。

⚠️ **`N/A` 的代价要如实说**：Origin 支因此**没有字体侧的机械承重**——
它的字体一致性只能靠"**导出命令里写了主题**"来保证，而那条**今天没有产物级判据**。

⚠️ **中文字形是独立边界**（Origin 实测）：Times 名下汉字走 **SimSun 回退**，**渲染正常但文本不可提取**（Type3、无 unicode）。
⇒ 若规范要求 PDF 可检索、或要判"字体族一致"，**中文标签要单独定口径**；本设计**不覆盖中文**，如实登记（见 §10）。

## 10. 已知缺口（写进文件头，不许藏）

1. **H11（网格 / 图例 / 双 Y 轴）不在表内** —— 规范明确不覆盖，**本设计不承诺这一族一致**。
2. **字号 / 线宽 / 刻度朝向今天仍无机械判据**：规范里没有数（H12 是社区值、H10 自标无验证）；
   表会把它们的**默认值钉住**（单源），但"这张图真的用了这个值"**今天判不了**
   （要新增 PDF `span["size"]` / 绘制指令解析，本仓尚无）。
3. **origin 支：部分有承重、字体那一格没有**（**2026-09-30 更新**，原写"无任何机械承重"已被实测推翻）。
   现在它**能脚本化、宽度可设（实测 F1 = 1.001）、底色是白、色序可设** ⇒ `F1`/`F4`/`F5` **在它上面有承重**。
   **但字体那一格没有**：它的 PDF **不内嵌字体**（34/34 个产物 `/FontFile*` = 0）⇒ `F6` 对它只能判 **`N/A`**。
   ★ **订正（2026-10-03 批量清 `M3-origin-T1i`）**：这半句**已被证伪** —— Origin 产物**依产物**三态：
   含内嵌 `Type3` 过程字形件 ⇒ `F6` 按族名判 `PASS`/`FAIL`；不含才 `N/A`（`/FontFile* = 0` ≠ 没内嵌）。
   ⇒ 它的字体一致性**只能靠"导出命令里写了主题"保证，今天没有产物级判据**（此句**仍成立**）。
   另有两条本支特有的事实：**PDF 不内嵌 ⇒ 最终呈现取决于打开它的机器**（**只引用未内嵌**时成立）；
   **干净检出复跑不相容**（依赖本机已授权的 OriginPro）。
4. **中文字形不在射程内**（2026-09-30 新增）：Times 名下汉字走 SimSun 回退，**渲染正常但文本不可提取**（Type3、无 unicode）。
   本设计**不覆盖中文标签**；若将来要覆盖，口径要单独定。
5. **Origin 的"文字转轮廓"未排除**（2026-09-30 新增）：`opdf.ini` 的 `[Fonts] Embed=2` 注释原文写着 "outline fonts"，

6. **两载体的字体是"同族不同文件"**：python = 入库 OTF，matlab = 系统 TNR。
   这是**有意接受**的差异（§1.8），不是缺口 —— 但要**写清楚**，免得后来者以为"完全一样"。
7. **`check-figure-style.py` 的 `F1`/`F2`/`F4`/`F5` 只读 `doc[0]`**（既有已知）：多页 PDF 的 page2 及以后在射程外。
   ⚠️ 精确说法（原写"只读 `doc[0]`"已不精确）：**`F6` 例外** —— `F6` 走 `page_font_split()` **遍历全部页**
   （它判的是"整份 PDF 的内嵌字体族"）；`F3a`–`F3d` 只吃图注文本、与页无关。
8. **origin 列的"可照做的操作步骤"（§6.3③ 的菜单路径 + 控件名）** 全部未填（M3-style 终审 M-6 补登）：
