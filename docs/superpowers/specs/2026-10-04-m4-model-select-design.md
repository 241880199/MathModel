## 2. 文件结构

★★ **本结构对设计文档 §3 有一处改动（已获用户 2026-10-04 认可）**：设计文档写的是"**一类一个文件**"（八个 `references/*.md`），
实测**装不下** —— 全深度下网络那类有 **11 个方法** × 六格 ≈ 1000+ 行。⇒ 改成 **"一类一个索引 + 一方法一文件"**。
理由：① 本仓偏好**聚焦小文件**；② 赛时是"**先选类、再选方法**"的**两跳**，正好对应两层文件。

```
.claude/skills/mcm-model-select/
├─ SKILL.md                       # 决策树 + 边界声明 + 八类索引（<150 行）
├─ check-model-select.py          # 判据 MS1–MS6（随 skill 走，全仓唯一一份）
├─ assets/matlab/<类>/<方法>.m    # 代码骨架（随 skill 入库）
└─ references/
    ├─ evaluation.md              # 类索引：何时用这一类 + 类内判据树 + 方法清单（指向 methods/）
    ├─ evaluation/ahp.md …        # 一方法一文件（六格）
    └─ （八类同构）

tests/skills/model-select/
├─ mutate-model-select.py         # 变异驱动器
├─ make-evidence.py               # 证据生成器
├─ MODELSELECT-evidence.md        # 由生成器产出
├─ verify/                        # ★★ 骨架的独立参照与验证记录（见 §4）
└─ README.md
```

★ **判据本体随 skill 走**（同 `mcm-abstract/check-summary.py`、`mcm-section-writer/check-section.py` 先例）；
**测试侧只放驱动器与证据**；**判据逻辑全仓只许一份**。

### 2.1 ★★ 两条**硬命名约定**（设计复核 Medium，初稿完全没定）

1. ★★ **MATLAB 文件名必须是合法 ASCII 标识符** —— **中文名不能作为 MATLAB 函数被调用**
   ⇒ 骨架一律用 **ASCII 蛇形**（如 `shortest_path.m` · `topsis.m` · `sir_seir.m`），**不许用中文文件名**。
2. ★★ **"中文方法名 ↔ ASCII 文件名"的映射表**必须**随 skill 入库**（建议 `assets/matlab/MAP.md` 或写进各**类索引**的清单列）。
   ★ **它同时是 `MS6` 的前提** —— 没有那张表，"最短路" ↔ `shortest_path.m` **无法机械对齐**，`MS6` 就实现不了。
   ★ **并规定**：**类索引的方法清单**每行**三列** = **中文名 · ASCII 文件名 · 六格文件的相对路径**（`MS6` 就按这三列双向核）。

### 2.2 ★★ 盘上素材的**路径写法**（**收口复核标为 A 类：不写死会让 `MS2` 静默假绿**）

**问题**：本件 §11 的花名册通篇用**简写** `src/…`（如 `src/GreySystem灰色系统/GM_1_1.m`），
而**实际位置**是 `corpus/algorithms/src/GreySystem灰色系统/GM_1_1.m`。
★ 若 `references/**` 沿用 `src/…` 简写，而 §5.1 的抽取语法**只认 `corpus/` 与 `.claude/` 前缀** ⇒ **`MS2` 对归档路径的覆盖 = 0**
—— ★ **注意它不会因此判红，因为那些引用压根不在抽取面上**（**"不被覆盖"与"判绿"是两个不同的失效**：见 §5.2）。

**写死**：
1. ★★ **`references/**` 与 `assets/**` 里凡引盘上素材，一律写全路径**（`corpus/algorithms/src/…`），**不许用 `src/…` 简写**。
   ★ **本件 §11 花名册里的 `src/…` 是"表内简写"**，**它的定位是"给人读的范围定义"，不是"给判据核的指针"** ——
   ⇒ **写方法文件时必须还原成全路径**（**这一步是 Task 0 的活儿之一**）。
2. ★ **§5.1 的抽取前缀白名单**（`corpus/` · `.claude/`）**保持不变**；**并把"白名单之外的前缀一律不认"作为已知边界写清**。
3. ★ **进变异驱动器**：把某条引用的全路径改成 `src/…` 简写 ⇒ 该条**必须从"被覆盖"变成"不被覆盖"并被 `MS2` 报出来**（**证明这个洞不是静默的**）。

### 2.3 ★★ `SKILL.md` 的**决策树形态**（**收口复核标为 A 类：完全没写会卡住计划**）

**写死**（节点与字段 —— ★ **注意：下表大部分字段机械判据管不到，见本节末的诚实边界**）：

| 项 | 规格 |
| :--- | :--- |
| **入口** | 用户给的**题面特征**（不是数据）—— 如"要排序/评价"·"要预测未来"·"要有机理的动力学"·"要最优决策"·"要模拟演化" |
| **每个节点** | **一问 + 该问的判据 + 它指向的类**（八类之一或"再看下一问"） |
| **叶** | **一个类**（不做"类内选方法"的机械决策 —— 类内由**类索引的判据树**继续） |
| **每片叶必须带** | ① **该类的适用判据** · ② **该类的反面（什么时候不该用它）** · ③ **指向该类索引的路径** |
| **★ 必须显示声明的** | §1.1 的官方边界（"最终选择与结论由队员负责"）**必须在 `SKILL.md` 里显式成句**（`MS5` 判这个） |
| **★ 不许有的** | **不许**在 `SKILL.md` 里复述各方法的具体步骤/参数（那是 `references/**` 的内容 —— 第二份来源） |

★ **行数上限照契约**：`SKILL.md` **< 150 行**（设计文档 §4）。
★ **本节的"两跳"写死**：**第一跳 = `SKILL.md` 的决策树（题面特征 → 类）**；**第二跳 = 类索引的判据树（类内 → 方法）**。

★★ **诚实边界（末轮核验 B 类，必须写在这里，否则就是"声称比事实大"）**：
**上表里除"边界声明"（`MS5` 判）与"叶的类索引路径"（可并入 `MS6`）外，其余各行 `MS1`–`MS6` 一条都不管**
⇒ **不许**把本节写成"有可核面"（初稿那句"使 `MS5`/`MS6` 之外的部分也有可核面"**已删**）。
**它们的处置**：**进人工/独立复核的清单**（复核员拿本节这张表逐行核 `SKILL.md`）；**机械判据不覆盖**。
★ **并补第二跳的规格**（末轮核验 Q1① 指出的缺口）：**八份类索引**同样**按本节这张表的形态写**，只是"入口"换成**该类内部的方法特征**、
"叶"换成**一个方法**（→ 指向 `references/<类>/<方法>.md`）——**即：类索引是同一个决策树形态的"第二层实例"**。

## 4. ★★★ "算得对"的独立参照口径（**本模块最难的一格**）

本仓铁律（教训 1）：**实跑只能证明"不崩"，证明不了"算得对"**；**算法性缺陷只有拿独立参照逐个对照才现形**。
⇒ 每个骨架**必须有一份"独立参照记录"**。★ **注意措辞**：**"记录"是必须的、可判的；"真的独立"是判不了、要人读的**（见 §5 的两层处置）。
★★ **本句初稿写"必须有一个与它不同源的独立参照"，被设计复核判为"声明比事实大"，理由有二**：
① 它与本件 §5 自己承认的"**独立性机械判不了**"**互斥**；② 下头这几类里**确有方法套不上**（见 §4.1）。
⇒ 已降级为"**必须有记录**"，独立性另走判断层。

按方法性质**四选一**：

| 方法性质 | 参照形态 | 例 |
| :--- | :--- | :--- |
| **ODE / 差分方程** | **解析解** + **收敛阶检验**（步长减半，误差按阶下降） | `dy/dt = -λy` 有闭式解；RK4 应呈 4 阶 |
| **盘上已有素材的六类** | **盘上已有实现**交叉对照（**不同源**：我们新写的骨架 vs 归档里的老实现） | ★ **本格初稿举的"最短路 vs `grTheory` 的 `Dijkf.m`"是错的**（见 §4.2 与 §11.7：`Dijkf.m` 不在 `grTheory`；且**最短路不在 `fixed/` 六件里 ⇒ 本就不可作第 2 类参照**）。★ **正确形态**：**参照件只许取 `corpus/algorithms/fixed/` 的 6 个净室重写版**，如 `fuzzy_evaluation` 对模糊综合评价、`ahp` 对 AHP、`exponential_smoothing` 对指数平滑 |
| **确定性算法** | **手算的标准算例**（期望值能手算出来，写死在参照文件里） | TOPSIS 的三方案三指标算例 |
| **统计 / 随机算法** | **已知参数的合成数据**（从已知分布抽样，检验估计量/统计量是否达标） | 从 `t(ν)` 抽样验证 `ttest` 的拒绝率 |

★ **参照与骨架都落盘**（`tests/skills/model-select/verify/`），**跑得出同一个数才算过**；
★ **不许"跑通即算对"**；★ **随机算法必须固定种子**，且**给出多次运行的分布**（不是跑一次就宣称达标）。

### 4.1 ★★ 本口径的**已知覆盖缺口**（设计复核实测，**不许假装四类能盖住一切**）

**四类参照里有三个方法套不上** —— 这不是"待解决"，是**必须写进产物、由人工兜底**的：

| 方法 | 为什么四类都套不严 | 兜底（**判据管不到，归人工/独立复核**） |
| :--- | :--- | :--- |
| **ABM（多智能体仿真）** | 无解析解；不是估计量，合成数据也不对口（**输出是涌现行为，没有 ground truth**） | ① **手算一个 2–3 agent 的确定性小例**（能逐步推演）；② **性质检查**（守恒量 / 边界行为 / 参数单调性） |
| **t-SNE / UMAP（降维）** | 非确定性、**没有 ground-truth 输出**（"看上去分开了"不是判据） | ① **合成流形**：造一个**已知簇结构**的数据，查**邻域保持率**（kNN 一致性，这是个可算的量）；② 固定随机种子 |
| **元胞自动机** | 同 ABM（局部规则 → 全局演化，无闭式解） | ① **手算小网格前几步**；② **已知规则的标准图案**（如生命游戏的 glider 周期） |

★ ★ **因此**：`MS3` **只判"记录在场 + 四要素齐"**；上表三类的**兜底质量**只由**独立复核逐条读**。
★ **明写**：**这三类的"算得对"本模块没有机械保证** ⇒ **不许在 `references` 或证据件里写成"已验证"**（只能写"有参照记录、兜底方式见下"）。

### 4.2 ★★ 第 2 类（盘上已有实现交叉对照）**最容易造出假参照** —— 三条硬约束

**风险是真的**：① 若新骨架**是照归档代码改写**的，则**同源**；② 归档是**教辅级**（`INDEX.md` §10 确证 **20 个缺陷、含 4 个算法性**）
⇒ **两边不一致时无法判定谁错，一致也不能排除"同源同错"**。

**三条硬约束**：
1. ★ **参照件只许取 `corpus/algorithms/fixed/` 的 6 个净室重写版**（实测仅 6 个：`ahp` · `euler_circuit` · `exponential_smoothing` · `fuzzy_evaluation` · `parity_ca` · `trend_extrapolation`）——
   **其余归档件不得当独立参照**（它们没经过净室重写与数值验证）。
2. ★ 参照记录里**必须写明**："参照件与骨架的**算法、作者、来源不同**，且**骨架不是照它改写**"。
3. ★ **优先用第 1/3/4 类**（解析解 / 手算 / 合成数据）—— 它们**与任何实现无关**，**天然不同源**。
   **第 2 类只在没有别的选择时才用**，且**要在记录里说明为什么不得不用**。

★★ **本件初稿举的例子本身是错的**（设计复核实测抓出）：初稿写"最短路 vs **`grTheory` 的 `Dijkf.m`**" ——
**实测 `Dijkf.m` 在 `GraphTheory(图论)/detailed/最短路/Dijkf.m`，`grTheory` 是 `basic/` 下的 `gr*.m`（作者 Sergiy Iglin，最短路走 `grShortPath.m`，用 Floyd-Warshall）** ⇒ **两条线的作者与算法都不同**，初稿把它们混成一个东西了。
⇒ 正确写法：`grShortPath.m`（`basic/`，Floyd-Warshall）**才是** `grTheory`；`Dijkf.m`（`detailed/`）是**另一个作者的 Dijkstra 实现**。
