# §2 定位符（`理由` 的第一个字段，空格前）
# ---------------------------------------------------------------------------
#
#   * `kw:<稳定 ID>`    —— 词形在该篇 **`TAGS.md` 的 `keywords` 栏**里可定位
#                          （`taxonomy.normalize_for_locate` 口径的**空白归一化子串命中**）。
#   * `kwseg:<稳定 ID>` —— 词形在该篇 **md 的 `Keywords` 段**里可定位。
#                          段的切法（写死）：从 `V_KEYWORDS` 命中行的 `group(1)` 起，
#                          逐行并入**后续行**，直到遇到：空行 / `<!-- page` / `#{1,6} ` /
#                          `^\d+(\.\d+)*\s` / 又一处 keywords 行 / `Problem Chosen` / `Team Control`；
#                          并入时**行与行之间只留一个空格**（不补也不删字符）。
#                          ⇒ 断词（连字符行尾）在两路下分别得到 `Doubly ro- bust estimator`
#                          这种形态（**带空格**），本表的词形就按这个形态写，不替作者改字。
#
# **为什么要有第二个定位符**（**与任务书的出入，如实登记**）：任务书 §一 产物 2 写的口径是
# 「分流表里的每个词形**必须能在某篇论文的 `keywords` 栏里逐字找到**」。实测发现 `keywords`
# 栏对 **17 篇有截断**（§1），若只留第一个定位符，就会把**作者确实写了**的词形判成「编造的」
# ——那正是 M-11 要抓的**反向**误报。故加第二个定位模式，并**同时收紧**：每一行都要
# **指名到「哪一篇」**（任务书原口径只要求在 42 篇 keywords 栏的并集里能搜到，不要求指名）。
#
# ---------------------------------------------------------------------------
# §3 `类别` / `处置` 的定义（判据按这一节判，不按措辞猜）
# ---------------------------------------------------------------------------
#
#   * `模型`     = **模型 / 算法 / 方法 / 数学结构**的名字（不论通行还是作者自建）。
#   * `场景`     = **非方法**的语义词：领域 / 地点 / 赛事 / 政策语境 / 研究对象 / 物理量 /
#                  概念框架 / 任务名。（用户 2026-09-26 定案：「场景不进模型词表」。）
#   * `无法归类` = 既不是方法名、也不属上面那一类（断行残片、自造词、无法判定）。
#
#   **约束（判据 M-10 逐条判）**：`场景` ⇒ 处置**必须**是 `不收`；
#                             `无法归类` ⇒ 处置**必须**是 `待定` 且理由写明缺什么。
#                             `模型` ⇒ 三种处置都可能。
#
#   **`收录` 判据（写死，实施者按它逐条判）**：`类别=模型` **且** 该词形**可用作
#   「这道题用了什么方法」的检索键**（即：它是名字，不是一句描述；不是只在某一篇里成立的
#   自造缩写所指的**别的**东西）。
#   ——这条判据的代价与边界：它**允许**收录作者自建的名字（用户 2026-09-26：
#   「新遇到的模型/算法可以加入语料库」），但**不收**「描述性短语」（如
#   `Exponential decay weight design.`——它描述的是一种做法，不是一个名字）。
#
#   **复合名（场景词 + 通用模型名）怎么判（规则，controller 2026-09-26 裁决）**：
#     * **复合名**（**场景词 + 通用模型名**）——若**其通用模型名已在词表** ⇒ **不收**。
#       理由：查那个通用模型名**已经命中该篇**（逐篇可在 `TAGS.md` 的 `models` 栏里验），
#       收它**不增加检索能力**（是同一份事实的第二个落点），却会把**场景词**写进模型轴
#       ——与上面「场景不进模型词表」的定案直接抵触。
#     * **例外**：作者**自命名的专有**模型名、且**其通用模型名不在词表** ⇒ 按「模型」**收录**。
#     * 判「是不是复合名」看**后半是不是一个具体的通用模型名**（如 `system dynamics`、
#       `graph theory`），不是看它带没带 `model` 这个泛称（`Weathering Degree Model` 的
#       「Model」不是模型名，它是作者给自建模型起的名字 ⇒ 走**例外**分支）。
#   **这不是新精神**：本表已有两行在用它的精神 —— `dynamic feedback loops`（B-06：该篇实际
#   用的 `system dynamics` 已在词表）与 `network`（E-01：该篇实际用的 `graph theory` /
#   `network analysis` 已在词表）。收口轮（2026-09-26）**逐行核过全表 112 行**并按这条规则
#   重判了一遍：**实测计数见 §5**（复合名 1 行、机械候选 16 行、按「已覆盖 ⇒ 不收」精神判的
#   3 行、**同类不同判 0 处**）。
#
